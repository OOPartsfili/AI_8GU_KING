# 项目深挖：从“做过”到“能被追问”

使用边界：仅把背景报告中的经历作为对话起点。所有数据、配置、职责和结果由本人核对后使用。下列“回答骨架”不是可直接照搬的履历事实。

先读每题的场景与白话回答，再展开完整回答骨架或设计细节。所有个人经历仍需本人真实材料支持。

## J01｜用两分钟介绍内容安全项目（P0）


### 面试官先想知道，你替谁解决了什么问题

先说业务遇到的麻烦，再说你负责哪一段、做了什么、怎么确认有效。例如“误拦正常咨询太多”比一上来列十个模型名更容易理解。

下面模板中的数字和职责都要由本人真实记录填写；资料里的例子是练习，不是新增经历。

**直答：** 按业务问题、个人职责、关键做法、验证结果和失败经验介绍项目，让每一项成果都能追问到证据。

### 进一步：公式、边界与追问

**回答骨架：** “业务要解决的是___。我负责___，建立___标签与数据流程；以___为基线，完成 SFT 和偏好优化；在___冻结评测口径下，___指标发生变化，同时观察___风险；最主要的失败是___，后续用___验证。”

**展开：** 先说输入输出和业务代价，再说数据、训练、评测、部署。技术栈不应挤掉问题和结果。报告中的 2 万样本、24 类、precision 变化只有经本人确认后再填。

**追问答案：** “为什么用 DPO？”从成对偏好可得性、计算和稳定性讲，不回答“因为它先进”。“你个人做什么？”明确独立负责、协作和使用他人成果的边界。

**证据：** 数据卡、标签指南、配置、冻结集、对照、错误案例、资源日志。没有的材料列为证据缺口。

## J02｜2 万数据怎么来的，怎么保证质量？（P0）


### 2 万条不是答案，生产过程才是答案

这些样本从哪里来、哪些重复、谁判断对错、分歧怎么解决、训练和测试怎样隔开，决定它们是否值得学习。

可以先拿一条真实样本，从原始来源讲到最终标签，随后再说整体规模和审核比例。

**直答：** 用一条样本的完整处理过程说明质量机制，再用版本记录和统计说明规模，不能只报一个总数。

### 进一步：公式、边界与追问

**回答骨架：** 说明来源、去重、标注、审核、切分与更新链路，而不是只报数量。

**展开：** 把真实日志、公开数据、模型合成分别列量级与限制；标注指南带正反例、边界例；测双标一致性和仲裁原因；训练/验证/测试按会话和模板隔离。

**追问答案：** “标注不一致怎么办？”区分规范不清、样本缺上下文、真实偏好差异；分别修指南、补上下文或保留不确定性。“数据越多效果越好？”给学习曲线和固定 token 比较。

**易错：** 不能为填满回答编造各来源比例；未知字段写待本人确认，不加入成果数字。

## J03｜如何拆解 79%→96% 的贡献？（P0）


### 把“升级套餐”拆开，才知道哪一项有用

数据清洗、SFT、DPO 和阈值同时变了，最终 precision 上涨是整体结果。要拆贡献，比较只改变其中一步时的结果。

如果历史条件无法重建，就明确可证明的范围，再补可运行对照；不要用猜测填满每项贡献。

**直答：** 固定评测口径，按训练和决策阶段建立对照，分别报告指标与代价，区分观察到的提升和已经证明的因果贡献。

### 进一步：公式、边界与追问

**回答骨架：** 先固定 metric 定义与评测条件，再用阶段对照区分数据、训练和阈值贡献。

**展开：** 推荐表：原模型→同数据 SFT→继续 SFT→SFT+DPO；分别列 P/R、误拒、分类型召回、样本数、阈值和成本。另测规则或审核流程是否变化。

**追问答案：** “提升是不是只靠提高阈值？”给 PR 曲线或固定召回点。“没有旧模型怎么办？”仅陈述历史可追溯业务结果，不能声称已严格证明 DPO 单独贡献；补可重跑基线。

**易错：** 17 个百分点不是“提升 17%”；相对增幅约 21.5%，仍须先确认统计口径。

## J04｜讲一个真正有价值的失败案例（P0）


### 一份失败案例，应像一次故障诊断

不要只说“模型答错了”。先展示输入和错误，再解释怀疑原因，做一个能区分原因的小对照，最后验证修复是否帮助了独立新案例。

例如补上被截断的上文后恢复正确，是定位上下文问题的一条证据，仍需检查其他可能影响。

**直答：** 用失败表现、定位证据、修复措施和独立回归串起案例，说明自己怎样从错误找到可验证的原因。

### 进一步：公式、边界与追问

**回答骨架：** 用输入机制→失败表现→定位证据→修复→独立回归的顺序。

**展开：** 例如“跨轮信息被截断导致漏检”仅是可用案例类型，需换成本人真实样本。展示截断前后和上下文消融，说明是数据处理、模型理解还是策略阈值问题。

**追问答案：** “修复会不会误伤？”加入同机制正常近邻。“为什么不直接加规则？”说明规则覆盖范围与不可泛化边界，可把规则作为对照或应急措施。

**易错：** “增加数据后解决了”缺少机制和独立验证，难以证明知道原因。

## J05｜怎么把三知识库 RAG 讲得有算法含量？（P0）


### 三个库接起来以后，最难的问题在哪里？

选一个必须联合两库证据的问题，展示最初漏了什么、怎样改检索或排序、如何证明证据找全了。

这样能让面试官看见算法判断：候选为什么选、指标怎么定、失败怎么修，而不只是服务接口连通。

**直答：** 用真实跨库问题说明路由、检索、重排和证据评测中的个人决策，并提供相同条件下的对照。

### 进一步：公式、边界与追问

**回答骨架：** 围绕跨库路由、证据匹配、重排、冲突处理和归因评测讲。

**展开：** 给三个库的类型/边界及典型跨库问题；建立需哪些证据的 gold 标签；比较 BM25、向量、混合与 rerank；记录各阶段 recall 和最终忠实性、完整性。

**追问答案：** “加 rerank 提升多少？”提供候选池相同的对照。“没做过定量评测？”如实说明已实现链路、目前缺少哪类评测，并给出可执行补强方案。

**证据：** 解析样例、路由矩阵、gold evidence、召回日志、引用核对和时延分解。

## J06｜LangGraph 到底带来了什么？（P0）


### 框架帮你管理流程，你还做了哪些判断？

举一次工具超时或中断后的恢复，说明哪些状态被保存、哪条分支被触发、何时安全结束。然后区分框架现成功能与自己实现的业务逻辑。

“不用框架能不能做”可以从维护、调试和适配成本回答，不必把框架说成唯一选择。

**直答：** 用状态流转和恢复实例说明框架的作用，再如实说明自己写的逻辑、评测与改进。

### 进一步：公式、边界与追问

**回答骨架：** 它承载了有状态执行、条件分支和恢复管理；价值要由任务完成和可维护性证明。

**展开：** 画出简洁状态图，并说明每个节点的输入输出、不变量、失败处理和终止条件。不要把框架提供的能力都说成个人原创。

**追问答案：** “不用框架能做吗？”可以，比较自建状态机的维护成本与现成框架适配性。“Agent 比固定流程好吗？”同任务预算比较，不预设答案。

**易错：** tool calling 演示与完整业务闭环不是同一完成度。

## J07｜如何讲模型评测与平台经历？（P0）


### 平台的价值，是让错误更容易被发现和追查

例如模型总分没变，某个安全类别却退步。平台如果能定位版本、题目、生成参数和评审记录，就能帮助团队及时发现回归。

介绍时用一个真实“发现—定位—复现”的过程，比列页面和按钮更有说服力。

**直答：** 说明平台怎样统一比较条件、发现问题并重跑验证，再用具体案例展示个人贡献。

### 进一步：公式、边界与追问

**回答骨架：** “统一数据快照、执行配置、评分协议和结果归档，让多个模型版本可比较、可追踪、能发现回归。”

**展开：** 说明批量调度、失败重试、去重、日志、结果汇总和异常标记；展示一个总分不变但某类退化被平台发现的真实案例。

**追问答案：** “judge 不靠谱怎么办？”人工黄金集、盲评顺序随机化、分维度评分和仲裁。“平台创新在哪里？”按实际贡献回答协议、故障归因或成本优化，不虚构底层框架。

**证据：** 版本对比报告、任务配置、异常日志、复现步骤、阈值选择依据。

## J08｜驾驶人因研究如何与大模型岗位衔接？（P0）


### 把会的方法说清楚，也把新领域的差异说清楚

人因研究处理隐藏意图、行为不确定性和连续决策，这些经验可以帮助理解 Agent 状态和驾驶 VLM 可靠性。

但相关经验不等于已经做过 VLA 训练。可以选择一个小型视觉干预或行为评测课题，把迁移能力变成实际证据。

**直答：** 先指出可迁移的建模和实验方法，再说明领域差异与补强计划，用真实工作证明连接。

### 进一步：公式、边界与追问

**回答骨架：** “两类工作都把人的行为或偏好转成学习信号，并用部署相关指标评估高风险决策。”

**展开：** 人因研究的隐变量、POMDP、EM 和可解释规则，连接 Agent 的部分可观测状态、记忆和长链路评测；驾驶视觉注意连接 VLM grounding 和危险行为分析。

**追问答案：** “直接能做 VLA 训练吗？”说明相关能力与尚缺工程证据，建议用可靠性小课题证明迁移。“论文自己贡献什么？”准备问题定义、算法推导、实验与协作边界。

**易错：** 不说两个领域完全一样，说明可迁移方法与必须补的差异。

## J09｜没做过 GRPO，面试如何回答？（P0）


### 可以会讲原理，但不要把阅读说成训练经历

清楚说明已做过 SFT/DPO、理解了 GRPO 的哪些机制，能展示哪些 CPU 教学验证；真正的大模型训练如果没做，就提供具体复现方案。

这样面试官才能区分你的当前能力与学习计划，也更容易展开有意义的追问。

**直答：** 如实区分理解、教学实现和实际训练，用可展示的内容证明已有基础，再给出能执行的补强步骤。

### 进一步：公式、边界与追问

**回答骨架：** “我理解组内优势、采样更新和主要失效，实际经验目前在 SFT/DPO；可以说明复现方案与需要验证的点。”

**展开：** 先讲清 RL06–RL14，再给小模型可执行任务的实验设计：SFT 基线、验证器单测、固定 rollout 预算、组大小消融、熵/长度/成本指标。

**追问答案：** “会不会只是看论文？”承认已做与未做，用实际运行的 CPU 核心计算说明理解，用真实 GPU 日志支撑未来复现。

**易错：** 不把本知识库中的教学代码称为大模型 GRPO 训练项目。

## J10｜技术简历的一条 bullet 如何写扎实？（P0）


### 一条简历，读完应知道做了什么、凭什么相信

先写动作和对象，再写关键方法、结果及测量条件。比如“改进检索”还应说明改了哪一步、对什么问题有效、用什么独立指标测。

没有真实数字就写已完成范围，不必为了句子漂亮加入“显著”“首创”等无法支撑的词。

**直答：** 用具体动作、对象、方法、结果口径和证据写项目条目，确保每个成果词都有实际依据。

### 进一步：公式、边界与追问

**回答骨架：** 动作＋对象/规模＋关键方法＋明确口径结果＋可验证条件。

**展开：** 可编辑模板：“针对___任务，负责___数据/算法环节，采用___；在___冻结集与___约束下，___从___到___，并通过___对照定位收益，成本为___。”没有真实结果的字段不要硬填。

**追问答案：** “你认为最弱的证据是什么？”指出尚缺的独立测试、资源记录或消融，并给补齐优先级。

**易错：** “主导、首创、显著提升”都需要对应职责、先例和统计证据。
