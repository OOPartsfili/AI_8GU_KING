# 14 多模态、自动驾驶与人因交叉

先分清看图、依据图像回答、生成动作这几件事。V03 用改图检查是否真看图；V08 用录像与实际接管解释开环和闭环。隐变量、EM 等可以按本人研究需要加深。

<a id="V01"></a>
## V01｜CLIP 学到了什么？（P0）


### 让图片和对应文字在同一个“坐标空间”里靠近

CLIP 同时处理图片和文字描述，训练时提高正确配对的相似程度，区分不匹配的配对。这样可以用文字去找相关图片，或比较图片与不同类别描述的匹配。

但“这张图像一只狗”这种整体对应，不自动等于精确理解每个位置、数量和因果关系。

**直答：** CLIP 通过图文配对学习可比较的表示，适合相似性匹配；细粒度定位和推理需要额外验证。

### 进一步：公式、边界与追问

**本章进阶约定与范围：**

定位：发挥驾驶人注意、POMDP、程序化模仿学习与大模型评测的共同优势。重点是可靠性和评测，不把阅读经历包装成 VLA 大规模训练经验。

**技术表述：** 将配对图像和文本映射到相互可匹配的表示空间，通过对比目标区分正确配对与其他组合。

**展开：** 训练通常同时考虑图像到文本和文本到图像的匹配；可用于零样本分类、检索和表征。它并不是直接自回归生成长回答的聊天模型。

**追问：文字描述正确就能精确定位目标吗？** 全局对齐不保证细粒度空间关系、计数或位置准确，需要专门评测和设计。

**易错：** 图文相似度不等于视觉事实正确概率。依据：S40。

<a id="V02"></a>
## V02｜VLM 通常怎样接上语言模型？（P0）


### 给语言模型接上能处理图片的输入通道

常见 VLM 先用视觉编码器把图片变成数字特征，再通过连接模块转成语言模型能使用的表示，与文字一起处理。

就像把图像内容转换成可读的内部材料，但不是简单把图片先人工描述成一句话。

**直答：** 典型 VLM 由视觉编码、连接模块和语言处理部分协作，让模型把图像信息用于回答；具体连接与训练方式各不相同。

### 进一步：公式、边界与追问

**技术表述：** 视觉编码器提取图像表示，通过投影/连接模块转换成语言模型可处理的视觉 token，再用图文数据对齐与指令训练。

**展开：** 视觉分辨率、patch 数、连接模块和是否冻结视觉编码器影响成本与能力。视频还需时间采样、帧间关系和长上下文管理。

**追问：多看几帧一定更好？** 可能增加关键信息，也可能引入重复、时延与截断；需要比较帧率、分辨率和时间覆盖。

**易错：** VLM 的视觉 token 数不等于原始像素数。依据：S41。

<a id="V03"></a>
## V03｜视觉 grounding 是什么，怎么测？（P0）


### 它真看了红灯，还是靠常识猜到“应该停车”？

视觉 grounding 关注回答是否对应图片里的具体证据。把红灯改为绿灯，若答案仍完全不变，就值得检查模型是否忽略了图像。

还可以遮住目标、打乱图片与问题、改变物体位置，观察回答变化是否合理；单次变化也要排除其他因素。

**直答：** grounding 是语言判断与实际视觉证据的对应关系，应用定位和受控图像干预验证，不能只看答案是否听起来合理。

### 进一步：公式、边界与追问

**技术表述：** 回答或决策是否真正依据当前图像，而不是语言常识或数据集偏差。

**展开：** 做干净图、模糊/遮挡、删除图像、替换图像、矛盾文本先验对照；比较关键对象、关系和危险动作判断。反事实图应保证除目标因素外尽量一致。

**追问：文本-only 仍答对说明什么？** 可能题目能靠常识猜对，提示泄漏，或数据不平衡，不能直接证明模型“看得很好”。

**易错：** 合理的解释不是视觉依赖的充分证据。依据：S42。

<a id="V04"></a>
## V04｜VLM 与 VLA 差别是什么？（P0）


### 会解释路况，和会输出动作，还差一层

VLM 使用视觉与语言，可能回答“前方有障碍”；VLA 进一步把感知与语言条件连接到动作输出，例如机械臂动作或驾驶控制相关表示。

动作会影响环境，错误也会累积，所以还要检查执行约束、反馈和连续行为。

**直答：** VLA 在视觉语言理解之外面向动作生成，评价需要关注动作可执行性和环境中的实际后果。

### 进一步：公式、边界与追问

**技术表述：** VLM 主要连接视觉与语言理解/生成；VLA 进一步将感知、语言与可执行动作输出或动作策略连接。

**展开：** 动作可以离散 token、连续控制或轨迹，具体需看模型。自然语言“向左”与可执行转角、速度和时间轨迹之间还有控制与约束。

**追问：为什么语言解释不能直接作为控制器？** 时延、单位、动态可行性、噪声和闭环稳定都需处理。

**易错：** action token 并不天然满足车辆运动学与安全约束。依据：S41、S46。

<a id="V05"></a>
## V05｜扩散规划为什么适合多模态轨迹？（P1）


### 同一个路口，可能有不止一条合理路线

如果左绕和右绕都安全，直接把两条路线取平均，可能恰好撞上中间障碍。这里的“多模态轨迹”是多种合理行为模式，不是说同时有图片和文字。

扩散规划通过逐步修正候选轨迹表示，可以表达多种可能，但候选仍要满足安全与动力学约束。

**直答：** 扩散规划能够建模多种可行轨迹选择，价值在于表达行为分布；不能因轨迹像样就省掉执行与安全检查。

### 进一步：公式、边界与追问

**技术表述：** 同一个场景可能有多条合理未来，生成式分布可表示候选路径，而简单均方误差回归可能平均出不合理轨迹。

**展开：** DDPM 类训练从加噪样本预测噪声/干净数据；规划时将场景作为条件，逐步生成候选。真实规划还需地图、动力学与交互约束。

**追问：为什么不能一味增加去噪步数？** 实时系统有严格延迟预算；更多步骤与候选要换来可测的安全/完成率收益。

**易错：** 多样不等于高质量，危险候选也会增加多样性。依据：S47、S45。

<a id="V06"></a>
## V06｜DiffusionDrive 的新意该怎么讲？（P1）


### 能生成很多路线，还得来得及用于驾驶

通用扩散往往需要多轮去噪。驾驶规划关注实时性，因此 DiffusionDrive 研究怎样用针对任务的设计减少生成开销，同时保持轨迹质量。

介绍它时先说明改变了哪些去噪、初始化或候选处理环节，再看对应评测，不把图像生成里的优势直接外推到驾驶。

**直答：** 该工作的价值要从轨迹分布建模与快速生成的结合解释，并保留其具体模型、步骤和评测条件。

### 进一步：公式、边界与追问

**技术表述：** 用多模态先验锚点与截断扩散安排，减少从纯噪声开始的长去噪过程，面向实时多候选轨迹生成。

**展开：** 讨论“起点更接近有意义轨迹”“条件信息如何注入”“速度与多样性如何验证”。论文的步数降低、FPS 和 PDMS 都有具体模型与硬件条件。

**追问：10 倍减少步数等于端到端 10 倍加速吗？** 不等，视觉编码、后处理与调度可能占大量时间。

**易错：** 不将论文特定测试的实时表现写成任何车辆上的部署保证。依据：S45。

<a id="V07"></a>
## V07｜世界模型为什么可能帮助规划？（P0）


### 先在脑中试走一步，再决定真实怎么走

世界模型预测“现在这样，执行这个动作之后，环境可能变成什么样”。规划器可以先模拟几种动作的后果，再选择。

但模拟误差会随着多步预测积累，尤其在少见场景中。因此“想象得合理”不能代替真实或更可靠环境中的验证。

**直答：** 世界模型提供动作后果的预测，支持规划和学习；使用时需要考虑预测偏差、长时间累积误差与验证环境。

### 进一步：公式、边界与追问

**技术表述：** 预测行动后的未来状态或表征，让规划能比较潜在后果；也可提供未来预测的自监督信号。

**展开：** 世界模型不一定生成高分辨率视频，也可预测 BEV、占用、潜变量和奖励。关键是预测条件里是否含动作，以及策略是否真的利用未来信息。

**追问：画面好看就能规划更好吗？** 不一定。物理关系、交互反应与长时误差比视觉观感更关键；做去掉未来信息、替换随机 latent 和改变行动的消融。

**易错：** 无动作条件的未来预测不能自动回答“如果我这样开会发生什么”。依据：S77；规划迁移部分为工程分析。

## V08｜开环和闭环评测差别在哪里？（P0）


### 看录像给建议，和真的接手方向盘

开环评测常比较模型输出与记录数据，但模型动作不会改变后续世界；闭环评测会让动作进入环境，再观察新状态并继续行动。

一次小偏差在录像题上可能不显眼，真正连续执行后却可能让车辆位置越来越偏，这就是闭环验证的重要性。

**直答：** 开环主要检查给定观测下的输出，闭环检查动作改变环境后的连续行为；二者能证明的可靠性范围不同。

### 进一步：公式、边界与追问

**技术表述：** 开环通常在固定记录上评价预测；闭环把模型动作送入环境，后续观察受动作影响，错误可能累积。

**展开：** 多条合理轨迹使单一专家 L2 不充分；小偏差也可能在下一步改变相对位置，最终导致碰撞或停滞。指标需覆盖完成、碰撞、违规、舒适与恢复。

**追问：闭环仿真就是真实安全？** 仿真仍有域差、行为模型偏差和覆盖限制，需要分层验证。

**易错：** 不要把所有带“simulation”的评价都称为完全反应式闭环。依据：S43、S44。

<a id="V09"></a>
## V09｜NAVSIM 与 Bench2Drive 怎么比较？（P0）


### 不同考场，不能只比总分高低

原始 NAVSIM 的非反应式评测有其仿真和评分设计，但周围交通不会像完整交互环境那样响应自车；Bench2Drive 等闭环设置考查另一类连续交互表现。

因此要逐项看环境是否响应、任务覆盖、传感器、动作与计算条件，而不是看到“驾驶基准”就认为等价。

**直答：** 先比较评测环境与反馈方式，再比较任务和指标；原始 NAVSIM 的边界应与完整反应式闭环明确区分。

### 进一步：公式、边界与追问

**技术表述：** 原始 NAVSIM 用数据驱动、非反应式仿真提供比纯轨迹误差更丰富的评测；Bench2Drive 在交互仿真场景中关注多能力闭环行为。

**展开：** NAVSIM 的周围环境不随被测策略任意响应，因此不能等同全反应式真实交互。两者的数据、协议、指标和版本不同，不把分数直接横比。

**追问：同名 PDMS 为什么不能随意比较？** 配置、数据版本、过滤、传感器和模型骨干变化可能影响难度；需固定完整协议。

**易错：** 2026 新论文引用 NAVSIM v2 时，应读其确切评价配置，不能沿用早期标签。依据：S43、S44。

## V10｜DPO 如何迁移到驾驶轨迹？（P0）


### 同一个驾驶场景，比较两条候选路线

偏好优化的对象可以从文本回答换成轨迹：在相同场景下，一条更安全或舒适，另一条较差。模型学习增加较优轨迹的生成倾向。

但轨迹概率怎样定义、偏好由谁给出、安全标准是否可靠，都需要按模型和任务重新处理，不能只把文本变量换个名字。

**直答：** 驾驶 DPO 需要同场景轨迹偏好及相应概率模型，并联合验证安全、舒适和闭环后果。

### 进一步：公式、边界与追问

**技术表述：** 将同场景的两段回答换成两条轨迹，偏好由安全、规则、进度、舒适和类人性构造。

**展开：** 轨迹的概率或评分定义依生成模型；连续动作不能不经推导就套 token logprob。偏好可能多目标冲突，例如安全保守与通行效率。

**追问：人类轨迹一定是最安全 chosen？** 不一定，人类示范也可能违反规则或依赖不可见信息；需结合可靠规则与交互评测。

**易错：** DriveDPO 的 NAVSIM 分数不是实车安全证明。依据：S46。

<a id="V11"></a>
## V11｜POMDP 与普通 MDP 有何区别？（P0）


### 开车时，你并不知道所有车主心里在想什么

普通 MDP 假设决策者拿到的状态足以描述当前情况；POMDP 允许只能看到部分信息，例如看见对方车速，却不知道对方是否准备让行。

模型可以维护一个“信念”：根据已见信息，对可能隐藏状态分配概率，再用新观察更新。

**直答：** POMDP 把状态不完全可见纳入建模，通过观测和历史形成对隐藏状态的判断，再据此决策。

### 进一步：公式、边界与追问

**技术表述：** POMDP 无法直接看到完整环境状态，需要根据观察和历史维护 belief，即对隐藏状态的概率分布。

$$b_{t+1}(s')\propto O(o_{t+1}|s',a_t)\sum_s T(s'|s,a_t)b_t(s).$$

**展开：** 驾驶员真实注意、意图和接管准备可能不可直接观测，只能从视线、操作与场景推断。belief 更新结合状态转移与新观察。

**追问：和 Agent 记忆有什么联系？** 两者都要基于不完整历史推断当前状态，但文本摘要不自动等于校准的 belief。

**易错：** 不要把隐藏状态当训练时每一步都可获得的真标签。依据：S73。

<a id="V12"></a>
## V12｜EM 在驾驶人因建模里做什么？（P0）


### 不知道驾驶风格，怎么估计它的行为规律？

假设观察了车速与让行行为，却不知道每段数据属于“谨慎”还是“激进”风格。EM 交替做两件事：先用当前参数估计隐藏风格的可能性，再按这些可能性更新行为参数。

像先暂时给作业分组，再根据分组改统计，反复迭代。这里的风格只是示例，真实隐变量取决于研究设定。

**直答：** EM 在隐藏变量不直接可见时，交替估计隐变量分布与更新参数；结果受建模假设和初始化影响。

### 进一步：公式、边界与追问

**技术表述：** 对含隐变量的模型，交替估计隐变量后验与更新模型参数。

**展开：** E 步在当前参数下计算隐变量的后验或足够统计量；M 步最大化期望完整数据 log 似然。适用于隐含意图、规则选择等建模，但具体变量必须按本人论文说明。

**追问：EM 保证全局最优吗？** 一般不保证；在标准精确 E/M 条件下可保证似然不降，但可能落入局部解。近似步骤还需检查性质是否保留。

**易错：** 不把任何“交替训练”都叫 EM。依据：S74。

<a id="V13"></a>
## V13｜程序化模仿学习有什么岗位价值？（P0）


### 不只模仿动作，还尝试得到能检查的规则

程序化模仿学习希望用某种程序或规则结构表达行为，例如哪些条件触发让行、何时切换决策。这样更方便检查逻辑、解释失败。

但人的行为不一定能被简单规则完整描述，可解释性也不自动保证规则正确。

**直答：** 用可检查的结构学习或描述行为，有助于解释和测试；需要验证规则覆盖、表达能力与实际行为质量。

### 进一步：公式、边界与追问

**技术表述：** 用带结构的规则或程序表示策略，在拟合行为的同时提升可解释性与可检查性。

**展开：** 可展示触发条件、时间关系与规则组合，便于分析“何时看哪里”“何时提示或接管”。价值需用准确性、复杂度、稳定性和人因效用共同衡量。

**追问：规则可读就等于符合真实心理机制吗？** 不等，可能只是可解释的拟合；机制解释需要额外实验。

**易错：** 报告称已有论文和专利，但具体作者贡献、算法细节与结果仍须本人原文和材料支撑。

<a id="V14"></a>
## V14｜3DGS、合成数据与世界模型怎么连接？（P1）


### 重建场景、生成训练图、预测未来，各做一件事

3D Gaussian Splatting 用许多带位置、形状和颜色等信息的高斯表示来渲染场景；重建或生成的场景可帮助制作训练数据。

世界模型则还要考虑动作与时间下的变化。画面逼真，不代表交通反应和危险情形也足够真实。

**直答：** 3D 表示可支持渲染与数据生成，世界模型关注动态演化；连接使用时分别验证视觉质量、行为真实性和训练迁移效果。

### 进一步：公式、边界与追问

**技术表述：** 3DGS 等表示可重建与渲染场景，生成模型或世界模型可扩展场景变化，最终目标是补足训练和评测中的稀缺条件。

**展开：** 合成样本需保持相机、对象运动、地图、控制与标注的一致性。覆盖长尾交互比只追求逼真截图更有实际价值。

**追问：合成数据如何证明有效？** 固定真实训练数据与预算，增加合成组；在独立真实场景测性能与退化，排除资产或模板泄漏。

**易错：** FID 改善不直接证明闭环驾驶改善。依据：S75。

<a id="V15"></a>
## V15｜你最适合做怎样的驾驶与大模型交叉项目？（P0）


### 从能证明的小问题切入

例如研究驾驶问答是否真正依赖图像：固定问题，改变信号灯或关键障碍，检查答案变化、危险建议和误判原因。

这个小课题能把视觉、人因理解和模型评测连接起来。范围明确、对照干净，比一下子声称训练完整自动驾驶大模型更容易形成可信证据。

**直答：** 从与已有研究相连的可靠性问题切入，定义可控干预、风险指标和对照，用实际完成的证据证明迁移能力。

### 进一步：公式、边界与追问

**技术表述：** 从 VLM 视觉可靠性与人因决策评测入手，把已有驾驶理解与大模型安全评测经验结合。

**展开：** 用驾驶图像构造干净、模糊、遮挡、缺图、误导文本组；标注关键对象与危险动作建议，分别评解释与行为。结合注意/接管问题，分析哪些视觉遗漏最影响风险。

**追问：为什么优先评测而不是训练大 VLA？** 与现有证据、预算和可交付周期更匹配；后续再用失败集推动适配或偏好学习。

**易错：** 数据规模、运行结果和指标必须真实填入，不把方案写成已完成。依据：S42；岗位建议。
