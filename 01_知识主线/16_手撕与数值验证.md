## H01｜手写稳定 softmax 和交叉熵（P0）


### 把一次预测拆成四个可检查步骤

拿分数 [1000,1001]：先减最大值，得到 [−1,0]；再算 softmax，约为 [0.269,0.731]；找到实际标签对应的概率；最后算它的负对数。

这样每一步都有预期结果，容易发现溢出、取错标签或符号错误。先读 M02、M04，再打开代码会更容易。

**直答：** 先保证概率计算稳定，再按实际标签取负 log 概率；用平移前后结果一致和简单手算检查实现。

### 进一步：公式、边界与追问

**本章进阶约定与范围：**

代码位于 03_代码实验。先按本章要求自己写，再比较实现；测试通过只证明这些教学算例与性质，不证明真实大模型训练正确。

**技术表述：** 先减去每行最大值，再用 logsumexp 计算 log-softmax，按正确 token 取负值。

**展开：** 输入 shape、axis、mask 的 True 含义必须明确；空有效行应显式报错。对 logits 做平移结果不变，概率和为 1。用有限差分核查 p−y 梯度。

**追问：为什么不用 exp 后加 1e−8 解决所有问题？** 无法修复已溢出的 exp，还可能改变极小概率对应的损失。

**实现入口：** log_softmax、masked_softmax；独立校验包含大 logits、平移不变和梯度差分。

## H02｜手写带 causal mask 的 attention（P0）


### 第三个位置可以看前三个，不能偷看第四个

先算 Q、K 匹配分数，再把未来位置遮住，接着做 softmax，最后用这些权重加总 V。顺序错了，可能在归一化时把未来信息算进去。

一个好检查是只修改未来内容，观察前面位置的输出是否不变。

**直答：** 按匹配、遮罩、归一化、加权汇总实现因果注意力，用“不受未来改动影响”的性质检查，而不只看形状正确。

### 进一步：公式、边界与追问

**技术表述：** QKᵀ 除以 head dim 平方根，屏蔽未来位置，沿 key 维 softmax，再乘 V。

**展开：** 支持 batch/head 维广播，验证输出 shape；修改未来 V 不应改变更早输出。这个性质测试比只看一组输出是否“像对的”更有力。

**追问：KV cache 增量版怎么扩展？** 新 token 计算 Q/K/V，K/V 追加到历史，Q 只需查询可见缓存；因果位置偏移需正确处理。

**实现入口：** causal_attention。当前实现是同长度 self-attention 数学演示，不含 GPU kernel 或缓存服务。

## H03｜从 logits 取回答序列 logprob（P0）


### 每个位置的一大排概率，只取实际写出的那一项

模型在每个位置都会给整个词表打分。先转成 log 概率，再取目标 token 的那一项；只保留回答中应计分的位置，最后求和或按长度平均。

最容易出错的是对齐：前一个位置用于预测下一个 token，不能拿当前位置去预测自己。现有教学函数要求输入目标事先对齐。

**直答：** 明确预测与目标的移位关系，按 token 取 log 概率，再应用回答遮罩和规定的聚合方式。

### 进一步：公式、边界与追问

**技术表述：** 先对齐每个位置预测的目标 token，再 gather 正确 logprob，屏蔽 prompt/padding 后求和或平均。

**展开：** shift 必须只做一次；无效 target 可设 −100，但 gather 前要替成合法占位索引；最后再 mask。分母是有效回答 token。

**追问：为什么不直接把 logits 加起来？** logits 未归一化，可以任意平移；概率语义来自 log-softmax。

**实现入口：** sequence_logprob；它要求调用者已对齐目标，不偷偷再次 shift。

## H04｜手写 DPO/SimPO 并检查符号（P0）


### 写完损失，先问好答案变好时分数会怎样

给一个小例子，增大好答案相对差答案的优势，检查损失是否下降。DPO 要减参考差值，SimPO 要按回答长度平均并减 margin。

先验证这个方向，再处理批量计算。程序能跑，并不能排除把 chosen 和 rejected 写反。

**直答：** 用小算例检查偏好方向、参考项、长度与缩放，再用梯度验证关键符号，最后扩展到批量训练。

### 进一步：公式、边界与追问

**技术表述：** 将偏好 logit z 写清，用 softplus(−z) 稳定求 loss；DPO 含参考差，SimPO 含长度与 margin。

**展开：** DPO 当前=参考时 loss=ln2；提高相对 chosen 的 logprob 应降低单样本 loss。SimPO 按比例复制总 logprob 与长度，平均值和 loss 不变。

**追问：单样本性质能证明参数训练总向好？** 不能，参数共享、多样本权重和泛化仍需真实实验。

**实现入口：** dpo_loss、simpo_loss；含 DPO 有限差分与 P09 算例。

## H05｜手写 GRPO 优势与 PPO clip（P0）


### 先让四份答案排出相对好坏，再限制更新

奖励 [0,0,1,1] 能算出正负组内优势；奖励 [1,1,1,1] 应得到零优势。再分别构造正优势与负优势的概率比，检查 PPO 裁剪是哪一项起作用。

把两个步骤分开检查，比对着整行目标函数排错容易。

**直答：** 分别验证优势归一化、零方差组和正负优势的裁剪分支，再确认回答与 token 的聚合权重。

### 进一步：公式、边界与追问

**技术表述：** 按 prompt 分组减均值，按所选约定缩放；clip 目标用原项与截断项取较小值。

**展开：** 明确 std 的 ddof 和 ε；全相同奖励优势为零。分别测试正优势/负优势与 ratio 过高/过低四种情况。

**追问：为什么 std 的实现差异会影响值？** 样本标准差与总体标准差不同，小 group 时差别明显；论文、框架与代码必须对齐。

**实现入口：** grpo_advantages、ppo_surrogate、aggregate_token_losses；演示三类长度归一化。

## H06｜手写 pass@k 与 paired bootstrap（P0）


### 组合问题用枚举检查，统计问题用成对结果检查

pass@k 的小规模例子可以枚举所有选法，看有多少组合至少包含一次成功；成对 bootstrap 则每次把同一道题的新旧结果一起抽走。

如果两个模型结果完全相同，差值区间应该为 [0,0]，这是很直观的检查。

**直答：** 用可枚举的小案例验证采样公式，用保持配对关系的重采样验证差值统计，并固定随机种子方便复查。

### 进一步：公式、边界与追问

**技术表述：** pass@k 用无成功组合数占比；配对 bootstrap 对同样本差值共同重采样。

**展开：** pass@k 用连乘避免巨大组合数；小 n 可穷举所有 k 子集验证。bootstrap 先明确每个元素是独立样本或会话聚合得分。

**追问：同一批样本 A=B，区间应是什么？** 配对差恒为零，区间应为 [0,0]，可作关键性质测试。

**实现入口：** pass_at_k、paired_bootstrap。

## H07｜手写 LoRA 前向与合并（P0）


### 两种写法，应该算出同一个结果

一种先算原矩阵与输入的乘积，再加 LoRA 两个小矩阵产生的结果；另一种先合成更新后的大矩阵，再乘输入。

在对应精度与假设下，这两条路线应数值接近。改变 rank 和输入形状，能帮助发现矩阵方向写错。

**直答：** 用分支计算与合并矩阵的等价性检查 LoRA，明确矩阵维度、缩放和允许的数值误差。

### 进一步：公式、边界与追问

**技术表述：** 按给定形状计算 xWᵀ+(α/r)(xAᵀ)Bᵀ，并与 x(W+(α/r)BA)ᵀ 比较。

**展开：** 用随机小矩阵测试两种路径一致；B=0 时应还原基座输出。训练时不能把所有基座计算错误地切断梯度。

**追问：NumPy 这个测试验证了训练吗？** 只验证线性代数等价，不含自动求导或量化合并误差。

**实现入口：** lora_forward。

## H08｜实现一次“写入成功但响应超时”的恢复（P0）


### 故意丢掉回执，看看系统会不会重复办事

教学服务先记录“退款成功”，再模拟返回超时。恢复逻辑应通过同一个请求标识查询状态，发现已完成后直接返回，而不是再写一次。

这里完全是本地模拟。关键检查是最终状态正确、实际写入次数为 1，而不只是没有抛异常。

**直答：** 用“提交已生效但响应丢失”的故障检查幂等恢复，验证业务结果和写入次数，避免重复副作用。

### 进一步：公式、边界与追问

**技术表述：** 保留逻辑请求标识，超时后查询权威状态；确认已成功就返回，未知则保留未知并按有限策略处理。

**展开：** 模拟服务先提交退款再抛超时；恢复后操作次数仍为 1，重复同一幂等键不再写入。真实系统还需处理最终一致性、权限与补偿。

**追问：为什么不能只捕获异常重试？** 异常不必然表示没有副作用，重复写入会造成业务错误。

**实现入口：** MockRefundService、recover_refund。全部是内存模拟，不访问真实订单或账户。
