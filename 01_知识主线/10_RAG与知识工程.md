# 10 RAG、检索与知识工程

把 RAG 想成一次开卷考试：整理资料、找相关页、读证据、组织答案。先读 R01、R02，再看每一阶段为何会失败；召回这个流程名和召回率这个指标要分开。

<a id="R01"></a>
## R01｜RAG、长上下文、微调和工具怎么选？（P0）


### 不会的问题，是查书、读长材料、补课，还是调用机器？

RAG 先检索相关资料，再据此回答，像开卷考试；长上下文把更多材料直接放进输入；微调改变模型参数，像补课；工具可以执行查询、计算或业务动作。

问最新政策适合查可更新资料，算复杂数值适合调用计算工具。也可以组合，先不要把所有问题都当作“再训练一下”。

**直答：** 根据缺的是知识、上下文容量、行为习惯还是执行能力，选择检索、长输入、微调或工具，并考虑更新频率和成本。

### 进一步：公式、边界与追问

**本章进阶约定与范围：**

定位：三知识库与航空业务经历的直接延伸。核心是证据如何流动、错误如何归因，不止会画“向量库→LLM”。

**技术表述：** RAG 解决外部证据获取，长上下文增加单次可读内容，微调改变模型能力与行为，工具获取或执行精确结构化操作。

**展开：** 经常变更的政策可检索，订单状态查数据库，固定输出格式可 SFT，大文档整体分析可用长上下文；可以组合，先测最简单可用基线。

**追问：有 1M 上下文还要 RAG 吗？** 输入成本、权限过滤、知识更新和干扰仍在，检索可缩小证据范围；但小知识库直接全放也可能更简单。

**易错：** RAG 不保证没有幻觉。依据：S25。

<a id="R02"></a>
## R02｜完整 RAG 链路包含什么？（P0）


### 从一柜子文件，到一句有根据的回答

先把文件转成可读取文本，再切成片段并建立索引；收到问题后找候选资料、重新排序，把较相关证据交给模型组织答案，最后核对引用。

就像图书馆先编目，再找书、翻页、摘录、作答。任何一步丢了内容，最后都可能答错。

**直答：** RAG 是从文档处理到检索、重排、生成和引用核对的一整条流程，需要保存各阶段记录才能定位问题。

### 进一步：公式、边界与追问

**技术表述：** 数据解析→切分与元数据→索引→查询理解/路由→召回→重排→上下文组织→生成与引用→验证和日志。

**展开：** 每一步有版本与证据 ID。航空场景先确认问题是政策、流程还是实时记录；检索权限过滤应在可见内容进入模型前生效。

**追问：哪些要缓存？** 查询或前缀可缓存，但键需包含用户权限、索引/文档版本、模型及模板；动态事实要设置失效机制。

**易错：** 一个总体 judge 分无法知道失败发生在哪个阶段。

## R03｜Chunk size 和 overlap 怎么选？（P0）


### 资料卡太短看不懂，太长又难找重点

把“退票条件”和“适用航班”切到不同片段，检索到一半就可能误答；整本手册当一个片段，又会带入太多无关内容。

overlap 是让相邻片段保留少量重叠，减少边界断裂，但也增加重复。最好按真实问题需要的完整证据选择切法。

**直答：** 切片要兼顾语义完整、检索定位和输入长度，重叠能缓解断裂但会增加冗余，不能只套固定字数。

### 进一步：公式、边界与追问

**技术表述：** 按文档结构、问题粒度与检索/生成预算选择，通过小规模受控对照找平衡。

**展开：** 太短可能丢定义与条件，太长会稀释向量表示并带入噪声。保留标题、表头、条款编号、有效日期和父文档。overlap 减少边界断裂，但增加重复与成本。

**追问：表格怎么切？** 保留表头、单位、行列对应和注释；只抽出数字而丢单位，会制造错误证据。

**易错：** 固定“500 字加 50 overlap”只是起始配置，不是最佳实践定理。

<a id="R04"></a>
## R04｜稀疏检索、稠密检索为什么互补？（P0）


### 对上关键词，和听懂同一个意思

关键词检索擅长精确型号、编号和专名；向量检索把文本变成数字表示，尝试找到意思相近的内容，例如“改期”和“换个日期”。

前者可能漏掉换说法，后者可能把语义近但编号不对的文档排前面，组合时可以互补。

**直答：** 稀疏检索重视词项匹配，稠密检索重视学习到的语义相似；两者的强弱随任务不同，混合要通过证据召回验证。

### 进一步：公式、边界与追问

**技术表述：** 稀疏检索重视词项匹配，适合编号、专名和精确词；稠密检索捕捉语义相似，适合同义表达。

**展开：** BM25 结合词频饱和、逆文档频率与长度归一；向量检索依赖 embedding 的训练分布。航空代码、型号、政策编号常需要精确匹配，口语改写更需要语义。

**追问：为什么 embedding 相似却答非所问？** 相似不代表蕴含，可能只在主题上相近；还可能忽略否定、时间与适用条件。

**易错：** 不同检索器原始分数的尺度不可直接随意相加。依据：S26、S67。

## R05｜RRF 如何融合多个检索结果？（P0）


### 两个老师的原始分数不一样，先比较名次

关键词检索给分 12.3，向量检索给分 0.82，量纲不同，直接相加可能没有意义。RRF 根据各列表中的排名给贡献，再把同一文档的贡献加起来。

在多个列表都靠前的文档更有优势。它简化融合，但不理解文档内容本身。

**直答：** RRF 用排名而非原始分数融合多个检索结果，减少分数尺度不一致的问题，常数和候选范围仍需设定。

### 进一步：公式、边界与追问

**技术表述：** 依据排名而非原始分数融合，降低不同检索器分数尺度不一致的问题。

$$\mathrm{RRF}(d)=\sum_j\frac1{k_0+\mathrm{rank}_j(d)}.$$

**展开：** k₀ 是平滑常数，不是 top-k 检索条数；不在某列表中的文档该项通常记零。先统一文档/段落 ID、去重，再融合。

**追问：RRF 一定最好吗？** 不是，它丢弃分数间距信息；有可靠验证集时也可做校准加权或学习排序。

**练习：** 同一文档两榜排名 1 与 3，k₀=60，得分 1/61+1/63≈0.03227。依据：S68。

<a id="R06"></a>
## R06｜Bi-encoder 与 Cross-encoder 如何分工？（P0）


### 先快速海选，再让评委仔细比较

Bi-encoder 分别把问题和文档编码，文档可以提前算好，适合从大量资料里快速找候选。Cross-encoder 把问题与每份候选放在一起分析，能做更细的交互判断，但更费计算。

因此常先召回几十份，再精排其中最有用的几份。

**直答：** 双编码器适合大规模快速召回，交叉编码器适合小候选集精排；分工来自速度与细粒度匹配的取舍。

### 进一步：公式、边界与追问

**技术表述：** Bi-encoder 分别编码 query/document，便于离线建索引与快速召回；Cross-encoder 联合输入，细粒度判断相关性，常用于较小候选集重排。

**展开：** 重排无法找回召回阶段完全漏掉的证据；所以先确认候选池 recall，再比较重排。还要看长文本截断和中文/领域适配。

**追问：rerank 后效果变差？** 可能重排模型不适合领域、关键信息超出长度、只按主题相似而非回答支持排序。

**易错：** 更大 reranker 未必在固定延迟预算下更好。依据：S26、S69。

## R07｜Embedding 的对比学习与难负例怎么讲？（P0）


### 教模型分清“相关”和“看起来很像但不相关”

训练文本向量时，让问题靠近正确证据、远离不相关片段。难负例是容易混淆的错误候选，例如问国内退票规则，却给国际航班的相似条款。

难例有价值，但若它其实也能回答问题，把它当负例反而教错。

**直答：** 对比学习拉近正确匹配、区分错误匹配；难负例要有代表性，并确认不属于漏标的正确证据。

### 进一步：公式、边界与追问

**技术表述：** 拉近问题与相关文档表示，推远不相关文档；难负例与主题相近但不支持答案，能提供更有用区分。

$$L=-\log\frac{\exp(s(q,d^+)/\tau)}{\exp(s(q,d^+)/\tau)+\sum_j\exp(s(q,d_j^-)/\tau)}.$$

**展开：** in-batch negatives 省计算，但其他样本的正例可能也是当前 query 的正确证据，形成 false negative。去重与多正例标注很重要。

**追问：余弦和点积等价吗？** 向量都 L2 归一化时排序可等价，否则范数会影响点积。

**易错：** 换 embedding 模型后旧索引通常需要重建或明确兼容策略。依据：S26。

## R08｜Recall@k、MRR、NDCG 怎么选择？（P0）


### 找没找到、第一条好答案多靠前、整页排序好不好

Recall@k 看前 k 条有没有覆盖需要的相关资料；MRR 关注第一条相关结果的名次；NDCG 可以考虑多条结果的相关程度，并更重视前面的名次。

如果任务需要两份不同证据，仅把第一份排第一仍然不够，指标要匹配真正的信息需求。

**直答：** 检索指标分别强调覆盖、首个命中或分级排序质量；先定义相关证据，再选择能反映任务目标的指标。

### 进一步：公式、边界与追问

**技术表述：** Recall@k 看需要的相关项找回多少；MRR 看第一个相关结果排多前；NDCG 支持分级相关性与位置折扣。

**展开：** 多跳问题需要多条证据，仅“第一条命中”不足。文档级命中与片段级可回答性也不同。统一 relevance 定义和去重单位。

**追问：检索 top-k 大一点一定好？** recall 可能提高，但噪声、上下文占用和生成干扰也会上升。

**易错：** hit@k（至少一个命中）不等于多证据场景的 recall@k。依据：S67。

## R09｜三知识库路由如何设计和评测？（P0）


### 问题该去哪个柜子找，也可能要查两个柜子

假设有航班规则、会员政策和内部流程三个库。问普通退票查一个库可能够，问“会员如何退改签”可能要联合查。

路由就是决定搜哪里。评测不仅看库是否选对，还看最终找齐了哪些证据以及多查带来的成本。

**直答：** 按问题的信息需求决定单库或跨库检索，测试路由错误、证据完整性和资源代价，避免把多库简单串在一起。

### 进一步：公式、边界与追问

**技术表述：** 先定义每库的知识边界、权限与更新周期，再支持单库、多库和不确定路由。

**展开：** 将任务标注为需哪些库的证据；统计漏路由、错路由、跨库组合、无库可答。低置信度可多库召回后重排，而非强迫单选。

**追问：路由准确率高但回答差？** 可能路由标签太粗、证据缺失、检索失败或跨库规则冲突。做 oracle 路由对照估计其损失上界。

**易错：** 只按“问题中有某个词”硬编码时，要测同义和歧义例。

## R10｜查询改写、HyDE、多跳检索有什么风险？（P1）


### 换个问法有助于查书，也可能把原问题改偏

查询改写尝试更适合检索的表达；HyDE 先生成假想答案再用它检索；多跳检索根据前一次结果继续查下一步。

这些中间文字不是已经证实的事实。如果假想答案错了，还被后面当真，就会把搜索带向错误方向。

**直答：** 查询扩展可以提高覆盖，但必须保留原始意图、追踪证据来源，并检查中间生成错误是否被放大。

### 进一步：公式、边界与追问

**技术表述：** 它们扩展查询表达与检索路径，但也可能改错意图或引入虚构约束。

**展开：** 保留原 query，与改写结果联合检索；多轮改写应解析指代但保留实体、日期、否定与权限。HyDE 类方法用假设文档帮助检索，不能把其内容当真实证据。

**追问：多跳什么时候停？** 依据证据覆盖、预算、重复查询或无法解决的冲突停止，必要时澄清。

**易错：** 将改写器编造的航班号或规则编号传给后续会放大错误。依据：S70。

## R11｜Faithfulness、正确性、完整性、引用精度怎么区分？（P0）


### 说得有出处、说得对、说得全，是不同要求

回答忠实于旧手册，却可能不符合新政策；引用了一条真实规定，却漏掉关键例外；标了引用，但那一页其实不支持该结论。

所以要分别检查是否依照给定证据、事实是否正确、所需内容是否完整、每条引用是否真的支持它旁边的话。

**直答：** 忠实性、正确性、完整性和引用支持度分别回答不同问题，不能用“带引用”直接证明答案可靠。

### 进一步：公式、边界与追问

**技术表述：** 忠实性看是否被证据支持，正确性看是否符合真值，完整性看需求覆盖，引用精度看引用是否真正支持所附结论。

**展开：** 证据本身过期时，回答可以忠实但错误；回答事实正确但没被所引文档支持，则引用不可靠。将回答拆成可核对 claims，分别标支持与覆盖。

**追问：RAGChecker 的价值？** 用细粒度诊断区分检索和生成问题，比只看一个总体生成分数更可操作。

**易错：** 有引用标记不等于引用有效，引用到整本手册也未必可定位。依据：S29。

## R12｜证据冲突、缺失、过期时怎么回答？（P0）


### 两本手册互相矛盾，不能随便挑一句顺眼的

先看版本、适用对象、发布权限和时间；如果仍无法消除冲突，就说明冲突在哪里，并按任务要求进一步确认。

找不到证据时也不要用流畅表达掩盖缺失。区分资料确定支持的内容与仍待核实的部分。

**直答：** 冲突先核版本和适用范围，缺失就明确说明并继续查证或升级处理，让回答强度与证据强度匹配。

### 进一步：公式、边界与追问

**技术表述：** 按来源权威、适用范围和生效日期处理；缺证据则澄清、查工具或明确不能确认。

**展开：** 文档版本与事件发生时间可能不同；新规则不一定适用于旧订单。引用中保留条款位置、版本和有效期，不让模型凭措辞自信决定哪个为准。

**追问：无证据拒答怎么评测？** 构造可答、缺证据、冲突和过期四类，分别测有效帮助、正确拒答与误拒。

**易错：** 最新发布时间不必然等于最新生效规则。

<a id="R13"></a>
## R13｜Self-RAG、RAPTOR、GraphRAG 各有什么价值？（P1）


### 检索也可以学会反思、做层级笔记、整理关系

Self-RAG 关注是否需要检索及生成后的自我评价；RAPTOR 用分层摘要组织资料，帮助不同粒度的检索；GraphRAG 利用关系组织或汇总信息，支持某些跨文档问题。

它们不是同一个算法换名字，各有建立索引和维护的成本。

**直答：** 先识别当前困难是检索决策、层次概括还是跨文档关系，再考虑对应方法，并与简单基线比较。

### 进一步：公式、边界与追问

**技术表述：** Self-RAG 研究何时检索与自我评估；RAPTOR 用层级摘要服务不同抽象层的问题；图式检索适合实体关系和跨文档聚合。

**展开：** 增加结构会带来构建、更新与错误传播成本。摘要可能遗漏限制条件，图边可能抽取错，反思标签也需可靠训练。

**追问：企业小知识库是否都要 GraphRAG？** 不需要先假定；与简单混合检索比较多跳覆盖、事实可靠、延迟与维护成本。

**易错：** 原论文的学习式 Self-RAG 不等于在提示词加一句“请反思”。依据：S27、S28、S71。

<a id="R14"></a>
## R14｜RAG 变差如何快速归因？（P0）


### 分阶段问：书在不在、找没找到、读懂没有

先确认答案证据确实进入了索引；再看检索是否拿到、重排是否保留；最后把正确证据直接给模型，看它能否答对。

这个“替换成已知正确输入”的办法能缩小问题范围，比盲目增大模型或切片更有效。

**直答：** 沿解析、索引、召回、重排、生成逐层检查，用正确证据替换实验定位瓶颈，再做针对性修复。

### 进一步：公式、边界与追问

**技术表述：** 顺着“数据是否存在→能否召回→是否保留→模型是否使用”逐层查。

**展开：** 先找 gold evidence；不存在是数据问题；存在却没进候选是解析/路由/召回；候选有但重排后没了是排序；输入有却答案错是组织或生成。用人工正确证据替换检索结果，看端到端提升上界。

**追问：长上下文里证据明明在为什么仍错？** 可能位置、干扰、冲突或条件组合难，需做位置交换与噪声消融。

**易错：** 不先做 oracle 分析就换更大模型，可能花钱掩盖上游错误。

<a id="R15"></a>
## R15｜向量库为什么常用 ANN，HNSW 怎么取舍？（P1）


### 百万资料里找邻居，不一定逐个量距离

ANN 是近似最近邻搜索，允许少量近似误差，换取更快查询。HNSW 把向量组织成多层邻接关系，可以先大步靠近，再细找相似向量。

搜索更仔细通常能找到更好的邻居，但也更慢、更耗资源。“向量邻居近”仍不保证它能回答业务问题。

**直答：** ANN 加速相似向量查找，HNSW 用分层图搜索实现速度与召回的取舍；最终还要评估真实证据检索效果。

### 进一步：公式、边界与追问

**技术表述：** 近似最近邻 ANN 以少量召回损失换取大规模检索速度；HNSW 利用分层邻近图，从粗层导航到细层搜索。

**展开：** 图的连接度、构建搜索与查询搜索预算影响内存、构建时间和召回。需要用精确检索作小样本参照，再调实际质量—延迟曲线。

**追问：ANN recall 高就代表 RAG 好吗？** 它常衡量相对精确向量近邻的找回率；精确向量近邻本身也可能不是支持答案的证据。

**易错：** 索引 recall、语义 relevance recall、最终答案正确率是三个不同层次。依据：S78。
