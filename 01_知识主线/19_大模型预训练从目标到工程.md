# 19 · 大模型预训练：从目标到工程

**先建立一个完整画面：**预训练把大量文本变成“根据前文预测后文”的练习。训练系统负责把文本送进模型、算错多少、更新参数并不断检查是否学到了可迁移的能力。

第 3 章讲数据治理；本章把**训练目标 → 数据与分词 → 模型与预算 → 优化与工程 → 评测 → 后续训练**串起来。先读 PT01、PT02、PT04、PT08、PT10、PT11、PT17、PT20，再补工程细节。

| 阶段 | 核心产物 |
|---|---|
| 准备教材 | 可追踪的数据版本、切分、过滤和配比 |
| 定义练习 | tokenizer、预测目标、样本边界与 mask |
| 定义学生 | 模型结构、参数规模、上下文长度 |
| 开始学习 | 优化器、学习率、批次、数值精度和训练日志 |
| 防止白学 | 独立评测、稳定性监控、可恢复的检查点 |
| 进入应用 | 继续训练、SFT、RL、蒸馏与工具系统 |

这里提供方法理解和实验设计，不将预训练经验写成你的既有项目经历。开放训练案例采用 Olmo 3、DeepSeek-V3 等一手技术资料，明确它们不是同一套配方。

<a id="PT01"></a>
## PT01｜预训练没有人逐题标答案，模型到底在学什么？（P0）

**先看例子：**原文是“北京是中国的首都”。把前半句“北京是中国的”给模型，后面的“首都”就能充当目标。答案来自原文自身，所以这种学习叫自监督。

模型要在大量语境里预测合理的后续内容，就会学习语法、事实关联、表达方式以及某些可复用的推理模式。但原文也有错误，目标不是一个自动保证真实性的机制。

**直答：**自回归语言模型预训练主要利用文本自身构造下一 token 预测任务，通过降低预测损失学习文本中的统计规律和可迁移表示。

### 进一步：公式、边界与追问

给定一段 token 序列 x，常见目标为：

$$L_{\mathrm{NTP}}=-\frac{1}{T}\sum_{t=1}^{T}\log q_\theta(x_t\mid x_{<t})$$

xₜ 是实际出现的下一个 token，T 是本次计分的有效目标数；实现会处理序列起点、padding 与文档边界。基础负对数解释见 M02。

**追问：预测下一个词为什么能出现推理能力？**为了在很多复杂语境中预测后续，模型有机会学到有用的结构和规律；但这不是“只要训练就必然会推理”的定理。需要用未见任务、变体题和干预评测判断。

**追问：预训练后的 base model 为什么不一定像聊天助手？**它主要练续写，未必充分练过遵循用户指令和工具协议；后续训练可进一步塑造这些行为。依据 S48、S100。

<a id="PT02"></a>
## PT02｜一次预测训练里，输入、标签和因果 mask 怎么对应？（P0）

**先看例子：**把文本简化成四个 token：[我，喜欢，机器，学习]。训练时可以同时练三道小题：“我→喜欢”“我喜欢→机器”“我喜欢机器→学习”。

虽然这些练习并行计算，每次预测仍只能读取目标之前的内容。例如输入位置“机器”可以看见“我喜欢机器”，但不能偷看要预测的“学习”。

**直答：**因果语言模型把输入与目标错开一个位置，用因果 attention mask 限制可见前文，再只对有效目标计算损失。并行训练不等于可以看见未来。

### 进一步：公式、边界与追问

~~~text
输入位置：  我       喜欢       机器
预测目标：  喜欢     机器       学习
可见前文：  我       我喜欢     我喜欢机器
~~~

一些模型接口允许 labels 与完整 input_ids 相同，由模型内部做移位；另一些接口要求调用方自行移位。必须确认具体实现，不能多移或漏移。

**追问：loss mask 和 attention mask 有什么区别？**前者决定哪个目标直接计分；后者决定当前位置能读取哪些信息。一个不计分的上下文 token，仍可能被后面的预测读取，见 KD11。

**检查：**打印一条样本的输入 token、目标 token、有效标签和注意力可见范围。损失很低但目标等于当前位置已知输入，是常见的错误信号。依据 S01、S48；例子为教学简化。

<a id="PT03"></a>
## PT03｜下一词预测、掩码预测、FIM，训练目标有什么不同？（P0）

**先看例子：**“今天下雨，所以我带了……”是续写；“今天下雨，所以我带了［空白］出门”是补空；代码编辑则常需要同时看缺口前后的程序，再补中间一段。

**直答：**下一 token 预测按顺序续写；掩码语言建模利用保留下来的上下文恢复被遮住的内容；FIM 通过数据变换教自回归模型在给定前后文时补中间部分。

### 进一步：公式、边界与追问

| 目标 | 可见信息与训练方式 | 常见用途 |
|---|---|---|
| Causal LM / NTP | 看当前序列前缀，预测下一个 token | 自回归生成 |
| MLM | 预测被遮住的 token，可利用双向上下文 | BERT 类表示学习 |
| FIM | 将原文拆成前缀、中间、后缀，重排后训练生成缺口 | 代码补全与编辑 |

FIM 仍可使用自回归网络：先把允许提供的前后文作为输入，再生成目标中间段。这里“后缀可见”是任务定义，不是将该段要生成的答案泄漏给自己。（S59、S103）

**追问：把 FIM 数据全部替换掉普通续写数据好吗？**要对照配比及普通续写能力；任务分布改变会影响能力侧重，不能仅凭 FIM 测试提升决定全部替换。

<a id="PT04"></a>
## PT04｜Tokenizer 是预处理小细节，还是会影响模型能力？（P0）

**先看例子：**同一句中文，一种分词方式切成十个 token，另一种切成二十个。在上下文最多容纳 4096 个 token 时，能放进去的实际内容会不同，训练与推理的计算量也会变化。

**直答：**Tokenizer 决定文本怎样变成离散符号，影响压缩率、上下文利用、不同语言的表示以及词表参数规模。设计时要覆盖目标语言、代码和特殊格式，并验证可还原性。

### 进一步：公式、边界与追问

常见子词方法包括 BPE 与 Unigram；是否按字节处理、是否使用字节回退、怎样规范化文本，需要看实现。编码和解码还涉及空格、换行、Unicode、特殊 token。

**追问：词表越大越好？**较大的词表可能缩短序列，但会增加嵌入与输出层规模，一些低频 token 也可能训练不足。词表大小与 token 数量、参数和语言覆盖要一起比较。

**追问：中文每个字都对应一个 token 吗？**不一定。字符、字节、子词与 token 不是一回事。还不能直接比较不同 tokenizer 下的每 token 困惑度，见 PT17。依据 S58。

<a id="PT05"></a>
## PT05｜预训练数据流水线应该怎样组织？（P0）

**先看例子：**从网页抓到一页内容，里面可能混着导航栏、重复页脚、广告和正文。把整页都喂给模型，会让大量算力用来记重复模板。

**直答：**先解析提取正文，再进行语言识别、质量过滤、去重、污染检查、分组切分、配比与分词；每一步保留版本和统计，使训练结果能追溯到具体数据。

### 进一步：公式、边界与追问

一条可审查的流程是：数据来源登记 → 内容提取 → 语言/领域识别 → 规则与模型过滤 → 精确/近似去重 → 开发测试隔离 → 分词打包 → 训练。

顺序可按场景调整，但必须清楚“过滤”和“切分”依赖了什么信息。近重复族应尽量在切分前识别，避免同一家族跨训练与测试。

**追问：英语过滤规则直接用于所有语言行吗？**FineWeb2 针对多语言处理差异研究自适应流水线，提醒我们不能把某种标点、长度或重复率阈值机械套到所有语言。（S101）

**追问：全用高分数据可以吗？**过滤器可能误删方言、专业资料或少数语言。抽查保留与删除样本，并做固定训练 token 的下游对照。数据细节见 D03、D04。

<a id="PT06"></a>
## PT06｜文档怎样变成训练序列？EOS 能阻断跨文档信息吗？（P0）

**先看例子：**文章 A 只有 100 个 token，训练序列可以装 2048 个。直接填满 padding 很浪费，于是会把多篇文章装进一个训练块。

**直答：**打包提高有效 token 比例，但必须规定文档边界、EOS、截断、position ID、attention mask 和 loss mask。EOS 是一个符号，本身不等于阻断跨文档注意力。

### 进一步：公式、边界与追问

两种设计都可能合理：将文本流连接后做因果预测；或将独立文档装进一个块，同时用 mask 隔开它们。关键是训练与评测声明一致，并监测边界附近的预测。

**追问：只重置 position ID，就隔离文档了吗？**没有。位置编号说明“在什么位置”，可见范围由注意力规则决定；具体快速注意力接口可能通过额外的变长序列信息处理边界。

**追问：训练长文时截断哪里重要？**截断可能切断代码、数学证明和问答关系。可比较连续片段、文档对齐与长度混合的效果，并统计文档完整性。依据 S48、S100；更短的入门解释见 D06。

<a id="PT07"></a>
## PT07｜预训练数据配比怎么决定？DoReMi 在解决什么？（P1）

**先看例子：**教材包含网页、书籍、代码和数学。按原始数量混合，网页可能占绝大多数；人为把代码拉高，又可能减少其他领域得到的训练机会。

**直答：**配比决定每个领域消耗多少训练 token。可以用固定预算的小模型实验比较；DoReMi 则用较小的代理模型学习领域权重，再用该权重训练较大的模型。

### 进一步：公式、边界与追问

S102 的 DoReMi 以领域重加权和稳健优化为核心。代理训练根据相对参考模型的学习情况分配领域权重，再把得到的混合比例用于大模型；它不是简单“哪个领域原始 loss 最大，就永远多喂哪个”。

**追问：小模型最优比例能直接迁移吗？**这是一种需要验证的经验迁移。模型规模、tokenizer、训练长度与目标能力不同，比例可能改变。

**追问：我应该报样本占比还是 token 占比？**两者都可记录，计算预算尤其要看 token。十条长代码可能比一百条短句占用更多训练与损失权重。基础见 D05。

<a id="PT08"></a>
## PT08｜参数量、数据量、算力，怎样一起算预算？（P0）

**先看例子：**同样预算可以让大模型少读一点，也可以让小模型多读一点。模型很大但没读够材料，容量未必用得上；反复读高度重复的数据，也未必继续有效。

**直答：**用参数、训练 token 与计算的经验关系建立候选预算，再用小规模实验校准。Chinchilla 提供训练计算最优的研究依据，但部署量很大时，还应考虑整个生命周期的成本。

### 进一步：公式、边界与追问

对常见 dense Transformer，粗估训练计算：

$$C\approx 6ND$$

N 是参数量，D 是训练 token 数，C 是浮点运算次数的估计。例如 N=10 亿、D=200 亿，得到约 1.2×10²⁰ FLOPs。

**追问：FLOPs 能直接除以显卡宣传峰值算训练时长吗？**那只是理想下界式估计；实际要考虑有效吞吐、通信、数据加载、重计算、故障和利用率。长上下文注意力与 MoE 还会改变这个粗估的适用性。

**追问：token 与参数的比例是否固定？**不是。数据质量、模型结构、额外训练收益与推理服务规模都会影响选择。依据 S05、S48。

<a id="PT09"></a>
## PT09｜预训练选择 dense 还是 MoE，主要权衡什么？（P1）

**先看例子：**Dense 像每道题都让同一整组网络处理；MoE 则在部分层里把每个 token 分配给少数专家。总容量可以很大，但每次并不调用全部专家。

**直答：**Dense 的计算与实现较直接；MoE 用稀疏激活扩大总容量，同时引入路由、负载均衡、通信和专家训练覆盖问题。比较时要同时报告总参数和每 token 激活参数。

### 进一步：公式、边界与追问

专家不是预先保证有明确职业分工的人类专家，路由也不自动代表语义分类。不同架构可能采用共享专家、不同稀疏层比例和负载处理策略。

**追问：激活参数少，就一定更省显存吗？**计算量和权重存储是两回事。未激活的专家仍需要存放或调度，分布式通信与服务批次也影响成本。

**追问：只看理论 FLOPs 够吗？**还要看实际吞吐、硬件拓扑、通信等待、专家负载和收敛。DeepSeek-V3 提供 MoE、注意力、精度与训练系统共同设计的案例，不是仅靠 MoE 一项改动。（S48、S60）

<a id="PT10"></a>
## PT10｜AdamW、学习率预热和衰减，各负责什么？（P0）

**先看例子：**模型刚开始学习时，参数和优化器统计还没稳定，步子太大容易摔倒；后期已经接近不错的解，继续大步跳也可能扰动已学到的内容。

**直答：**AdamW 利用梯度历史调整更新尺度，并将权重衰减与梯度更新分开；warmup 逐渐提高学习率，后续调度再控制学习强度。它们一起影响训练速度和稳定性。

### 进一步：公式、边界与追问

权重衰减可直观理解为让权重适度收缩，但 AdamW 不是把 L2 惩罚简单加进 Adam 梯度就一定完全等价。具体参数组是否衰减也需记录。（S55）

常见学习率调度包括预热后余弦衰减，以及预热、稳定训练、再衰减等分阶段方案。不同配方的训练长度、token 批次和停止策略不同，不提供脱离上下文的唯一“最佳学习率”。

**追问：loss 抖动就把学习率降十倍吗？**先查数据批次、有效 token 数、梯度范数、精度溢出和训练恢复状态。盲目降学习率可能遮住数据或实现错误，见 PT13。工程实例见 S48、S100。

<a id="PT11"></a>
## PT11｜全局 batch、梯度累积、训练步数，怎么换算？（P0）

**先看例子：**8 张数据并行卡，每张一次处理 2 条长度 1024 的序列，积累 4 次再更新。如果都没有无效 token，一次参数更新就看过 65536 个 token。

**直答：**全局更新批次由数据并行份数、每卡微批次和累积次数共同决定；训练预算还要乘有效序列长度与更新次数。模型并行使用的卡不能重复算成数据并行份数。

### 进一步：公式、边界与追问

设 n 为数据并行份数，b 为每份微批次序列数，g 为累积次数，L 为序列长度：

$$B_{\mathrm{tokens}}=n\,b\,g\,L$$

上例是 8×2×4×1024=65536；1000 次更新约处理 6553.6 万个 token。若有 padding、mask 或不同长度，应统计实际有效 token。

**追问：两个微批次的平均 loss 直接再平均就行吗？**只有有效 token 数相同等条件下才等价。例如两个批次平均损失为 1 和 3，有效 token 分别为 2 和 6，总平均应是 2.5，不是 2。

**追问：梯度累积与真大 batch 完全一样吗？**需要相同损失归一化和更新时机等条件；随机层、数值顺序与某些跨样本运算还可能造成差异。分布式基础见 X01、X02；工程依据 S35、S48。

<a id="PT12"></a>
## PT12｜BF16、FP16、FP8，精度降低会怎样影响训练？（P1）

**先看例子：**用较少位数记录一个数，可以减少存储和数据搬运，但细小差别或极大数值可能表示不好。训练里有很多次相乘与累加，小误差也可能累积。

**直答：**混合精度让适合的运算使用低精度，把敏感的累积、缩放或统计保留在更合适的精度。要同时关注动态范围、有效精度、硬件支持和训练稳定性。

### 进一步：公式、边界与追问

BF16 与 FP16 都是 16 位，但指数与尾数分配不同；不能只按位数推断动态范围和误差。FP8 训练还涉及缩放粒度、异常值和哪些张量允许降精度。

**追问：把所有张量直接转成 FP8 就是 FP8 训练吗？**不是。DeepSeek-V3 的技术报告涉及精度管理和训练系统配套，不能将其结果归因于一次类型转换。（S48）

**追问：混合精度出 NaN，先查什么？**定位第一次非有限值出现的层和步骤，检查输入、激活/梯度范围、缩放、归一化及优化器状态；先构造小规模可重复样本再扩大训练。

<a id="PT13"></a>
## PT13｜预训练 loss 突然尖峰，应该怎么排查？（P0）

**先看例子：**模型训练了几天，某一步 loss 突然升高。可能是遇到异常数据，也可能是学习率、数值精度、损坏检查点或分布式同步出了问题；仅凭一条曲线无法区分。

**直答：**记录尖峰的样本、模型状态和系统指标，先判断是单批数据难度变化、持续优化发散还是工程故障，再决定跳过异常样本、回滚或修正训练配置。

### 进一步：公式、边界与追问

建议保留：全局有效 token、学习率、loss 与分领域 loss、梯度范数、非有限值、吞吐、数据游标、随机状态和检查点版本。不要只保存一份最后权重。

**追问：断点恢复只加载模型参数够吗？**继续同一训练轨迹还需要优化器、学习率调度器、数据进度、随机状态，部分设置还涉及缩放器和分布式状态。遗漏会改变实际训练过程。

**追问：遇到尖峰直接删那批数据行吗？**可以作为诊断对照，但需解释删除规则和影响；难而正确的数据不应因为 loss 高就被全部删掉。依据 S48、S100；清单是工程归纳。

<a id="PT14"></a>
## PT14｜长上下文能力，是把最大长度参数改大就有了吗？（P0）

**先看例子：**模型原来只练过几页材料，突然给它一本书，即使输入接口接受，也不代表它能找到跨章节线索或可靠使用最前面的信息。

**直答：**扩展上下文通常涉及位置表示、长序列训练数据、训练阶段与计算资源，并需要长距离任务评测。能接收更多 token 与能正确利用它们是两件事。

### 进一步：公式、边界与追问

常见方案会在基础训练后加入长上下文训练，配合位置扩展和长短数据混合；具体阶段长度与比例按技术报告记录。Olmo 3 与 DeepSeek-V3 提供了各自的训练流程案例。（S100、S48）

**追问：只做“大海捞针”够吗？**只能覆盖一部分检索行为，还要测试多证据整合、顺序依赖、跨段推理、长代码理解和无关信息干扰。

**追问：训练代价主要多在哪？**除了 token 数增多，注意力计算、激活与通信也可能增加；FlashAttention 降低内存访问开销，不自动把标准全注意力的算术复杂度变成线性。见 T04、I03。

<a id="PT15"></a>
## PT15｜MTP 多 token 预测，和普通下一 token 预测怎么衔接？（P1）

**先看例子：**普通练习只问“接下来一个词是什么”；多 token 预测还让模型练更靠后的目标，提供更多训练信号。它在某些实现中还能为推理时的草稿生成服务。

**直答：**MTP 是 Multi-Token Prediction，通过附加目标或模块预测多个未来位置。不同架构可能采用独立或顺序关联的预测模块，不能把一个通用名字当成同一计算图。

### 进一步：公式、边界与追问

一个用于理解目标组成的简式是：

$$L=L_{\mathrm{next}}+\sum_{k=2}^{K}\lambda_k L_{\mathrm{future},k}$$

第一项练下一个 token，后面的项练更远目标，λ 控制权重。这个式子不规定各预测头如何共享信息，也不替代具体实现。

**追问：是否能在当前预测时直接看见未来答案？**不能通过输入或注意力路径把当前目标泄漏给自身预测。若顺序 MTP 模块使用前一预测步的训练 token，还需逐层核对位移和可见关系。

**追问：训练用了 MTP，推理就必定一次输出多个 token 吗？**不一定。DeepSeek-V3 讨论 MTP 辅助训练；MiMo-V2-Flash 还研究将 MTP 模块用于推测解码。实际使用方式和加速需要分别测量。（S48、S93）

<a id="PT16"></a>
## PT16｜继续预训练、mid-training 和 SFT，怎么区分？（P0）

**先看例子：**模型已经广泛读过书，接下来可以补读一批专业资料，也可以练长代码、多步推理或工具格式，之后再做面向用户的指令训练。研究团队可能把这些中间阶段起不同名字。

**直答：**继续预训练通常延续语言建模等基础目标来适配新数据；mid-training 常指基础预训练与最终后训练之间的能力强化阶段，定义不完全统一；SFT 则以示范输出进行监督学习。

### 进一步：公式、边界与追问

判断阶段时，直接列出“输入数据、预测目标、更新参数、训练规模、想改变的能力”。阶段名字不能代替这些信息。

继续预训练与 SFT 都可以使用下一 token 的负对数损失；常见差别在于训练材料怎样组织、哪些位置计分，以及想培养什么行为。不能只看损失函数名字判断阶段。

**追问：训练数据是领域文档，就一定叫预训练吗？**还要看怎么构造样本和目标。把文档用于续写，与把它变成问题—回答对，训练信号不同。

**追问：一份报告里的 mid-training 配方能当行业标准吗？**不能。Olmo 3 给出其公开生命周期，可用于理解具体阶段；其他团队可能用不同名字或边界。（S100）基础阶段对比见 D01。

<a id="PT17"></a>
## PT17｜预训练模型怎么评测？loss 低就代表更好吗？（P0）

**先看例子：**一个模型把网页模板背得很熟，平均预测损失降低了，却仍不会理解新代码。另一个模型在中文上进步，在英语上退步，总平均可能掩盖这种变化。

**直答：**同时看独立文本上的预测损失、分语言分领域表现，以及目标能力任务。沿训练过程比较 checkpoint，并检查数据污染、遗忘和成本。

### 进一步：公式、边界与追问

相同 tokenization、目标与计分规则下，困惑度常写为：

$$\mathrm{PPL}=\exp(L_{\mathrm{NLL}})$$

L 使用自然对数且按有效 token 平均。它衡量对参考文本的预测，不直接等于推理、安全或 Agent 成功率。

**追问：不同 tokenizer 的 PPL 能直接比吗？**计量单位变了，通常不能直接比较每 token PPL；可考虑统一数据和更可比的字节等单位指标，仍需说明预处理规则。

**追问：为什么还要保留分领域曲线？**总体平均的改善可能来自容易领域占比变化，掩盖关键能力退化。报告 token 预算、验证分布和下游指标，避免只挑单个最佳 checkpoint 的分数。依据 S05、S100、S101。

<a id="PT18"></a>
## PT18｜新人怎样做一个能证明理解预训练的小实验？（P0）

**先看例子：**先训练一个很小的文本续写模型，确认它从接近随机预测逐步学会局部结构；再改变数据去重或配比，看独立文本表现如何变化，比一开始就规划训练巨大模型更容易定位问题。

**直答：**固定小模型、tokenizer 和训练预算，只改变一个因素，保存训练与验证曲线、生成样本、有效 token 和资源消耗。重点是能解释结果与失败，而非只交一个训练脚本。

### 进一步：公式、边界与追问

建议两层实验：

1. CPU 数值层：检查输入标签移位、因果可见性、有效 token 平均和预算换算。
2. 可用训练资源下的小模型层：比较原始数据与去重数据，或两种数据配比；保持有效训练 token 和评测规则一致。

**追问：代码跑通就算预训练项目吗？**它证明实现可以执行；能力结论仍需独立验证、对照和资源记录。若只计算过几条公式，就如实写成数值练习。

**交付模板：**数据版本与切分、模型配置、训练目标、优化设置、计算预算、曲线、样本、异常排查和结论适用范围。见“03_代码实验/后训练与预训练数值练习.md”。本题是实验设计，未声称已完成模型训练。

<a id="PT19"></a>
## PT19｜想看完整开放训练流程，Olmo 3 能帮助理解什么？（P1）

**先看例子：**只有最终模型，像只拿到一张毕业证；如果还能看到教材、训练阶段、检查点和评测，你就能追问“这项能力在哪一步出现，付出了什么代价”。

**直答：**Olmo 3 的公开材料强调完整模型生命周期，适合把数据、基础训练、中间阶段和后训练串起来研究。它的价值在于可审查的流程，而非可以不加条件地复制其所有超参数。

### 进一步：公式、边界与追问

阅读 S100 时按四列做笔记：阶段输入；优化目标；预算与配置；对应能力评测。然后对照 S48 的 DeepSeek-V3，区分 dense/MoE、精度、数据、MTP 等不同选择。

**追问：开放流程就等于自己能完全复现吗？**还取决于硬件、数据可得性、软件版本与计算预算。复现可以从缩小规模的机制对照开始，并明确与原设置的差别。

**追问：能把公开训练报告写成自己的项目吗？**只能把真实完成的阅读、分析或缩小实验作为个人工作；原团队的训练规模与成绩应明确归属。依据 S100。

<a id="PT20"></a>
## PT20｜预训练、后训练、蒸馏，怎样串成一次完整面试回答？（P0）

**先看例子：**先让模型广泛学习语言和知识，再用示范与反馈教它按要求完成任务，最后把昂贵或分散的专家能力迁移到适合部署的学生。部署后的工具环境和失败案例又会形成新的训练材料。

**直答：**预训练建立广泛能力基础；SFT、偏好优化和 RL 塑造任务行为；蒸馏利用教师信号迁移或整合能力。实际流程可以交替，最终按任务成功、可靠性与总成本评价。

### 进一步：公式、边界与追问

一分钟回答可以按这条顺序组织：

“先定义任务和预算，准备可追踪、去重且独立切分的数据；选择 tokenizer、模型结构与训练目标，控制有效 token、优化与数值稳定性。基础训练后，用示范与反馈发展目标能力。如果已有强教师或多个领域专家，再分别考虑 OPD、OPSD、MOPD 等迁移方式。最后在部署信息条件下测泛化、失败恢复、延迟与每成功任务成本。”

**追问：预训练不强，后训练能补多少？**可通过改进表达、探索和利用已有能力获得收益，也可能学习新任务模式；但不是无限补偿数据和容量不足。需比较不同基础 checkpoint 与相同后训练预算，见 F02、F07。

**追问：这几个阶段是不是严格先后？**不必。继续训练、数据合成、专家 RL 与蒸馏可以形成循环；描述你自己的方案时把每次输入、输出和评测边界写清。阶段案例依据 S48、S92、S100。
