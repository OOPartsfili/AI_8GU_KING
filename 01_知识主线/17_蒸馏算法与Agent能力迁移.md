# 17 · 蒸馏算法与 Agent 能力迁移

**先抓住一个画面：**公司有一位能力强、调用费用高的“老师”，想让便宜、响应快的“学生”接手一类重复工作。要搬过去的不是老师的参数文件，而是可观察、可验证的做事能力。

本章共 34 题。**要看 OPD、OPSD、MOPD，先读 KD25 → KD27 → KD29 → KD34**：依次弄清学生在哪里学习、老师怎样构造、多个老师如何整合。再用 KD26 理解更新信号。

本章贯穿一个教学场景：用户要查订单，助手需要补齐订单号、查订单工具、读返回结果、给出有依据的答复。所有数字和业务方案都是教学设计，不是论文实测。

**第一遍先读：KD01 → KD02 → KD03 → KD05 → KD07 → KD11 → KD17 → KD21。**再读 KD22 做项目方案。KD09、KD10、KD14、KD15 放在理解基本流程之后。

| 想让学生学什么 | 典型做法 | 最先确认什么 |
|---|---|---|
| 老师写出的答案 | 序列蒸馏，用教师文本做 SFT | 答案是否正确、学生部署时有没有同样的输入 |
| 老师对下一步的判断 | 软标签蒸馏、GKD、MiniLLM | 能否取到所需概率，词表与上下文是否对齐 |
| 查资料、调工具、处理异常 | Agent 轨迹蒸馏 | 工具是否真实执行，观察与动作是否分开 |
| 学生走错以后怎么补救 | 学生采样 + 教师纠正，DAgger/OPD 思路 | 老师是否看见学生真正到达的状态 |
| 从做完的任务中总结经验 | 自蒸馏，结合反馈或技能的训练 | 经验是否可靠，训练提示能否被真正学进参数 |
| 用参考解帮助老师评价学生路径 | OPSD（KD27） | 训练参考信息与测试输入严格区分 |
| 整合几个领域专家的能力 | MOPD（KD29） | 教师专长、任务路由、同预算对照 |
| 从环境详细反馈中学习 | SDPO（KD31） | 反馈是否可靠，教师怎样更新 |

“高级模型”通常提供较强的教师行为，但教师可能出错。蒸馏能迁移哪些能力，需要用具体任务和部署预算验证；模型名字本身不是效果保证。一般概率、交叉熵、KL 的前置解释见 M02、M04、M07。

<a id="KD01"></a>
## KD01｜蒸馏究竟在蒸什么？和 SFT、量化有什么区别？（P0）

**先看例子：**老师处理过一批订单咨询，把“缺订单号先询问、查到后按事实回答”的过程留下来。学生反复练这些示范，希望以后独立完成同类任务。

这里的“知识”包括答案格式、选择工具的习惯、判断依据和处理异常的办法。学生不一定更小；同样规模的模型，也能通过更好的示范或反馈改善某项能力。

**直答：**蒸馏是用教师提供的行为或信号训练学生；SFT 是一种训练方式，所以“用教师答案做 SFT”本身就可以是蒸馏。量化则是减少权重或计算使用的数值精度，主要改变存储与计算方式，二者可以组合。

### 进一步：公式、边界与追问

按信号分，常见有教师输出文本、下一 token 的概率分布、中间表示和任务交互轨迹。不能只问“有没有蒸馏”，要补齐“教师给了什么、学生在哪些输入上学习、损失怎样算”。

**追问：学生能超过老师吗？**可能在某个测试任务上超过，例如数据筛选和任务专门化带来收益。但这不是获得老师全部能力，也不保证跨任务更强；比较时还要统一工具、提示词和推理预算。

**依据：**S79、S80；本题的订单例子为教学设计。

<a id="KD02"></a>
## KD02｜只能调用教师 API，还能蒸馏吗？（P0）

**先看例子：**你可以问老师问题，拿到完整答案，却看不到老师给每个候选词打了多少分。这仍足够制作“问题—优质回答”训练对，也可以收集工具调用过程。

如果接口额外返回部分 token 的概率，那只是多拿到一些信息，不等于看见全部词表。

**直答：**能。只有文本时，先做答案或轨迹蒸馏；拿到兼容的概率分布后，才考虑相应的 token 级 KL 方法。先盘点接口实际返回什么，再选算法。

### 进一步：公式、边界与追问

| 能拿到的信号 | 可行方向 | 常见误会 |
|---|---|---|
| 文本、工具调用与真实执行结果 | 序列 SFT、轨迹 SFT、验证后筛选 | 文本不能还原教师全部 logits |
| 少量候选 token 的 logprob | 显式说明近似的分布训练或置信度特征 | top-k 重新归一化不是原始全词表 KL |
| 兼容词表上的完整概率 | 软标签 KD、所需条件满足时的 GKD | 还须对齐每个位置的上下文 |
| 可访问教师内部张量 | 中间层、特征蒸馏 | 张量维度相等也不保证语义对齐 |

**追问：教师和学生分词不同怎么办？**序列文本可以分别分词。逐 token 概率不能直接按数组下标相减；需要有定义的对齐方法，或者换用文本级监督。详见 KD16。

**依据：**S79、S80、S88。具体商业接口能力随版本变化，实施时核对实际接口。

<a id="KD03"></a>
## KD03｜软标签、温度和 T²，能用一个例子讲清吗？（P0）

**先看例子：**把下一步简化成三个动作：“查订单、查天气、直接猜”。硬标签只告诉学生“选查订单”。软标签还告诉学生老师对三项的判断，例如 90%、8%、2%。后者额外表达了备选动作之间的差别，但这些差别也可能包含教师的错误。

温度像把尖锐的分数差距摊平一些。温度升高时，原本接近零的选项通常更容易被看见；温度过高又可能把有用区别冲淡。

**直答：**软标签让学生学习老师对多个候选的概率，而不只学一个答案。经典蒸馏把师生 logits 都除以温度 T，再比较概率；T² 用于补偿高温下软目标梯度变小的尺度效应。

### 进一步：公式、边界与追问

logit 就是 softmax 前的原始分数。教师分数记为 v，学生分数记为 z：

$$p_i^{(T)}=\frac{\exp(v_i/T)}{\sum_j\exp(v_j/T)}$$

$$q_i^{(T)}=\frac{\exp(z_i/T)}{\sum_j\exp(z_j/T)}$$

一种常见的组合目标是：

$$L=(1-\alpha)L_{\mathrm{hard}}+\alpha T^2 D_{\mathrm{KL}}(p^{(T)}\|q^{(T)})$$

硬标签项在温度 1 下计算；α 控制两个教学信号的比例。教师固定时，软标签交叉熵与上述正向 KL 对学生的梯度相同。

**为什么是平方？**softmax 的求导带来一个 1/T；在高温近似下，师生概率差又常缩小约 1/T，合起来约 1/T²。补乘 T² 是经典尺度处理，不是所有温度、所有损失下都精确抵消。

**追问：生成文本的采样温度就是这个 T 吗？**用途不同。一个控制采到哪些文本，一个控制比较分布时的平滑；实现可能分别设置，也可能复用参数，必须看文档和代码。数值实验见本目录的蒸馏实验说明。

**依据：**S79；三动作例子为教学简化，实际语言模型通常比较词表中的 token。

<a id="KD04"></a>
## KD04｜正向 KL、反向 KL，为什么蒸馏时老在讨论方向？（P0）

**先看例子：**老师认为两条查询路径都能解决问题，概率是 60% 和 40%。学生却把第二条几乎判成不可能。正向 KL 会对这个“漏学老师认可的路径”给出很大的惩罚。

换一个情况：学生喜欢走一条老师几乎不认可的路径。反向 KL 会特别关注学生自己常去的地方，在那里检查老师是否也认可。

**直答：**本章约定 p 是教师、q 是学生。正向 KL 用教师概率加权，反向 KL 用学生概率加权；它们强调的错误不同。选择方向还要结合学生能采到哪些序列、能得到什么反馈以及学生容量。

### 进一步：公式、边界与追问

$$D_{\mathrm{KL}}(p\|q)=\sum_i p_i\log\frac{p_i}{q_i}$$

$$D_{\mathrm{KL}}(q\|p)=\sum_i q_i\log\frac{q_i}{p_i}$$

“正向偏覆盖、反向偏集中”是理解受限模型行为的直觉，不是每个离散问题都会出现的结论。当 q 可以完整表示 p、概率条件满足时，两个目标的最优解都在 q=p。

**追问：反向 KL 一定更好吗？**不一定。它可能低估多种有效解的多样性；而且整段序列 KL 的优化，比固定一个前缀比较下一 token 分布复杂。MiniLLM 见 KD09，GKD 见 KD10。

**依据：**M02、S81、S82。

<a id="KD05"></a>
## KD05｜序列蒸馏是不是“拿老师答案微调一下”？（P0）

**先看例子：**老师为“怎么查我的订单”写出一段合格回答。学生训练时，看着这段回答的前半句，练习预测老师接下来写的词。

这比只拿原始问题容易组织成数据，也适用于看不到教师内部概率的情况。不过学生在训练中常走在老师铺好的路上，自己部署时写错一个词、选错一步，就可能进入没练过的局面。

**直答：**序列蒸馏的基本做法，就是把教师生成的序列作为监督目标训练学生。它是重要的基础方法；效果取决于任务覆盖、示范质量、训练分布和评测设计。

### 进一步：公式、边界与追问

教师生成的目标序列记为 y*：

$$L_{\mathrm{seq}}=-\sum_t\log q_\theta(y_t^*\mid x,y_{<t}^*)$$

x 是问题，y* 的前缀是老师给出的前文。每一步让学生提高老师下一个 token 的概率。实际训练可以按有效 token 做平均，具体归一化须写清。

**追问：老师每题只生成一条够吗？**可以作为基线。多采样能增加候选，但近重复、错误推理和较长答案也会增加；应按可执行验证与任务覆盖筛选，不能把“生成量”当作“有效数据量”。

**依据：**S80。原论文主要研究机器翻译，迁移到 Agent 轨迹属于进一步的任务设计。

<a id="KD06"></a>
## KD06｜推理蒸馏是在教学生“思考”，还是背长答案？（P1）

**先看例子：**一道题只给“答案是 12”，学生缺少中间联系。如果再给“先查库存是 20，扣掉已预订的 8，所以剩 12”，学生可以练习连接证据、步骤和结论。

但如果中间写了无关的两百字，学生可能只学会啰嗦。写出推理文本也不保证模型内部真的按这段文本完成计算。

**直答：**推理蒸馏利用可取得的解释、解题步骤或过程标签提供更细的监督。训练目标可以是“过程加答案”，也可以将解释和答案设为不同任务；要检验正确性与迁移，不能只看输出更长。

### 进一步：公式、边界与追问

Distilling Step-by-Step 用教师给出的理由补充监督，并将理由生成与标签预测组织成多任务训练。它提醒我们：解释可以提供额外教学信息，但监督格式需要有意设计。（S84）

工程上可比较“只学最终答案”“学经验证的简短步骤”“学长过程”三组，统一训练量和测试时 token 预算，再测新题、变体题以及错误证据下的反应。

**追问：教师只提供最终答案怎么办？**按已有信号做序列蒸馏，或请求可公开输出的解释、调用记录。不能假设能取得教师未提供的内部推理过程，也不能把自行编造的过程标成教师原始思考。

## KD07｜on-policy 蒸馏为什么要让学生自己先写？（P0）

**先看例子：**老师示范时总能正确查到订单，学生上线却把订单号少写了一位。继续给学生看老师的完美示范，未必能教会它如何处理这个报错。

on-policy 的关键是：先让当前学生做一次，记录它真正走到的上下文，再让老师对这个局面给出指导。这样能集中练学生正在犯的错。

**直答：**离线示范训练主要学习固定数据里的情境；on-policy 蒸馏把学生当前生成的前缀或轨迹纳入训练，让教师反馈更贴近学生实际会遇到的状态。

### 进一步：公式、边界与追问

一个教学用的 token 分布匹配目标可写为：

$$L=\mathbb E_{h\sim d_q}\left[D(p(\cdot\mid h),q_\theta(\cdot\mid h))\right]$$

h 是包含历史动作和观察的上下文；d_q 表示学生产生这些上下文的分布；D 是选定的分布差异。学生会变，因此上下文也需刷新。

**实现边界：**把已采样的 h 当固定数据进行 token KL 更新，与对“整段序列分布目标”求完整梯度不是同一件事。不能只看到一个期望符号，就把所有方法说成相同算法。

**追问：为什么不用全 on-policy？**学生早期可能只产生低质量轨迹，教师查询和工具执行也有成本。固定优质示范与学生数据混合，常是可检验的折中方案；混合比例应做消融。依据 S82、S83、S88。

## KD08｜DAgger 和普通“多收集一点数据”差在哪？（P1）

**先看例子：**新司机在练习时开偏了，教练根据车当前的位置指导怎么回到车道。收集的数据不只是“高手正常开车录像”，还包括新司机容易偏到的地方。

Agent 同理：学生在真实工具状态里走错后，请教师给出可执行的下一步，再把这些纠正例子加入训练集。

**直答：**DAgger 的核心循环是让学习者到达状态、请求专家在这些状态上的示范、累积数据并重新训练。它针对模仿学习中“训练看见的状态与自己运行时的状态不同”的问题。

### 进一步：公式、边界与追问

教学循环：初始示范训练 → 学生与环境交互 → 专家标注学生遇到的状态 → 聚合新旧数据 → 更新学生 → 重复。

**追问：这就是 GKD 吗？**有共同的“在学生状态上教学”思想，但监督信号和优化不同。DAgger 通常讨论专家动作标签与数据聚合；GKD 讨论生成模型上的教师分布匹配及不同散度。不要仅因都用了学生采样就混用名称。

**工程追问：走错以后还能求助老师吗？**必须把可恢复的环境状态、工具响应和当前历史提供给老师。若只截取最终错误答案，老师看不到问题发生在哪里。不可恢复的动作应在可重置的任务环境中练。依据 S83、S82。

<a id="KD09"></a>
## KD09｜MiniLLM 为什么用反向 KL？（P1）

**先看例子：**学生容量有限，老师会的表达方式太多。MiniLLM 关注的是：学生已经有可能生成的序列，老师是否也认为合理；避免把精力全花在拟合教师极多的低概率输出上。

**直答：**MiniLLM 以学生到教师的反向 KL 为核心，并为自回归序列设计优化方法。理解它要同时看“KL 方向”和“如何对学生生成的整段序列学习”，不能只把代码里 KL 的两个参数交换。

### 进一步：公式、边界与追问

省略对训练问题 x 的平均，序列层面的目标为：

$$L(x)=\mathbb E_{y\sim q_\theta(\cdot\mid x)}
\left[\log q_\theta(y\mid x)-\log p(y\mid x)\right]$$

y 是学生采样的完整序列；p 是固定教师。学生参数既影响括号里的概率，也影响会采到哪些 y。论文据此采用带稳定化设计的策略梯度优化。（S81）

**追问：只对采到的 log q-log p 直接反向传播就行吗？**不能据此宣称实现了完整序列反向 KL 梯度；采样分布依赖参数这一项需要正确处理。复现应核对作者目标、采样、梯度估计和长度处理。

**边界：**反向 KL 可能减少有效解的覆盖，优势须在选定任务、容量和预算下验证。KD23 的小实验只演示固定上下文下的离散 KL，不冒充 MiniLLM 训练。

<a id="KD10"></a>
## KD10｜GKD 怎样训练？TRL 里的参数怎么读？（P1）

**先看例子：**学生写出半句，老师查看这半句，对“下一个词应该怎么分配概率”打分。学生既能练原有示范，也能练自己刚写出的前缀。

**直答：**GKD 把生成模型的蒸馏放到学生生成的数据上，并允许选择不同的分布差异及数据混合方式。它让“在哪些上下文学习”和“用什么散度比较师生”成为可调整的两个维度。（S82）

### 进一步：公式、边界与追问

下面固定讲 **TRL v0.24.0 GKDTrainer**，避免把其他版本参数套进来：

| 参数 | 白话含义 | 读代码时注意 |
|---|---|---|
| lmbda | 使用学生生成序列的比例 | 0 偏固定数据，1 使用学生序列；中间值混合 |
| beta | 控制采用的散度 | 0 为正向 KL，1 为反向 KL，中间为广义 JSD；不是 DPO 的 β |
| seq_kd | 在非学生生成的分支上，是否改由教师生成序列 | 不等于自动改成 KD05 的纯硬标签交叉熵 |
| temperature | 文档中用于生成的温度 | 不能仅凭同名就当作 KD03 的 T² 软化配方 |

**追问：lmbda=0 就没有蒸馏了吗？**仍可以在固定序列上比较师生分布；“是否由学生生成”和“是否有教师监督”是不同问题。

**复现最小记录：**版本、教师与学生、tokenizer、数据来源比例、散度方向、温度的实际作用位置、loss mask、token 归一化与教师查询量。框架示例不构成已完成实验。依据 S88。

<a id="KD11"></a>
## KD11｜Agent 蒸馏要保存哪些数据？工具返回也要让模型背吗？（P0）

**先看例子：**老师先发出“查订单 A17”的调用，系统返回“已发货”，老师再说“订单 A17 已发货”。这里至少有三类东西：模型的动作、环境给的事实、模型的答复。

学生需要学习什么时候调用工具、怎样填参数、怎样读结果。订单状态是工具当时提供的事实，不能训练成学生以后直接凭空生成一个工具结果。

**直答：**轨迹应保存任务输入、工具说明、每轮模型输出、工具调用参数、真实观察和结束状态。做普通助手 SFT 时，通常只对模型应生成的部分计算损失；工具观察作为后续决策的上下文保留。

### 进一步：公式、边界与追问

~~~text
user: 查询订单 A17 的状态
assistant/tool_call: get_order({"order_id":"A17"})    ← 学生要学
tool: {"order_id":"A17","status":"shipped"}           ← 真实观察
assistant: 订单 A17 已发货。                         ← 学生要学
~~~

~~~text
训练记录建议字段：
task_id / task_family / split / teacher_version
messages / tool_schema_version / environment_seed
tool_results / final_state / verification / token_loss_mask
~~~

**追问：mask 掉工具返回，是把它从输入删掉吗？**不是。它仍作为输入影响后续答案，只是它自己的位置不直接作为预测目标。还要核对 token 的一位移位：前一个位置的 logits 预测下一个 token。文本角色标签不能代替实际 mask 检查。

**依据：**S85、S87；字段与示例是可实施的教学方案，非某论文要求的统一格式。

## KD12｜AgentTuning 和 AgentInstruct，名字相近是同一个东西吗？（P1）

**先看例子：**一类工作让高手演示“怎样调用工具把事情办成”；另一类工作让多个 Agent 充当出题老师，大规模生成教学题目。两者都能产出训练数据，但作用点不一样。

**直答：**AgentTuning 用筛选后的 Agent 交互示范与通用数据联合训练。微软的 AgentInstruct 研究用 agentic flows 组织合成教学数据。AgentTuning 自己的数据集也叫 AgentInstruct，阅读时要用作者、年份和链接区分。

### 进一步：公式、边界与追问

| 名称 | 这里指的来源 | 主要学习点 |
|---|---|---|
| AgentTuning（2023）及其 AgentInstruct 数据集 | S85 | 交互示范筛选；Agent 与通用任务数据混合 |
| AgentInstruct: Toward Generative Teaching with Agentic Flows（2024） | S86 | 从种子资料组织多种教学任务与回答 |

**追问：用 Agent 生成数据，就叫蒸馏 Agent 能力吗？**还要看训练目标。如果合成的只是摘要题，学生主要学摘要。要迁移工具使用，应提供相应动作、真实观察和任务验证，不能仅凭数据生成流程用了 Agent 就声称学生具备完整 Agent 能力。

## KD13｜检索、代码工具型 Agent 蒸馏，有什么具体研究可看？（P1）

**先看例子：**用户问一个需要计算的问题。老师先找数据、再运行计算代码，最后引用结果。若只留下最后一个数字，学生看不到何时检索、何时执行代码。

**直答：**可看 Distilling LLM Agent into Small Models with Retrieval and Code Tools。它研究把带检索与代码工具的解题行为传给小模型，重点是完整任务轨迹，而不只保存最后答案。（S87）

### 进一步：公式、边界与追问

读这类论文时，分开记录两种改动：训练数据怎样构造；测试时是否额外采样、投票或选择动作。S87 同时讨论教师引导轨迹构造与测试时的动作一致性选择，比较收益时应把额外推理成本单列。

**追问：为什么要分开？**假设学生从一次尝试变成五次尝试再挑选，即使成功率提高，也不能全归因于蒸馏。公平比较可以同时报告“每题一次”的训练效果和“相同总预算”的系统效果。

**项目迁移：**保留工具输入输出、执行报错和终态检查；分别测检索失败、代码运行失败、证据读错。论文上的提升不能替代你自己的业务测试。

## KD14｜SOD 为什么给不同工具步骤不同的蒸馏权重？（P2）

**先看例子：**学生第一步就查错订单，后面再认真解释，也是在错误对象上解释。老师对这种偏离正常路径的上下文给出的分布，不一定像正常状态下那样有帮助。

**直答：**SOD 研究逐步调整 on-policy 蒸馏强度：师生分歧加大时降低后续步骤的影响，学生恢复后允许权重回升，并结合结果奖励训练。它不是“一旦出错就把后面全删掉”。

### 进一步：公式、边界与追问

S89 为 2026 年 5 月预印本，本章依据 v1。其步骤权重依据相邻步骤的分歧变化，并有上限；分歧是方法中的代理信号，不是人工判定正确性的替代品。

**追问：分歧越大，越应该用力纠正吧？**这取决于反馈是否可靠。若教师确实能指导当前错误状态，纠正有价值；若状态已严重偏离教师熟悉的情境，强行模仿可能放大噪声。这正是需要验证的假设。

**实验追问：怎么判断加权有用？**在相同 rollout 与训练预算下，对照统一权重、出错后全屏蔽和自适应权重，并按出错位置、恢复成功率分组。论文结果限定于其环境和模型，本章未复现。

<a id="KD15"></a>
## KD15｜SEED 怎样把“事后复盘”变成训练信号？（P2）

**先看例子：**学生做完一次任务，复盘出“遇到空检索结果先改写查询，不要重复同一句话”。只把这句话存进笔记，不保证下次模型会改变动作；蒸馏希望把这种指导的影响学进参数。

**直答：**SEED 先训练轨迹分析能力，再用当前策略采集任务过程并总结技能；比较普通上下文与加入技能的上下文对已采样动作的概率，形成细粒度指导，与任务结果奖励联合训练。

### 进一步：公式、边界与追问

S90 为 2026 年 7 月预印本，本章依据 v1。技能来自已经完成的轨迹，是训练阶段的额外信息；论文设计希望部署时无需附加这些技能提示。

**追问：这和一直把复盘笔记放进提示词有什么区别？**提示词方案在每次推理时提供笔记；这里的目标是通过训练，使普通输入下的策略也吸收技能带来的行为改变。是否真正吸收，要在不提供技能提示的测试中检查。

**边界：**复盘可能归因错误；还要防止把测试题的答案或未来观察带进评测输入。可对照 SFT、只做 RL、固定技能、自更新技能，并测新任务恢复能力，而不只看训练任务分数。

<a id="KD16"></a>
## KD16｜不同词表、中间层、top-k 概率，怎样避免“对齐错了”？（P1）

**先看例子：**老师把“上海市”切成一个 token，学生切成“上海”和“市”。老师的第 100 个词表项与学生的第 100 个词表项未必是同一个词，不能直接比较两个数组。

中间层也一样：老师第 12 层的某个维度，不天然对应学生第 6 层的同编号维度。

**直答：**蒸馏前要对齐监督对象。文本级方法可以用各自 tokenizer；token 分布匹配需要兼容的词表与位置语义；特征蒸馏需要有依据的层、位置和维度映射。

### 进一步：公式、边界与追问

一种特征匹配的教学示意是：

$$L_{\mathrm{feat}}=\|P(h_{\mathrm{student}})-h_{\mathrm{teacher}}\|_2^2$$

P 是把学生表示映射到教师表示空间的投影。这个公式只说明匹配形式，不会自动解决不同分词、不同层语义或不同位置的问题。

**追问：教师只给 top-k，重新归一化后算 KL 行不行？**可以构造一个明确定义的近似目标，但它只比较保留集合内的条件分布。缺失尾部质量时，不能把数值标成完整词表 KL，也不能假设尾部概率全为零。需要说明截断和对齐方法，并做对照。

**依据：**S79、S88；投影式与词表例子是教学说明，不对应某一完整训练配方。

<a id="KD17"></a>
## KD17｜教师生成了一万条轨迹，怎么判断哪些值得学？（P0）

**先看例子：**老师的回复很流畅，却查了错订单；另一条虽然先报错，但随后补齐参数、重新查询，最终办成了事。只筛“语言漂亮”和“没有报错”的数据，会把关键差别弄反。

**直答：**先验证任务是否完成、工具结果是否真实、动作是否符合要求，再看覆盖和成本。保留正确示范，也有针对性地保留可验证的恢复过程；失败轨迹要标清用途，不能直接当成正例模仿。

### 进一步：公式、边界与追问

建议分层记录：

1. **格式层：**工具名存在，参数符合结构要求，消息顺序完整。
2. **执行层：**实际调用成功；返回值与轨迹中记录一致。
3. **业务层：**最终状态满足任务条件，回答忠于观察。
4. **覆盖层：**任务类型、长度、异常、工具组合是否多样，近重复是否过多。

**追问：失败数据怎么利用？**有可靠修正时做纠正监督；有成对优劣且偏好可信时做偏好训练；只知道失败而不知道正确动作时，可以用于评测或结果奖励，不能凭空生成“正确标签”。

**工程边界：**失败与成功应按任务族划分训练/测试，避免同一订单模板的改写跨集合泄漏。轨迹筛选思路见 S85，评测基础见 E01、E05、A07。

## KD18｜更强老师、更多上下文，为什么学生反而学不好？（P1）

**先看例子：**老师看得到内部订单数据库，学生上线却没有查询工具。老师每次都直接给出正确状态，学生只能学会模仿“很确定地回答”，学不到事实来源。

另一个问题是老师会很复杂的步骤，学生容量或训练预算不足，未必能照搬。

**直答：**先确认教师示范在学生部署条件下可实现，再匹配学生能力和教学难度。教师更强可以改善监督，但额外信息、难度差距和错误示范都可能让迁移失败。

### 进一步：公式、边界与追问

教师训练时可以使用额外信息，这属于“更好的教学条件”；关键在于它给出的目标是否能帮助学生仅凭部署输入学到可迁移规律。不能把只存在于教师上下文中的新事实，期望学生在未来凭空知道。

**追问：怎样做课程安排？**先练单工具、短链路与可验证答案，再逐步加入多工具和异常恢复；同时混入已掌握任务以监测遗忘。这是实验设计建议，应与相同预算的随机混合训练比较，不能未经测试就说必然更好。

**参考联系：**KD07 的学生状态反馈解决部分分布错位；KD15 讨论训练时额外反馈；S82、S89 提供相关研究角度。

## KD19｜多个教师一起教，会不会一定比一个教师好？（P1）

**先看例子：**一位老师善于查资料，另一位善于写代码。按任务分工可能互补。但一个要求“先确认订单号”，另一个直接猜，混在一起也可能让学生学到互相冲突的习惯。

**直答：**多教师有机会扩展覆盖，但需要统一工具规范、事实验证和行为标准。可以按任务选择教师，也可以比较多个候选后保留经过验证的示范；多数票不能替代事实验证。

### 进一步：公式、边界与追问

若教师词表与输入对齐，可以讨论加权混合分布；若只有文本，通常先生成候选再按验证结果选择，而不是把不同答案按字符串拼起来。权重应该有数据依据。

**追问：一个很强的裁判模型够吗？**裁判也可能偏爱长答案或熟悉的写法。能运行工具、检查业务终态、执行代码测试的部分，优先用这些信号；主观部分再结合裁判和抽样人工复核，见 E05、E09。

**最小消融：**最强单教师、按任务选择、多教师经同一验证器筛选。统一学生训练 token 数和教师总调用预算，判断改善来自教师互补还是多花了钱。本题为工程设计建议；经典多模型知识迁移背景见 S79。

## KD20｜蒸馏省不省钱，应该怎么算？（P0）

**先看例子：**教学准备花了 3000 元。每次直接用老师花 0.10 元；学生自身花 0.01 元，但有 10% 的任务还要转给老师。先忽略其他开销，平均每单就是 0.02 元，省 0.08 元，大约 37500 单才能摊平准备费用。

这些都是假设数字，只演示算法，不代表任何平台价格。

**直答：**成本要包含数据生成、清洗、训练、部署，以及上线后的重试和教师兜底。在任务质量达到要求的前提下，看累计节省是否超过前期投入，并同时检查响应时间。

### 进一步：公式、边界与追问

$$c_{\mathrm{hybrid}}=c_{\mathrm{student}}+\rho c_{\mathrm{teacher}}$$

$$N_{\mathrm{break}}=\frac{C_{\mathrm{setup}}}
{c_{\mathrm{teacher}}-c_{\mathrm{hybrid}}}$$

ρ 是转交教师的比例；简式假设每次转交增加一次完整教师成本。第二式只有在分母为正时才有摊平点；有额外重试、工具费、固定服务费时需逐项加入。

**追问：学生单次便宜就能上线吗？**还须满足正确率、稳定性和延迟要求。学生多试五次的成本、错误导致的人工返工，都可能抵消单次价格优势；按“办成一件任务”的成本比较更有意义。评测见 KD21。

## KD21｜怎么证明蒸馏出的 Agent 真能工作？（P0）

**先看例子：**学生总能输出结构正确的工具调用，但订单号填错一半。格式分很高，用户的事仍然没办好。再比如正常工具调用很熟练，一遇到超时就循环重试。

**直答：**同时检查最终任务结果、每步工具调用和异常恢复。测试任务应覆盖未见过的任务实例与变化条件，并让师生使用可比较的工具、提示和预算。

### 进一步：公式、边界与追问

| 检查项 | 具体看什么 |
|---|---|
| 最终成功 | 环境终态与业务约束是否满足，而非只看最终文本 |
| 工具执行 | 名称、参数、先后依赖、结果读取是否正确 |
| 恢复 | 缺参数、空检索、超时、工具报错后能否继续或合理结束 |
| 泛化 | 新任务族、新实体、工具说明变化、较长任务 |
| 可靠性 | 重复运行成功率、严重错误类型、错误区间 |
| 总预算 | 模型 token、工具次数、教师兜底、延迟和每成功任务成本 |

**追问：基线怎么设？**至少有原始学生、同样任务数据的基础 SFT、教师；研究某个蒸馏改动时，再加去掉该改动的对照。一次尝试与多次择优分别报告，别混用 pass@k 和重复可靠性，见 E07、E08。

**依据：**S31、S87；表格是面向订单 Agent 的评测方案，不是某基准的官方评分表。

## KD22｜面试让你设计“把强模型蒸馏成订单 Agent”，怎么回答？（P0）

**先看例子：**业务只需要处理订单查询，不要求学生拥有老师的全部知识。最有说服力的方案，是先把这类工作定义清楚，再逐步证明学生可以承担哪些部分。

**直答：**我会先定义任务范围与成功条件，用教师在可重置工具环境中采集并验证轨迹，训练轨迹 SFT 基线；根据学生的失败类型补充纠正数据，在接口支持时比较 on-policy 蒸馏；最后用独立任务、异常测试和真实成本决定是否采用。

### 进一步：公式、边界与追问

**可落地的六步：**

1. 写任务合同：输入有哪些、工具有哪些、完成条件是什么、哪些情况需要补问。
2. 按任务族留出测试集；工具和环境版本固定，预先准备终态验证器。
3. 教师采集：保存完整调用链与真实观察，筛选正确及可解释的恢复轨迹。
4. 学生训练：先用轨迹 SFT，只监督助手生成位置，记录数据量、长度与资源消耗。
5. 定向迭代：从学生新跑出的错误状态求教师纠正；若只有文本，做纠正示范；若有匹配概率，再比较 GKD 等方法。
6. 对照评测：普通学生、轨迹 SFT、改进蒸馏、教师；同预算测成功率、恢复、泛化、延迟和兜底比例。

**追问：失败最多出在哪里？**分别统计“理解任务、选工具、填参数、读结果、结束判断”。如果工具 schema 就错了，先修数据接口；如果学生只在自己偏离示范后失效，再针对分布差异做训练。

**追问：你的贡献是什么？**拿出可重放数据、失败分类、关键消融和成本曲线。不要把“调用老师生成了一批回答”直接等同于完成了 Agent 蒸馏项目。本题为工程方案，不声称已训练或上线。

## KD24｜蒸馏算法这么多，面试时怎样选，不背名字？（P0）

**先看例子：**你手里只有老师生成的文本，却直接说“用全词表反向 KL”；或者根本没有真实工具环境，就说“在线蒸馏恢复能力”。这两种方案都缺少实施条件。

**直答：**按四个问题选：教师能提供什么信号；学生在哪些状态犯错；任务结果能否验证；总预算是否允许迭代。先把最简单的可行基线做实，再引入对应瓶颈的方法。

### 进一步：公式、边界与追问

| 条件或问题 | 先考虑 | 再检查 |
|---|---|---|
| 只有教师文本 | 序列蒸馏 / 轨迹 SFT | 质量、覆盖、学生输入是否足够 |
| 有兼容的教师概率 | 软标签 KD | 温度、方向、词表、mask |
| 学生偏离示范后失效 | 学生状态纠正 / GKD 思路 | 反馈可靠性与查询成本 |
| 研究序列反向 KL | MiniLLM | 完整目标、梯度估计与稳定化 |
| 工具链后续反馈失真 | 逐步可靠性分析，研究 SOD | 分歧是否真能反映反馈质量 |
| 完成任务后有可复用经验 | 反馈或技能自蒸馏，研究 SEED | 无额外技能提示时是否仍有效 |

**一分钟口述示例：**“蒸馏是用教师信号训练学生。我会先确认能拿到文本还是概率。Agent 任务要保留动作和真实工具观察，只监督模型该生成的部分。先跑轨迹 SFT，再根据学生自己运行时的错误，决定是否补纠正数据或做 on-policy 分布匹配。最终看独立任务成功率、异常恢复和每成功任务成本，并用消融证明收益来自哪里。”

**追问：DPO 算蒸馏吗？**如果教师为学生候选提供偏好标签，DPO 可以成为教师反馈迁移的一种训练环节；但 DPO 本身不等于概率分布蒸馏。先说明数据来源与优化目标，见 P04、P06、KD04。

**依据：**S79—S90；表格为教学归纳，具体方法条件以对应题目和原来源为准。

## KD25｜OPD 到底是什么算法？和 GKD、普通蒸馏是什么关系？（P0）

**先看例子：**学生自己查订单，走到“工具说找不到订单”的一步。老师查看学生这条真实记录，判断下一步应该询问、重试还是结束。学生练习的是自己容易遇到的局面。

这就是 on-policy 的关键：训练情境由当前学生产生。老师提供的是这些情境下的教学信号，不一定需要重新写一整份标准答案。

**直答：**OPD 是 On-Policy Distillation，即在学生自己采样的前缀或轨迹上进行蒸馏。它是一类训练范式，有不同的损失和实现；GKD、MiniLLM 与后来的 OPD 配方之间有继承和差异，不能把 OPD 当成唯一一条固定公式。

### 进一步：公式、边界与追问

先把四个维度分开：

| 维度 | 要回答的问题 |
|---|---|
| 谁产生训练轨迹 | 当前学生、旧学生、教师，还是固定数据 |
| 谁提供指导 | 外部教师、带额外信息的自身、分领域专家 |
| 指导有多细 | 最终得分、已采到的 token 概率、完整下一词分布 |
| 怎么更新 | 直接比较分布，还是把概率差当策略梯度信号 |

Thinking Machines 2025 年的 OPD 配方使用逐 token 反向 KL，并采用只优化当前 token 的局部反馈，便于利用现有策略优化训练流程。它也明确承接 GKD、MiniLLM 等工作。（S91、S81、S82）

**追问：OPD 就是反向 KL 吗？**不是。on-policy 描述数据从哪里来，KL 方向描述怎么比较概率。OPSD 的特定版本选择正向 KL，仍然是 on-policy 学习。看 KD27。

**追问：on-policy 是否要求学生每更新一次就完全重采所有数据？**理想定义强调当前策略，工程中可能有小批量复用和采样延迟；需要记录采样策略版本及偏移处理，不能把很旧的数据默认为当前分布。

## KD26｜OPD 怎样把教师 logprob 变成每个 token 的指导？（P0）

**先看例子：**在同一个上下文里，学生给自己选中的动作 20% 概率，老师给 50%。老师比学生更认可这一步，就可以鼓励学生提高它的概率。反过来，学生给 50%、老师只给 20%，就应压低。

这里比较的是“老师比学生更认可多少”，不是老师宣布动作绝对正确。

**直答：**一种常见 OPD 实现，把教师与学生对已采样 token 的对数概率差当作逐 token 优势。优势在更新时停止梯度，学生据此提高或降低相应 token 的概率。

### 进一步：公式、边界与追问

令 h 为固定上下文，a 为学生采到的 token，p 为教师、q 为学生：

$$A(a,h)=\mathrm{sg}\left[\log p(a\mid h)-\log q(a\mid h)\right]$$

$$L_{\mathrm{local}}=-A(a,h)\log q_\theta(a\mid h)$$

sg 表示“本次更新中把这项当作固定数”。例子中 log(0.5/0.2)≈0.916，为正；交换两个概率则约为 −0.916。

**关键边界：**这是一个局部、采样式的更新示意。固定上下文下，对当前学生的 token 采样取期望，可以得到反向 KL 的梯度；它不自动包含“改变前面动作后会访问哪些未来状态”的完整梯度。S91 的当前 token 配方与 KD09 的完整序列讨论要分开。

**追问：直接对 log q-log p 求导行吗？**对离散采样结果直接求导会漏掉采样概率随参数变化的部分。使用停止梯度的优势构造策略梯度，或对完整词表显式算 KL，是不同的正确实现路径。配套数值实验枚举小词表，检查这两个固定上下文梯度是否一致，并用有限差分复核。

**追问：教师给同一 token 的概率高，就代表工具调用正确吗？**不能。它只代表教师认可；最终仍应检查工具执行和业务终态。依据 S91、S92。

## KD27｜OPSD 怎么让同一个模型既当老师又当学生？（P0）

**先看例子：**同一道数学题，你闭卷时可能不会；拿到参考解后，往往能发现“原来第二步就理解错了”。同一个人，看到的信息不同，能提供的指导也不同。

Self-Distilled Reasoner 用这个差别建立教师：学生只看题目，教师分支额外看到参考解，然后指导学生已经生成的前缀。

**直答：**OPSD 是 On-Policy Self-Distillation。同一个模型借助不同上下文形成师生：学生负责生成，带参考解的教师负责提供更充分的分布监督；更新只通过学生分支传播。

### 进一步：公式、边界与追问

下面用 x 表示题目，y* 表示训练时可用的参考解，h 表示学生前缀：

$$q_\theta(\cdot\mid x,h)$$

$$p_{\mathrm{teacher}}=\mathrm{sg}\left[q_\theta(\cdot\mid x,y^*,h)\right]$$

在 S18 的 v3 实验配方中，作者采用正向 KL，并对词表项的散度贡献作截断，以减弱少数风格 token 主导训练的问题。它不是把 GRPO 的概率比剪切原封不动搬过来。

**追问：老师停止梯度，是不是永远不更新？**不是。停止梯度只描述这次反向传播；共享模型更新后，下次构造的教师分布也会改变。是否另设固定快照或移动平均教师，需按具体方法区分。

**追问：为什么有些介绍说 OPSD 用 JSD？**框架允许不同散度，版本和实验配置也可能不同。该论文 v3 明确比较了正向 KL、反向 KL 与 JSD，并选用正向 KL 做后续实验；应记录版本，不能只背早期简介。

**依据：**S18，2026 年论文 v3 方法与消融；报告第 4 页的 Self-Distilled Reasoner 对应本题。

## KD28｜OPSD 已经给老师参考答案了，不就是把答案泄漏给学生吗？（P0）

**先看例子：**老师批作业时拿着标准答案，这当然算一种监督。问题在于考试时学生能不能只看题目作答。如果测试时也把该题答案塞进学生输入，再报告闭卷能力，就不成立。

**直答：**OPSD 使用训练参考解提供特权监督，不能称为“完全没有外部监督”。合理评测要求参考解只用于训练教师分支，测试学生时移除它，并严格隔离训练与测试题。

### 进一步：公式、边界与追问

训练数据可以有答案，关键是界定信息的使用位置：

1. 学生采样输入只包含部署时可获得的信息。
2. 教师分支接收训练参考解和同一条学生前缀。
3. 对齐师生的目标 token 位置，不能按两段输入的绝对位置直接比较。
4. 教师分支停止梯度；普通学生输入用于独立评测。

**追问：有答案为什么不直接 SFT？**可以，且应作为基线。差别是 SFT 主要模仿参考文本；OPSD 用参考解帮助教师评价学生自己的路径。是否值得增加计算，要控制数据、训练量与评测预算再比较。

**追问：多了参考解，还能直接和没有参考解的 RL 比吗？**可报告整个方案效果，但必须交代监督信息不同。若要说明算法本身的优势，应给各基线可比的监督或单列信息增益消融。本题为基于 S18 的实验审查方案。

## KD29｜MOPD 怎样把多个专业老师的能力合到一个模型里？（P0）

**先看例子：**数学老师擅长解题，代码老师擅长调试，工具老师擅长处理多步任务。让每位老师专门练强项，再让一个学生针对不同问题向对应老师学习，可能比一开始就让一个模型同时追逐冲突目标更容易组织。

**直答：**MOPD 是 Multi-Teacher On-Policy Distillation。其典型流程是分别训练领域专家，再按问题路由到对应教师，在学生自己的生成轨迹上做蒸馏，把多种能力整合进同一个学生。

### 进一步：公式、边界与追问

S92 的流程是：共同 SFT 起点 → 各领域分别 RL → 教师池 → 一个学生进行多教师 OPD。MiMo-V2-Flash 技术报告也采用该路线。（S93）

用 d(x) 表示给问题 x 分配的教师，单步教学目标可表示为：

$$L(h)=D_{\mathrm{KL}}\left(q_\theta(\cdot\mid h)\|p_{d(x)}(\cdot\mid h)\right)$$

这只是本地目标的简写；完整实现还包括采样、有效 token 平均及稳定化。S92 提供采样式策略梯度与 top-k 分布蒸馏两种实现。

**追问：是不是把几个教师权重平均一下？**MOPD 通过训练学生整合行为，教师参数无需直接求平均。也不是部署时每题都运行一组老师投票；能否由学生单独服务，要看整合后的测试结果。

**追问：学生和老师一定不同尺寸吗？**不一定。能力整合可以发生在相同结构、相同起点但专长不同的模型之间；蒸馏的目的不只有压缩参数量。

## KD30｜MOPD 的难点是“多放几个老师”吗？（P1）

**先看例子：**一个问题同时需要查资料和写代码，整题交给哪位老师？如果数学老师喜欢详细推导，客服老师强调简洁，学生又该学哪种回答标准？

**直答：**关键在教师专长、任务路由、各领域训练机会以及冲突处理。教师数量增加，并不自动意味着学生更强。

### 进一步：公式、边界与追问

设计时先固定教师选择规则与数据配比，再逐项比较：

| 对照 | 想确认什么 |
|---|---|
| 单一最强教师 vs 多教师 | 是否来自专长互补 |
| 同预算混合任务 RL vs 分领域 RL 后 MOPD | 是否缓解领域间性能此消彼长 |
| 正确路由 vs 随机路由 | 教师匹配是不是关键 |
| 各领域单项分数与通用能力 | 总分是否掩盖某项能力退化 |

**追问：教师 top-k 概率重新归一化，就实现了论文吗？**S92 的 top-k 目标含概率质量修正项，不能替换成“保留 top-k 后随手归一化”的 KL 再宣称等价。KD16 解释了缺失尾部信息的问题；实施时核对保留集合、原概率质量和梯度。

**追问：同起点的专家有什么作用？**S92 用同一 SFT 起点训练专家和初始化学生，以减小初始分布差异。这是论文配方的条件，不是任意异构教师都能同样稳定整合的保证。

## KD31｜SDPO 和 OPSD，缩写差不多，实际区别在哪？（P1）

**先看例子：**程序跑错后，系统返回“访问了不存在的键”。只给模型一个 0 分，会丢掉这句话里有用的信息。把报错交给模型复盘，它可能知道该检查哪一步。

**直答：**SDPO 是 Self-Distillation Policy Optimization。它利用环境给出的详细反馈构造自教师，再把反馈影响转化为学生原始尝试上的细粒度学习信号。OPSD 的代表论文则以参考解构造特权上下文，二者关注的监督来源不同。

### 进一步：公式、边界与追问

S94 的核心过程：学生尝试 → 环境反馈 → 带反馈的自教师重新评价原尝试 → 蒸馏回普通输入下的学生。实际稳定化还包括对教师变化的约束，如移动平均或与初始教师的约束组合。

**追问：这就是让模型看报错后再回答一次吗？**再次回答可以作为推理策略；SDPO 还用反馈构造参数更新，让未来普通输入下的行为改变。是否更新了参数、更新目标是什么，需要讲清。

**追问：只有 0/1 分，没有文字反馈怎么办？**论文也讨论用同题成功轨迹给失败尝试提供信息。但当整组都失败时，这条信息来源可能不存在，不能假设每个训练题总有正确示范。

**面试记忆：**OPSD 看“特权参考解怎样形成自教师”；SDPO 看“任务反馈怎样变成可学习的细粒度指导”。方法家族可以重叠，简称不能代替完整流程。依据 S18、S94。

## KD32｜熵感知 OPD（EOPD）为什么在高熵位置增加正向 KL？（P1）

**先看例子：**下一步有时只有一个合理选择，例如补上 JSON 的右括号；有时可以先查库存，也可以先查订单。对后一类分岔处，强迫学生只学一种路径，可能损失有用的多样性。

**直答：**EOPD 保留基于反向 KL 的 OPD 目标，并在教师高熵位置额外加入正向 KL。老师拿不准时，学生因此获得更多关于“哪些选择都合理”的分布指导。

### 进一步：公式、边界与追问

熵衡量分布有多分散，见 M09。这里“高熵 token”实际指一个位置上的教师条件分布熵高，不是某个词天生具有高熵。

S19 的 v3 使用“原 OPD 损失 + 高熵位置的加权正向 KL”。高熵位置仍保留原目标；阈值决定在哪里增加监督，系数决定增加多强，不能理解成两种 KL 互相替换。实现还用教师 top-k 候选近似正向项来控制开销。报告第 4 页也提到了该方法。

**追问：学生熵越高越好吗？**不是。随机乱写也能有很高的熵；要看多样性是否对应可行解，并同时测单次成功率、多次采样覆盖和成本。

**追问：为什么 OPSD 有时更适合正向 KL，这里又保留反向 KL？**教师信息、学生容量、任务和实现预算不同。不能把某一组实验的最佳方向推广成所有蒸馏的固定答案。依据 S18、S19。

## KD33｜2026 年的 U-OPSD 没有标准答案，靠什么教自己？（P2）

**先看例子：**学生独立算八次，有六次得到同一个答案，可以暂时把它作为较有把握的候选，再回看另外两次为什么走偏。但六次也可能重复同一个错误。

**直答：**U-OPSD 用模型多次生成的一致性构造伪解，再以该伪解形成教师上下文，对不一致的学生尝试进行自蒸馏。它减少了对外部答案的依赖，代价是伪监督可能错误。

### 进一步：公式、边界与追问

本题依据 S95 的 2026-08-09 v2：先做多次采样与一致性筛选，再利用伪解条件下的模型分布指导不一致的完成序列。这是新研究方案，本知识库未复现。

**追问：多数答案一致就是真值吗？**不是。共享模型、提示和训练偏差会造成相关错误。独立测试仍需可靠真值或环境验证；不能让“生成伪标签的同一套投票”同时充当最终能力证明。

**追问：数学上有效，就能直接用于 Agent 吗？**Agent 的动作序列有多种等价解，文本相同不一定代表终态正确。需设计状态与结果层面的等价判断，并检查工具执行，不能直接拿最后一句话投票。

<a id="KD34"></a>
## KD34｜OPD、OPSD、MOPD、SDPO，怎样放到同一张图里理解？（P0）

**先看例子：**同一个学生，可以向外部高手请教，也可以拿到答案后复盘，还可以分别向多位专家学不同任务。相同之处是教学针对学生自己走过的过程，不同之处是老师的优势从哪里来。

**直答：**先记 OPD 的共同流程“学生采样 → 教师评价 → 更新学生”，再按教师来源区分外部教师、自身特权上下文、多领域专家和环境反馈。最后单独说明损失方向、粒度和采样新鲜度。

### 进一步：公式、边界与追问

| 方法 | 教师优势从哪来 | 本资料入口 |
|---|---|---|
| OPD 常见外部教师配方 | 教师本身更擅长任务 | KD25、KD26 |
| OPSD | 同一模型额外看到训练参考解 | KD27、KD28 |
| MOPD | 不同领域分别强化后的专家 | KD29、KD30 |
| SDPO | 执行反馈、评价文本或可用的成功尝试 | KD31 |
| EOPD | 关注教师不确定性，按位置调整损失 | KD32 |
| U-OPSD | 从自身多次生成中筛选伪解 | KD33 |

这些方法不是互斥的菜单。例如，多教师也可以按置信度调整监督强度，但这样的组合需要重新验证，不能因为两篇论文分别有效就声称组合必然有效。

**追问：哪个最先进？**要把“更新发表”“采用新机制”“特定任务效果更好”分开。本轮已检索到 2026 年 8 月的研究；选型仍要比较信息条件、工具环境、训练与推理总成本。新后训练算法对照见 HP01—HP08，预训练到后训练的串联见 PT20。

**依据：**S18、S19、S91—S95。表格是对这些来源的教学归纳。
