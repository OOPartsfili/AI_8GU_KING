# 13 分布式训练、量化与系统排障

本章解决“一张卡放不下或算不快”的问题。先读 I04 的显存组成，再看分数据、分计算、搬存储和降低精度各在解决什么负担。

<a id="X01"></a>
## X01｜DP、TP、PP、EP 分别拆什么？（P0）


### 多张卡，可以分试卷、分一道题、分工序、分专家

DP 数据并行：每张卡有模型副本，分不同数据；TP 张量并行：把一部分大矩阵计算拆开；PP 流水并行：不同设备负责不同层；EP 专家并行：把 MoE 专家放在不同设备上。

拆分减少某些单卡负担，却会增加同步和通信。

**直答：** 先说明拆的是数据、张量计算、网络层还是专家，再分析存储、通信和设备空闲的代价。

### 进一步：公式、边界与追问

**本章进阶约定与范围：**

定位：补齐工程问答。所有接口和支持精度随硬件与版本变化，面试先讲机制，再根据实际栈举例。

**技术表述：** DP 拆数据，TP 拆层内张量计算，PP 拆模型层流水，EP 拆 MoE 专家。

**展开：** DP 需要汇总梯度；TP 需频繁层内通信；PP 有流水气泡；EP 有 token 路由和专家负载。通常组合使用，收益取决于互联与模型结构。

**追问：为什么多卡不一定线性加速？** 通信、同步、负载不均、batch 太小与额外重计算限制扩展。

**易错：** 不能只用总显存相加判断模型能否高效训练。

<a id="X02"></a>
## X02｜ZeRO 1/2/3 各自分片什么？（P0）


### 每人都复印全套资料，还是分着保管？

数据并行里每卡若都存完整优化器状态、梯度和参数，存在大量副本。ZeRO 逐步把这些状态分片保管。

第 1 阶段分优化器状态，第 2 阶段进一步分梯度，第 3 阶段再分参数。需要使用时通过相应通信协调，不能只看节省显存的一面。

**直答：** ZeRO 1/2/3 依次分片优化器状态、梯度和参数，用通信与管理成本换取更少的单卡冗余存储。

### 进一步：公式、边界与追问

**技术表述：** Stage 1 分片优化器状态；Stage 2 再分片梯度；Stage 3 进一步分片参数。

**展开：** 分片降低每卡冗余，但需在计算时通信或聚合所需数据。FSDP 与全分片理念相关，但具体通信、API 和功能不能完全等同。

**追问：ZeRO-3 必然比 ZeRO-2 快？** 不一定，更省显存可能伴随更多通信；选择取决于内存约束、互联和算力。

**易错：** 不要把 stage 数字当流水并行的层数。依据：S35。

<a id="X03"></a>
## X03｜Activation checkpointing 与 offload 区别？（P0）


### 草稿放不下：用时重算，或暂时搬出去

Activation checkpointing 少存一部分中间结果，到反向传播需要时重新算，主要以计算换显存；offload 把部分数据转存到 CPU 内存等位置，主要增加数据搬运。

二者解决空间不足的方式不同，也可以配合。

**直答：** 检查点重计算减少保存的激活，offload 改变数据存放位置；选择时比较额外计算和传输的实际耗时。

### 进一步：公式、边界与追问

**技术表述：** Checkpointing 少存激活、反向时重算；offload 把部分状态移到 CPU 或其他存储，需付出传输代价。

**展开：** 前者交换计算和显存，后者交换传输/存储和显存。可组合，但慢互联或频繁搬运可能显著降低吞吐。

**追问：checkpointing 会减少参数状态吗？** 主要减少保存的中间激活，不直接改变优化器状态大小。

**易错：** 不要把训练恢复用的 checkpoint 文件与 activation checkpointing 混淆。

<a id="X04"></a>
## X04｜BF16、FP16、FP32 为什么需要区分？（P0）


### 数字能写多大，和能写多细，都重要

FP32、FP16、BF16 是不同的浮点表示格式。可用位数分给指数和有效数字的方式不同，所以可表示范围和精细程度也不同。

FP16 某些大数更容易溢出；BF16 的范围接近 FP32，但不能因此认为它同样精细。混合精度会让不同操作采用合适精度。

**直答：** 区分数值范围与精度，结合硬件和训练稳定性选择格式；低位表示节省资源，但需要检查溢出、舍入和关键计算。

### 进一步：公式、边界与追问

**技术表述：** 指数位决定可表达范围，尾数位影响精度；BF16 范围接近 FP32、尾数更少，FP16 范围较窄。

**展开：** 混合精度常让大矩阵乘用低精度，对敏感归一化、累积或优化器状态保留更高精度。FP16 更常需要 loss scaling，BF16 也不保证所有计算稳定。

**追问：BF16 是否总比 FP16 准？** 不是，量级小范围内 FP16 有更多尾数精度；最终训练稳定和效率取决于任务与硬件。

**易错：** 软件声明一种 dtype，不代表所有中间计算都使用该精度。

<a id="X05"></a>
## X05｜PTQ、QAT、weight-only quantization 怎么分？（P0）


### 训练后再压缩，还是训练时就练习适应误差？

PTQ 在已有模型训练完成后做量化；QAT 在训练中模拟或考虑量化误差；weight-only 说的是主要量化权重，而不是把所有中间计算都低位化。

前两者描述什么时候处理量化，后者描述量化什么，不能放在同一层面互斥选择。

**直答：** 分开说明量化时机与量化对象，并报告实际存储、计算精度和质量损失。

### 进一步：公式、边界与追问

**技术表述：** PTQ 在训练后量化，QAT 在训练中模拟量化影响；weight-only 主要压缩权重，激活和 KV 未必一起量化。

**展开：** 用 scale/zero point 把实数映射到有限整数；per-tensor、per-channel、group-wise 各有元数据与误差取舍。离群值会影响量化范围。

**追问：4bit 为什么不一定更快？** 若无高效 kernel，反量化和小 batch 开销可能抵消访存收益；应测目标硬件和真实 workload。

**易错：** 量化位数低不等于质量必然可接受。

<a id="X06"></a>
## X06｜GPTQ 与 AWQ 核心思路是什么？（P1）


### 压缩时，尽量别伤到最影响输出的部分

GPTQ 用校准信息近似考虑量化误差怎样影响结果，并补偿部分误差；AWQ 利用激活信息识别较重要的权重通道，通过缩放等办法降低量化影响。

校准样本不代表所有任务，所以压缩后仍要测目标能力，不能只看文件缩小。

**直答：** 二者都尝试用数据指导低位量化，降低关键误差；具体取舍看目标模型、校准集、硬件支持与任务结果。

### 进一步：公式、边界与追问

**技术表述：** GPTQ 利用近似二阶信息补偿逐步权重量化误差；AWQ 利用激活统计识别重要权重并做缩放保护。

**展开：** 两者都需理解校准数据与目标层，不能只凭模型文件名判断实际配置。量化后要测长上下文、代码、中文和安全边界等目标能力。

**追问：校准集为何重要？** 它代表运行激活分布；只用短英文句子校准，未必适合中文长对话。

**易错：** 不把校准集用于调参后继续当独立测试集。依据：S38、S39。

<a id="X07"></a>
## X07｜分布式 loss 如何避免变长样本权重错误？（P0）


### 两张卡分别做 10 题和 90 题，不能各占总成绩一半

若一张卡只有 100 个有效 token，另一张有 900 个，目标是所有 token 同权，那么前者应占 10%，后者占 90%。

直接平均两卡各自的平均损失，会错误地让少 token 的卡占一半。分布式训练的求和和分母必须一起考虑。

**直答：** 先确定样本或 token 的权重目标，再跨设备正确汇总损失与数量，避免“平均的平均”造成变长数据权重错误。

### 进一步：公式、边界与追问

**技术表述：** 明确全局目标的分子与分母，用有效 token 总数而非盲目平均各卡均值。

**展开：** 一卡 100 个有效 token、另一卡 1000 个，各卡均值等权平均会放大小卡 token 权重。DDP 的梯度平均机制需与 loss 的缩放配合，梯度累积也一样。

**追问：序列平均是不是一定错？** 如果目标本来要每条样本同权就合理；错误在于实现与声称的目标不一致。

**易错：** padding 和截断样本不能被当作有效监督计入分母。关联：RL10。

<a id="X08"></a>
## X08｜训练 OOM 从哪些方向处理？（P0）


### 显存爆了，先知道是谁占满了柜子

权重过大、序列过长、批次太大、中间激活太多，都可能触发 OOM。不同来源对应不同办法：减批次、累积、重计算、分片、量化或调整长度。

贸然截短所有输入虽然省空间，却可能丢掉关键监督，应同步检查任务影响。

**直答：** 按显存组成定位超额来源，再选择有针对性的资源方案，并验证输入信息与训练目标没有被意外改变。

### 进一步：公式、边界与追问

**技术表述：** 先定位是权重状态、激活、序列峰值还是临时缓冲，再选择缩 batch、控长度、重计算、分片或低比特。

**展开：** 记录失败时输入长度、batch、阶段和分配峰值；LoRA 节省优化器状态，却未必解决超长激活。减 batch 后可用正确加权的梯度累积维持目标。

**追问：清空缓存可以根治吗？** 对真正超出容量的活跃张量无效；内存泄漏需找保留计算图、日志张量或未释放引用。

**易错：** 频繁清缓存可能拖慢训练，还掩盖代码问题。

<a id="X09"></a>
## X09｜异步 rollout 与策略滞后怎么解释？（P1）


### 出卷时学生是旧水平，批改完他已经进步了

异步 rollout 让生成数据和训练同时进行，提高设备利用率；但训练收到的答案可能由较旧版本模型生成，与当前策略有差异。

这种策略滞后会影响更新。需要记录版本、控制滞后程度，并检查概率计算和修正方法。

**直答：** 异步采样提高并行利用率，也带来旧策略数据；需要显式管理版本、延迟与分布差异。

### 进一步：公式、边界与追问

**技术表述：** 采样和训练并行提高利用率，但轨迹可能来自较旧参数，更新时要知道对应行为策略。

**展开：** 每条轨迹记录策略版本、生成设置、token 与 logprob；控制队列陈旧程度，必要时丢弃过旧轨迹或做适当纠偏。工具任务越长，滞后越明显。

**追问：只更新模型权重就够了吗？** 采样服务的权重同步、缓存兼容、tokenizer/template 和概率计算也需一致。

**易错：** off-policy 修正不是无代价的万能解决，方差和支持仍限制效果。依据：S66。

<a id="X10"></a>
## X10｜Checkpoint 保存与恢复要验证什么？（P0）


### 存下模型，不一定就能接着同一次训练

若只保存权重，忘了优化器状态、学习率进度、随机状态和数据位置，重新启动可能不像从断点继续。

真正验证恢复，要让中断重启后的短段训练与连续运行比较，而不只是确认文件能够读取。

**直答：** 按用途保存权重及必要训练状态，并实际验证恢复后的行为；“可加载”和“可继续同一训练过程”不同。

### 进一步：公式、边界与追问

**技术表述：** 不仅保存权重，还要按恢复目标保存优化器、调度、随机状态、数据游标与分片信息，并实际试一次恢复。

**展开：** “能加载推理”与“能从同一步续训”是不同验收；分布式恢复要检查 world size 改变时支持情况。LoRA 必须记录对应基座 revision。

**追问：恢复后 loss 突变？** 查数据顺序、学习率、优化器状态、精度与损失缩放；不先假定是随机波动。

**易错：** 只把若干 checkpoint 目录列出来不证明它们可用。
