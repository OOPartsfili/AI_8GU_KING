# 06 PPO、GRPO 与可验证奖励

先把强化学习理解成“自己作答—获得成绩—调整下次选择”。RL01 解释策略、动作、奖励和 rollout；RL03 区分几种角色。先理解 RL06 的四份答案，再展开 GRPO 长公式。

<a id="RL01"></a>
## RL01｜语言生成怎么建模为强化学习？（P0）


### 从看标准答案，变成自己做完再看成绩

SFT 常让模型模仿示范；强化学习则可以让模型自己生成一份答案，系统给结果打分，再调整模型的选择倾向。

在这种描述里，前文是“当前状态”，选下一个 token 是“动作”，模型给各 token 的概率叫“策略”，答案得到的分数叫“奖励”。rollout 就是实际生成并记录这样一次过程。

**直答：** 语言生成可以看成连续选择 token 的过程；强化学习利用生成结果的奖励，调整以后走向不同答案的概率。

### 进一步：公式、边界与追问

**本章进阶约定与范围：**

定位：后训练高阶追问。必须区分当前策略 θ、采样旧策略 θ_old、固定参考策略 ref、奖励模型和价值模型。γ 在 RL 中常指折扣因子，和 SimPO 的 margin 同字母但含义不同。

**技术表述：** 状态是问题与已生成前缀，动作是下一个 token，策略是语言模型，终止于 EOS 或长度上限；奖励可在末尾或中间给出。

**展开：** 代码任务可用测试结果作奖励，偏好任务可用奖励模型；工具型 Agent 的环境状态还包括工具与外部系统。奖励最大化必须处理探索、延迟反馈和分布变化。

**追问：终局奖励如何影响前面 token？** 通过策略梯度把回报分配给轨迹中的动作；粗粒度分配未必准确定位真正关键步骤。

**易错：** “有 reward”不等于奖励可信。依据：S11、S12、S13。

## RL02｜策略梯度为什么用 log π？（P0）


### 结果不错，就增加走出这条路径的机会

模型写完答案后才得到一个分数。策略梯度把这个反馈接到生成概率上：好结果对应的选择更值得重复，差结果对应的选择要降低机会。

log 概率的导数提供了调整这些概率的方便表达，也能把一串概率乘积拆成求和。它不是“给奖励取 log”，更不是把最终分数平均分给每一步就自然正确。

**直答：** 策略梯度用奖励相关的权重，乘上生成动作的 log 概率梯度，把结果好坏转成概率更新方向。

### 进一步：公式、边界与追问

**技术表述：** 利用 ∇π=π∇logπ，把期望的梯度写成从当前策略采样即可估计的形式。

$$\nabla_\theta \mathbb E_{\tau\sim\pi_\theta}[R(\tau)]
=\mathbb E_\tau\left[R(\tau)\nabla_\theta\log\pi_\theta(\tau)\right].$$

在环境转移不依赖 θ 的条件下，轨迹 log 概率中可训练部分是各动作 logπ 的和。

**追问：为什么减 baseline？** 与当前动作无关的 baseline 在适当条件下不改变期望梯度，却能减少方差。优势表示动作相对预期表现的好坏。

**易错：** 奖励为负仍可学习；关键是相对优势与目标定义，而不是所有 reward 必须为正。

<a id="RL03"></a>
## RL03｜PPO 的 actor、critic、reward、reference 是什么？（P0）


### 写答案、预测前景、评卷、留旧稿

actor 是写答案的模型；critic 估计从当前情况继续写下去，大致能拿多少回报；reward model 或验证器给结果评分；reference 是固定参考模型，用来约束变化。

想象比赛里有选手、赛前预测员、裁判和原有表现基准，职责不同。实际程序能否共用部分网络，要看实现，不能靠角色数直接数模型份数。

**直答：** 先区分生成动作、估计价值、提供奖励和比较基准这四个职责，再讨论 PPO 系统具体需要哪些网络。

### 进一步：公式、边界与追问

**技术表述：** actor 生成动作，critic 估计价值，reward 提供评分，reference 限制策略偏移；可以有参数共享，但概念不同。

**展开：** 旧 actor 用来计算采样概率比；critic 通常跟训练更新；reference 常固定。不同 RLHF 系统可能合并、移除或预计算某些角色。

**追问：PPO 必须永远有四份完整模型同时驻留吗？** 不一定。实现可共享、分阶段、卸载或采用不同奖励来源，必须按实际架构算资源。

**易错：** old policy 不是“语义上判断好坏的老师”。依据：S11。

<a id="RL04"></a>
## RL04｜PPO clip 目标如何解释正负优势？（P0）


### 一次好成绩，不能让学生立刻押上全部赌注

**优势**先理解成“这次比通常预期好多少”。优势为正，想提高这条选择的概率；为负，想降低它。

PPO 再看新旧概率的比值。例如旧概率 0.2、新概率 0.3，比值为 1.5，变化已有 50%。clip 会限制目标从过大变化中继续获得好处，避免一次更新过分追随这批成绩。

它不是把实际概率硬锁在某个范围里。正负优势时，取最小项的作用方向还不同，下面的算例再展开。

**直答：** PPO 用优势决定鼓励还是抑制某些选择，再通过新旧概率比的裁剪限制过大的优化激励，帮助控制单次更新幅度。

### 进一步：公式、边界与追问

$$r_t(\theta)=\frac{\pi_\theta(a_t|s_t)}{\pi_{\rm old}(a_t|s_t)}$$

$$J_{\rm clip}=\mathbb E\min\big(r_tA_t,\ \mathrm{clip}(r_t,1-\epsilon,1+\epsilon)A_t\big).$$

**技术表述：** 用保守的替代目标，限制“继续朝已获益方向推得过远”的激励。

**展开：** A>0 时，r 超过上界后不再继续增加该样本收益；A<0 时，r 低于下界后不再继续奖励进一步压低概率。不是把真实更新或 KL 强行限制在一个硬球内。

**追问：clip 外梯度一定为零？** 要看优势符号和 min 选中的分支。负优势且 r 过大时，仍可能有纠正梯度。

**易错：** 训练通常最小化 −J，符号不能反。依据：S11。

<a id="RL05"></a>
## RL05｜GAE 是什么，λ 在折中什么？（P1）


### 一步走得好不好，要看眼前，也要看后果

下棋的一步暂时吃到子，却可能几步后丢掉更大优势。GAE 会综合不同长度的后续反馈，估计当前动作比预期好多少。

只看近处更依赖价值模型的估计，可能有偏；看得很远能利用更多真实结果，但随机波动也可能更大。λ 是调节这种混合方式的参数。

**直答：** GAE 混合不同时间长度的优势估计，用 λ 在依赖价值预测与承受长期回报波动之间取舍。

### 进一步：公式、边界与追问

**技术表述：** GAE 将不同长度的时序差分残差按权重累积，构造优势估计，在偏差与方差间折中。

$$\delta_t=r_t+\gamma V(s_{t+1})-V(s_t)$$

$$\hat A_t=\sum_{l\ge0}(\gamma\lambda)^l\delta_{t+l}.$$

**展开：** λ 接近 0 更依赖一步估计，λ 接近 1 更依赖长程回报；价值估计误差和轨迹终止规则影响结果。截断与真正终止的 bootstrap 处理不能混用。

**追问：GRPO 为什么省 critic？** 用同题组内奖励作比较基准，而不是为每个状态训练价值网络。

**易错：** 不要把 λ 当成学习率。依据：S61、S12。

<a id="RL06"></a>
## RL06｜GRPO 最核心的变化是什么？（P0）


### 不另请预测老师，先让同一道题的几份答案互相比

对一道题生成 4 份回答，得分为 [0,0,1,1]，平均是 0.5。两份成功回答高于组平均，应得到正向信号；失败回答低于平均，应得到反向信号。

GRPO 用这种组内比较来构造优势，省去 PPO 常用的独立价值模型。它仍要生成多份答案并评分，不能理解成训练完全没成本。

**直答：** GRPO 对同题多次生成的结果做组内比较，用相对奖励构造优势，再优化生成概率，减少对独立 critic 的依赖。

### 进一步：公式、边界与追问

**技术表述：** 同一个问题生成一组回答，以组内相对奖励估计优势，通常省去独立价值模型。

$$\hat A_i=\frac{R_i-\bar R}{\mathrm{std}(R_1,\ldots,R_G)+\varepsilon}.$$

**展开：** 简单 outcome reward 设置里，一个回答的多个有效 token 共享该优势，再通过 token 概率比更新。原始 GRPO 也讨论过程奖励；工程变体对归一化、KL 和采样纠偏有差异。

**追问：没有 critic 就没有 baseline？** 仍有组内均值基准，只是来源不同。

**易错：** “只奖励最佳答案”不等于 GRPO 的全部组内相对更新。依据：S12。

## RL07｜GRPO 完整目标怎么写？（P0）


### 先拆成三件事，别盯着整行公式

GRPO 目标里通常能看到：第一，根据组内表现判断该鼓励谁；第二，用新旧概率比和裁剪控制更新；第三，在相应设置中用 KL 约束偏离参考模型。

最后还要规定不同回答、不同 token 怎样求平均。看懂这些部件后，长公式只是把它们写在一行；不同实现会改变部件和开关。

**直答：** 读 GRPO 目标时按“优势—概率比与裁剪—可选约束—聚合方式”拆开，逐项确认具体论文和训练器版本的定义。

### 进一步：公式、边界与追问

以一种常见的原始形式表示：

$$J=\mathbb E\left[\frac1G\sum_{i=1}^{G}\frac1{|y_i|}
\sum_t\left(\min(r_{i,t}\hat A_i,\mathrm{clip}(r_{i,t},1-\epsilon,1+\epsilon)\hat A_i)
-\beta D_{i,t}\right)\right].$$

**技术表述：** 组内优势决定方向，概率比与 clip 稳定更新，KL 项可约束参考偏离；按序列或 token 聚合会改变权重。

**追问：所有 GRPO 框架都这样默认吗？** 不是。本文引用的 TRL v0.24.0 文档提供 dapo、dr_grpo 等选项，不能从“用 GRPOTrainer”推断实际目标。

**易错：** 这里 β 是 KL 项权重，与 DPO/SimPO 里的记号应按各自公式解释。依据：S12、S16。

<a id="RL08"></a>
## RL08｜组内奖励全相同会怎样？（P0）


### 四个人都得零分，排名就教不了谁

假设同题生成四份答案，奖励全为 0。每份减去组平均仍为 0，组内比较无法说明哪份更值得学习。全都得 1 分也一样。

这不是程序一定坏了，而是这一组没有相对差异。增加探索或挑选有学习空间的题可能有帮助，但不能凭空把错误答案标成成功。

**直答：** 同组奖励全相同时，常见组内中心化得到零优势，偏好方向的学习信号消失；需要检查题目难度、生成覆盖和奖励区分度。

### 进一步：公式、边界与追问

**技术表述：** 减去组均值后优势全为零，奖励驱动的策略梯度没有区分信号；KL 等额外项仍可能产生更新。

**展开：** 全对可能表示题太简单，全错可能题太难、验证器坏或探索不足。增加组大小仅提高遇到差异的机会，不保证解决。

**追问：怎么排查？** 分开记录全对、全错与部分正确的比例，检查奖励解析、采样温度、课程难度及是否被截断。

**易错：** std=0 加 ε 防止数值异常，但不会凭空产生学习信号。依据：S12、S16。

<a id="RL09"></a>
## RL09｜奖励标准差归一化有什么副作用？（P1）


### 一个班只差一分，除以很小的波动会怎样？

组内标准差表示这组奖励有多分散。把差值除以标准差，可以统一尺度；但如果整组差异很小，小小的奖励变化也可能被放得很大。

这会改变不同题目的相对权重。奖励中的微小噪声，也可能因此显得很重要。

**直答：** 标准差归一化既调整尺度，也可能改变题目权重并放大奖励噪声；要结合零方差处理和不同难度题的表现检查。

### 进一步：公式、边界与追问

**技术表述：** 它改变问题间的相对权重；同样的原始奖励差，在低方差组中可能被放大。

**展开：** 组归一化便于比较不同尺度，但可能引入题目难度相关偏置。移除标准差缩放、用 batch 统计或调整采样都是不同设计，需与基线比较。

**追问：只看 reward mean 够吗？** 不够，还看 group std、有效组比例、长度、熵与分任务收益。

**易错：** 任何归一化都在定义训练权重，不能视为纯数值清洁。依据：S15、S16。

## RL10｜GRPO、DAPO、Dr. GRPO 的归一化差在哪里？（P1）


### 先平均每篇作文，还是先平均每个字？

短回答有 2 个 token，长回答有 8 个。如果先算每条回答的平均损失，再各占一半，两个回答同等重要；如果把 10 个 token 放在一起平均，长回答占 8/10。

再改成除以预先规定的固定长度，整体更新尺度也会变。分母看似只是算术细节，其实在决定训练重视什么。

**直答：** 不同聚合方式给回答和 token 不同权重；讨论 GRPO、DAPO、Dr. GRPO 时，要写出实际分母，并区分各方法的其他改动。

### 进一步：公式、边界与追问

**技术表述：** 它们对回答长度和有效 token 的权重处理不同；DAPO 还包含其他训练改进，不能被缩成一个分母。

| 聚合示意 | 单题一组 token loss l 的聚合 |
|---|---|
| 原始序列平均 | (1/G)∑ᵢ(1/Lᵢ)∑ₜ lᵢₜ |
| DAPO 型 token 平均 | ∑ᵢₜ lᵢₜ / ∑ᵢLᵢ |
| Dr. GRPO 型常数归一 | ∑ᵢₜ lᵢₜ / (G·L_max) |

**展开：** 可用“短回答 2 token、长回答 8 token、同样每 token loss”手算，看单条回答和单个 token 的权重。分布式训练还需确认分母是否跨卡正确汇总。

**追问：两条回答各贡献多少？** 每 token loss 取 1，序列平均中各贡献 1/2；token 平均中分别为 2/10 与 8/10；常数归一取 L_max=10，分别为 2/20 与 8/20。单题组内 token 平均与常数归一的相对权重相同，但分母尺度及跨组关系不同。

**易错：** 不能只改名字不记录实际 loss_type、scale_rewards 与截断处理。依据：S14、S15、S16。

## RL11｜KL 的采样估计为什么可能出现负数？（P1）


### 真正的平均数非负，不代表每次抽样值都非负

KL 是一整个分布上的加权平均。实际大模型通常难以枚举所有完整答案，于是抽样估计。

像一个长期盈利的项目，某一天也可能亏损，单个样本的 log 概率比可以为负；这不否定对应真实 KL 的非负性。要看样本按哪个分布取得、估计量怎么定义。

**直答：** KL 的非负性属于正确计算的分布平均；有限样本或单条 log 比可能为负，需区分真值、估计量与采样误差。

### 进一步：公式、边界与追问

**技术表述：** 真正 KL 非负，但单个采样点的 log 概率比可以为负；有限样本均值也可能有波动。

若从当前 π 采样，令 u=π_ref(a|s)/π(a|s)，常见非负点估计为：

$$u-\log u-1\ge0.$$

它在支持与期望条件成立时对应 KL(π‖π_ref) 的期望。实现是否使用当前、旧策略或纠偏权重需确认。

**追问：logπ−logπ_ref<0 就是代码错吗？** 不一定，它只是该 token 在参考模型下更可能。

**易错：** token 抽样估计、词表精确 KL、整序列 KL 不要不加说明地混报。依据：S12、S16。

<a id="RL12"></a>
## RL12｜RLVR 与 reward hacking 是什么？（P0）


### 有客观判卷器很好，但模型可能钻规则空子

数学题可以核对答案，代码题可以运行测试，用这些可验证结果提供奖励，就是 RLVR 的典型思路。

如果程序只检查最后有没有出现正确数字，模型可能在正文乱答、结尾堆数字，也拿到分。这叫 reward hacking：学会迎合评分规则，却没实现真正目标。

**直答：** RLVR 利用可验证结果提供训练奖励；验证器需要检查真实任务要求，否则优化会放大奖励规则的漏洞。

### 进一步：公式、边界与追问

**技术表述：** RLVR 用规则、答案或执行结果提供可验证奖励；reward hacking 是策略利用评分漏洞获得高分，却没完成真实目标。

**展开：** 代码只通过可见用例可能硬编码；格式奖励过重可能产生漂亮空答案；答案提取器宽松可能接受矛盾输出。验证器需要负例、边界例、隐藏用例和解析失败统计。

**追问：规则奖励比模型奖励永远可靠？** 规则更可检查，但覆盖有限且可能被利用；正确运行的评分器也可能测错目标。

**易错：** reward=1 只表示通过当前规则，不自动证明完整推理正确。依据：S13。

<a id="RL13"></a>
## RL13｜过程奖励与结果奖励怎么选？（P1）


### 只看最后答案，还是也批改步骤？

结果奖励像只看最终答案是否正确，便宜直接，但不容易定位哪一步有贡献；过程奖励也评价中间步骤，反馈更细，却需要更可靠、更昂贵的步骤判断。

一道题可能有多种正确解法，若过程评审只认一种写法，就可能误罚其他有效路径。

**直答：** 结果奖励适合最终结果可可靠验证的任务；过程奖励能提供更细反馈，但要处理步骤标注成本与错误评审风险。

### 进一步：公式、边界与追问

**技术表述：** 结果奖励便于定义但反馈稀疏；过程奖励提供更密集信号，却需可靠地评价中间步骤。

**展开：** 数学最终答案可判定，不代表每一步可简单打分；错误推理可能偶然得到正确结果。过程评分器也可能偏爱熟悉路径，误伤新解法。

**追问：怎么公平比较？** 控制标注和评审计算预算，报告最终正确率、搜索成本、过程评分与人工一致性，做验证器失效分析。

**易错：** 把每步都给同一个最终 reward 不等于学到了准确的过程价值。依据：S17。

<a id="RL14"></a>
## RL14｜RL 训练不稳定时先看什么？（P0）


### 成绩乱跳时，先查试卷和裁判

在线训练中，模型不断生成新答案。若奖励程序有错、回答被截断、策略版本记混，就算优化器完全正确，训练也会异常。

先看完整生成案例、奖励分布、全错组、答案长度和更新幅度，再决定是否调整学习率。

**直答：** 先验证采样、奖励和数据记录，再查梯度与优化设置；训练不稳定往往来自整个学习流程，而不只是某一个参数。

### 进一步：公式、边界与追问

**技术表述：** 先排奖励与轨迹正确性，再看策略更新幅度、采样分布和系统一致性。

**展开：** 核查奖励解析、EOS/截断、response mask、old logprob 与当前权重版本；监控 ratio、clip fraction、KL、entropy、梯度与全零优势组。若 rollout 引擎与训练引擎算出的概率不同，需要明确纠偏或容忍范围。

**追问：reward 上升、真实测试下降怎么办？** 检查奖励投机、过拟合验证器、长度漂移和测试分布；停止只围绕训练 reward 选模型。

**易错：** 直接加大 KL 或降低学习率可能缓解表面症状，却没修复数据错误。

<a id="RL15"></a>
## RL15｜在线 RL 的真正成本在哪里？（P0）


### 不只上课花时间，出题、作答、批改也花时间

在线 RL 每轮需要让模型真正生成多份回答，再验证、打分、整理训练数据，最后更新参数。长回答、多候选和慢工具都可能让采样成为主要成本。

所以省掉 critic 并不等于省掉主要时间。要统计完整一轮，而不只是反向传播耗时。

**直答：** 在线 RL 的成本包括生成、环境交互、验证和训练更新；总预算要按整条流程计算，关注最慢的环节。

### 进一步：公式、边界与追问

**技术表述：** 不只反向传播，往往还有大量采样、长回答、评分、工具环境和同步等待。

**展开：** 成本记录包括生成 token、训练 token、每题组数、验证器调用、环境时间、GPU 利用率与峰值显存。长短任务混合可出现尾部等待；异步能改善吞吐，却引入策略滞后与轨迹版本管理。

**追问：省掉 critic 就一定比 DPO 便宜？** 不一定；在线探索可能远比一次离线训练昂贵，应比较总预算与质量。

**易错：** 不要用 optimizer step 数对比不同 rollout 长度和组数。

<a id="RL16"></a>
## RL16｜R1、GRPO、推理链的关系如何讲得准确？（P0）


### 产品、训练方法和写作过程，属于三个层次

R1 是具体模型与训练工作的名称；GRPO 是其中涉及的一类策略优化方法；推理链是模型生成的中间推理文本。

这好比某位学生、某种教学法、学生写下的解题步骤，三者有关，但不能互相当作定义。

**直答：** 把模型、优化方法和输出行为分开描述。某模型使用 GRPO，不代表任何 GRPO 训练都会获得相同推理能力。

### 进一步：公式、边界与追问

**技术表述：** GRPO 是训练方法之一；R1 系列工作展示了通过 RL 等训练阶段改善推理的路线；可见推理链是输出行为，不是算法本身。

**展开：** 区分 R1-Zero 与完整 R1 的冷启动、数据筛选和多阶段过程；“纯 RL”不能概括所有版本。推理链出现反思字样不证明该步骤真实贡献了正确率。

**追问：模型一定学到了新推理能力吗？** 要定义能力边界并控制采样预算，比较大 k 覆盖率、任务迁移和去污染评测。后续研究有不同条件下的发现，详见 F05。

**易错：** 不要把“我读过 R1”写成“我做过大规模 RL”。依据：S13。
