## F01｜CoT、Self-Consistency、Best-of-N 有何区别？（P0）


### 自己写步骤、大家投票、请老师挑一份

CoT 是引导或训练模型写中间推理；Self-Consistency 是生成多次后，对最终答案做聚合；Best-of-N 是生成 N 份，由评分器挑一份。

它们可以组合，但代价与失败方式不同：多数答案可能一起错，评分器也可能偏爱看起来漂亮的错答案。

**直答：** 三者分别改变推理表达、多次答案聚合和候选选择方式；都需要把多生成与多评审的成本算进去。

### 进一步：公式、边界与追问

**本章进阶约定与范围：**

本章不是排行榜。核查日 2026-09-15，精选能改变面试判断的研究；未逐一核实会议决定的工作按作者论文讨论，不声称正式接收。

**技术表述：** CoT 引导或训练中间推理；Self-Consistency 对多次采样的最终答案做聚合；Best-of-N 用评分器从 N 个候选中选一个。

**展开：** 三者可组合。答案投票要求可比较与规范化；Best-of-N 依赖评审器区分正确答案，不能使用部署时拿不到的标准答案。

**追问：N 倍采样一定得到 N 倍收益？** 候选高度相关、验证器有偏或题目超出能力覆盖时，收益会很小甚至恶化。

**易错：** 长 CoT 是计算行为，不是推理正确的证明。依据：S17、S62。

<a id="F02"></a>
## F02｜推理时计算为什么要按难度分配？（P0）


### 一分钟会做的题，不一定值得再想一小时

简单题追加计算可能帮助不大；完全超出能力的题，反复尝试也未必有效；有机会解出但不稳定的题，额外尝试可能更有价值。

部署时不能偷看标准答案来判断难度，只能利用分歧、验证结果或事先学到的难度线索。

**直答：** 根据可观测的困难程度和追加计算收益分配预算，用正确率、耗时与成本一起评估，避免所有题都无限多想。

### 进一步：公式、边界与追问

**技术表述：** 简单题继续采样收益小，极难题可能怎么搜都找不到有效解；中等难度题往往更有利用额外计算的空间。

**展开：** 可先低成本生成，用外部可验证信号或校准置信度决定追加采样、搜索或转人工。评价要用正确率—成本曲线，包含评审器成本和尾延迟。

**追问：难度标签从哪来？** 不能在部署时偷看标准答案；可用独立开发数据训练路由器，或采用可观测的分歧、验证失败、历史任务属性。

**易错：** “多想一会一定比换大模型划算”不是普遍结论。依据：S17。

<a id="F03"></a>
## F03｜离线蒸馏、on-policy 蒸馏、自蒸馏怎么分？（P0）


### 抄老师的范文，和让老师批改自己的草稿

离线蒸馏可以用事先收集的教师答案教学生；on-policy 蒸馏则让学生先写，再由教师对学生实际走到的内容提供反馈。

自蒸馏说的是教师与学生的关系：教师可能来自自己或相关版本，有时拥有额外上下文。它并不表示“没有额外信息也一定能无限变强”。

**直答：** 区分反馈在什么轨迹上产生，以及教师来自哪里；蒸馏的价值要看教师信号是否可靠、是否针对学生真实短板。

### 进一步：公式、边界与追问

**技术表述：** 离线蒸馏使用固定教师数据；on-policy 蒸馏在学生自己生成的轨迹上获取教师反馈；自蒸馏指教师来自自身模型或相关版本，具体机制需说明。

**展开：** token 分布蒸馏与只训练教师最终文本不同。前者需要概率信息与词表/对齐支持；后者常是序列级示范训练。on-policy 的价值是让教师处理学生实际会走到的状态。

**追问：同一个模型怎么教自己？** 可以给教师额外已验证解题上下文，而学生只看问题；学习将额外信息带来的行为压缩进学生。教师反馈本身仍可能错误。

**易错：** 学生不见特权信息，不代表教师生成数据可以包含测试答案。依据：S18。

<a id="F04"></a>
## F04｜Entropy-Aware On-Policy Distillation 新在哪里？（P1）


### 老师也拿不准时，别急着只学一种写法

教师在某些 token 上给多种选择较高概率，说明它也保留了多种可能。相关研究尝试在这些高熵位置增加特定方向的 KL 约束，缓和学生过度集中于少数路径的倾向。

这里先读 M03 的 KL 方向，再看论文的门控和损失细节。高熵只是选择位置的信号，不自动代表该位置更重要。

**直答：** 这类方法尝试根据教师的不确定性选择蒸馏约束，研究多样性与质量的权衡；结论要保留模型和任务条件。

### 进一步：公式、边界与追问

**技术表述：** 在教师高不确定性的 token 上，额外引入前向 KL 约束，以缓和只用反向 KL 时过度集中于少数路径的倾向。

**展开：** 先明确教师/学生分布方向，再看高熵门控与损失组合。论文在特定数学任务和模型规模上研究多样性与 Pass@8，不可直接推断所有聊天或安全任务都改善。

**追问：可做什么消融？** 固定教师、学生、轨迹预算，比较反向 KL、全位置双 KL、高熵位置双 KL；同时看单次正确率、采样覆盖、熵与成本。

**易错：** 高熵不天然等于关键推理点，方法收益需独立任务验证。依据：S19，作者版本 2026-06-12。

<a id="F05"></a>
## F05｜RL 是扩展能力还是重新分配概率？（P1）


### 考试更稳定，是新会了，还是原来会的更容易发挥？

如果模型偶尔本就能答对，训练后答对频率上升，可能主要是概率重新分配；要判断是否扩展了可解决题目的范围，就要看更广任务和更多次采样。

有限次没答对不能证明概率严格为零。不同研究的基础模型、训练强度和测试预算也不同。

**直答：** 先定义能力提升的含义，再区分单次成功率与可解题覆盖；不能只凭一个分数判断 RL 是否创造了新能力。

### 进一步：公式、边界与追问

**技术表述：** 不能一概而论。要先定义“能力”，再看基础模型、任务、采样覆盖和 RL 训练强度。

**展开：** S64 研究发现某些设置中小 k 性能提升伴随大 k 覆盖受限；S63 的 ProRL 在更长训练和不同设计下报告更广覆盖。这是条件不同的实证结果，不是互相否定的数学定理。

**追问：如何检验“基础模型不可能”？** 有限次未采到只支持“在该预算下未观察到”；无法证明其概率严格为零。应报告 k、温度、token 预算和任务划分。

**易错：** 不能用 pass@1 上升直接证明新增知识，也不能用一个研究断言 RL 永不产生能力提升。依据：S63、S64。

<a id="F06"></a>
## F06｜验证器为什么可能成为新的瓶颈？（P0）


### 候选答案越多，越考验挑选答案的人

生成 100 份答案，有一份正确当然有潜在价值，但只有选中它才能交付好结果。若评分器容易被漂亮措辞欺骗，候选越多，反而越可能找到“很会拿分”的错答案。

因此增加计算时，也要测试评审是否能识别关键错误。

**直答：** 多采样的收益受验证器限制；扩大候选数必须同时检查挑选能力和相关成本。

### 进一步：公式、边界与追问

**技术表述：** 更多候选只有在能可靠识别优劣时才有用；评分器的误报会被搜索放大。

**展开：** 如果 N 增大，越容易找到能欺骗评审器的候选。可构造“表面合理但关键错误”负例，比较与人工或执行结果的一致性，按任务难度校准。

**追问：多个 judge 投票能解决吗？** 若它们共享数据、偏好和失败模式，错误相关性仍很高；需要不同证据来源，不能只换提示词。

**易错：** 自评置信度并不天然等于真实正确概率。

<a id="F07"></a>
## F07｜测试时学习与上下文学习是一回事吗？（P1）


### 改笔记，和真正改大脑里的参数

把几个例子放进输入，模型按例子回答，通常没改权重；Agent 保存一条外部记忆，也可能只改了数据库。另一些测试时学习方法会实际更新模型参数。

因此看到“会学习”，要追问到底改的是提示、记忆还是权重，以及使用了什么反馈。

**直答：** 上下文、外部记忆和参数更新是不同适应方式；讨论测试时学习时先明确可修改对象和评价方法。

### 进一步：公式、边界与追问

**技术表述：** 上下文学习通常不更新模型权重，通过输入示例改变行为；测试时学习是更宽泛术语，可能指上下文适应、记忆更新或真正参数更新。

**展开：** 描述方法时交代可修改的是提示、记忆、检索索引还是权重，以及是否使用标签。线上适应可能遗忘旧规则，也可能引入污染。

**追问：Agent 写入记忆算训练吗？** 不一定，它改变外部状态而非参数。应分别评估记忆写入正确、时效、冲突与删除。

**易错：** 不要看到 test-time learning 就自动理解为反向传播。依据：S33。

<a id="F08"></a>
## F08｜扩散语言模型与自回归模型有何区别？（P2）


### 从左到右接写，还是多轮修复缺失部分？

自回归模型通常写出一个 token，再继续写下一个；某些扩散语言模型从被遮住或加噪的文本状态开始，通过多轮预测恢复内容。

第二种不代表一次就完成全文：可能要反复处理整段，训练目标和概率计算也不同。

**直答：** 两类方法的生成顺序和训练过程不同；并行恢复部分内容有潜力，但速度、质量和后训练方法都要按具体模型比较。

### 进一步：公式、边界与追问

**技术表述：** 自回归按前缀逐 token 建模；一些扩散语言模型通过多轮恢复或去噪生成文本，可利用不同的生成顺序与局部补全方式。

**展开：** 离散文本的噪声过程、训练目标和概率计算必须按具体模型定义；不能把图像扩散公式直接搬过来。减少串行 token 步数，也可能需要多轮全序列计算。

**追问：适合直接照搬 DPO/GRPO 吗？** 需处理序列似然估计、生成路径和动作定义；不能假定现成自回归 logprob 接口可用。

**易错：** “非自回归”不意味着一步出完整答案或一定更快。LLaDA 的掩码恢复建模见 S49；偏好优化研究入口见 S65。

## F09｜2026 Agent RL 值得关注什么工程问题？（P1）


### 训练一个办事助手，先得记清它到底做过什么

Agent 可能读网页、调用工具、遇到报错再重试。要用 RL 训练它，必须准确区分模型写出的 token、工具返回的数据、每一步的版本以及最终结果。

否则一份看似完整的记录，也可能把外部返回文字误当成模型动作。

**直答：** Agent RL 不只需要优化公式，还需要可靠的轨迹记录、环境执行和任务评分；工程接口本身就是学习能否成立的前提。

### 进一步：公式、边界与追问

**技术表述：** 除了优化器，长任务的轨迹重建、工具环境、异步采样与训练接口一致性直接决定能否有效学习。

**展开：** Polar 等工作把已有 Agent 运行环境接到 RL，强调准确记录模型 token 交互与评测。岗位上应追问：工具输出算不算生成 token、失败轨迹如何截断、策略版本如何跟踪、终态怎么评分。

**追问：换个 Agent 框架就提升，说明 RL 算法更好？** 未必，提示、工具接口和恢复逻辑都可能变化，要做同运行环境对照。

**易错：** 不将单个软件任务集的收益外推为所有 Agent；该条按作者预印本观察。依据：S66，2026-05。

## F10｜如何讲一篇新论文而不显得只追热点？（P0）


### 讲论文，先讲它修好了什么麻烦

比如“旧方法在所有候选都错时没有学习信号”，比先报算法缩写更容易理解。接着讲作者增加了什么信息或步骤、是否公平对比、在哪些情况仍会失败。

最后提出一个自己能完成的小验证，才能把阅读变成有判断力的理解。

**直答：** 用“问题—反馈—改动—对照—边界—验证”讲论文，并把读懂、实现和复现结果如实区分。

### 进一步：公式、边界与追问

**技术表述：** 用“问题—训练信号—关键变化—对照—边界—复现”六步回答。

**展开：** 先说原方法在哪种输入上失败；写出新增模块或目标；说明数据、采样与预算是否变化；报告主指标之外的退化；提出可以在现有资源上完成的最小验证。

**追问：论文自称 SOTA，能直接写简历吗？** 阅读可以写研究理解；只有真实复现日志和对照才支撑“复现/实现”，有原创改进与证据才支撑“提出/优化”。

**模板：** “该方法尝试解决___；我认为最关键的假设是___；若迁移到内容安全，我会先测___，失败标准是___。”

## F11｜IGPO 为什么利用局部补全来引导探索？（P2）


### 太难的题完全无从下手，可以先给一点已知正确的步骤

IGPO 在特定扩散语言模型设置中利用部分正确推理片段帮助探索，让模型更容易进入有希望的生成区域。

这相当于给了额外提示，因此对比时必须算入信息优势。训练时用提示，不代表测试时也能看答案。

**直答：** 该思路用部分已知正确内容引导探索，缓解成功轨迹难找到的问题；评估时必须说明额外监督和测试条件。

### 进一步：公式、边界与追问

**技术表述：** 在扩散语言模型在线采样中放入部分已知正确推理片段，让模型更容易进入有希望的轨迹区域，减少全组失败。

**展开：** 提示部分路径属于额外监督，比较时必须计入信息优势；不能把收益全归因于优化器。需要明确训练时插入比例、位置、如何评价以及测试时不提供答案。

**追问：这和纯粹奖励探索有什么差别？** 它混合了已知解信息与自生成轨迹，帮助解决稀疏奖励下找不到成功路径的问题。

**易错：** 不能用测试答案辅助生成再当作无辅助推理评测。依据：S65。
