# 04 SFT、LoRA 与训练排障

先看模型怎样模仿示范答案，再看怎样节省更新参数。前置是 M01、M02；先读 SFT01 和 SFT03，rank、alpha、量化等细节可以第二遍再看。

<a id="SFT01"></a>
## SFT01｜SFT 的目标和训练样本长什么样？（P0）


### 给模型看一份“题目和标准作答示范”

例如输入：“把这句话翻译成中文”，示范回答是正确译文。SFT 让模型读到输入后，把示范回答中实际出现的 token 概率调高。

这里不是只记住“翻译”这个标签，而是在学习怎样一步步写出回答。通常让模型阅读整个对话，但主要对助手应答部分计分。

**直答：** SFT 是用输入和示范输出训练生成模型，让它更容易按要求写出类似的回答；数据格式和哪些位置计分非常关键。

### 进一步：公式、边界与追问

**本章进阶约定与范围：**

定位：内容安全和后训练岗位的必答主线。建议结合本人 SFT 项目逐题补充实际配置与日志。

**技术表述：** 用高质量示范提升模型在给定指令下生成期望回答的概率。数据通常含 system、user、assistant 角色和模板化边界。

$$L_{\mathrm{SFT}}=-\frac{\sum_{i,t}m_{i,t}\log\pi_\theta(y_{i,t}|x_i,y_{i,<t})}{\sum_{i,t}m_{i,t}}.$$

**展开：** m 为有效目标 mask，常只覆盖回答 token。多轮样本需决定监督所有 assistant 轮次还是最后一轮；两种设计都要与任务对齐。

**追问：为什么高质量示范重要？** 损失会奖励示范本身；如果示范习惯无依据拒答，模型就会更倾向这种行为。

**易错：** 分母为有效 token 数的写法与先每样本平均再求平均不同。

<a id="SFT02"></a>
## SFT02｜全参微调、LoRA、Prompt Tuning 怎么选？（P0）


### 改整本教材、加小补丁、还是改开头提示？

全参微调允许改动模型的大量原有权重；LoRA 冻结原权重，只训练附加的小矩阵；Prompt Tuning 学习一段可训练的输入表示。

这是不同的“允许改哪里”。改动位置少通常节省部分训练资源，但不保证适合所有任务，也不能只按可训练参数量估算总显存。

**直答：** 根据任务变化幅度、资源和部署方式选择可更新的部分；全参、LoRA 和 Prompt Tuning 的核心差别是更新位置和自由度。

### 进一步：公式、边界与追问

**技术表述：** 全参更新容量大但资源需求高；LoRA 更新权重的低秩增量；Prompt Tuning 学习输入端或类似位置的连续提示参数。

**展开：** 选择要考虑任务变化幅度、数据规模、GPU、推理部署和多任务管理。LoRA 适合资源受限与多适配器场景，但不能预先保证性能等于全参。

**追问：只训练少量参数为什么还需不少显存？** 基座权重仍需参与计算，中间激活、反向传播路径和临时缓冲也会占用显存。

**易错：** “冻结参数”不等于所有基座层都能用 no_grad 包住，否则可能切断 LoRA 的梯度路径。依据：S06。

<a id="SFT03"></a>
## SFT03｜LoRA 的公式、参数量与初始化怎么推？（P0）


### 不重写整个大表，只学习它怎样改动

假设模型里有一张 1000×1000 的权重表，共 100 万个数字。LoRA 不直接更新整张表，而是训练 1000×8 和 8×1000 两张小表，共 1.6 万个数字。

两张小表相乘，仍得到 1000×1000 的修改量，再加到原表上。8 叫 rank（秩）参数，它限制修改量能表达的形式，所以不是任意大改动都能用这么少数字表示。

**直答：** LoRA 用两个小矩阵的乘积表示大矩阵的更新量，冻结原权重，只训练小矩阵，从而减少可训练参数和相关训练开销。

### 进一步：公式、边界与追问

**技术表述：** 将权重更新写成两个低秩矩阵相乘，学习 ΔW=(α/r)BA。

$$W\in\mathbb R^{d_{\rm out}\times d_{\rm in}}$$

$$A\in\mathbb R^{r\times d_{\rm in}}$$

$$B\in\mathbb R^{d_{\rm out}\times r}.$$

新增参数为 r(d_in+d_out)。当 d_in=d_out=4096、r=8 时为 65,536，原矩阵为 16,777,216，比例约 0.39%，忽略偏置。

**追问：A 随机、B 为零时，为什么一开始 A 梯度为零？** ΔW=BA；对 A 的梯度含 B，而 B=0。B 首步可有梯度，随后 A 也开始更新。

**易错：** A/B 命名可能被实现交换，答题先给形状。依据：S06。

<a id="SFT04"></a>
## SFT04｜LoRA rank、alpha、作用层如何调？（P0）


### 补丁有多大、力度多强、贴在哪里？

rank 影响补丁能表达多复杂的变化；alpha 参与调整补丁输出的缩放；作用层决定在哪些权重上加补丁。

不要把三个旋钮混成“越大越强”。补丁容量变大后，学习率、数据量和过拟合风险也要重新检查。

**直答：** 分别控制更新容量、缩放和位置，在固定数据与预算下逐项比较，并记录具体实现采用的缩放公式。

### 进一步：公式、边界与追问

**技术表述：** rank 控制增量表达容量；alpha 控制缩放；作用层决定能改变哪些计算。三者需要联合看。

**展开：** 普通 LoRA 常用 α/r，其他变体可有不同缩放。先固定数据和预算，比较低/中 rank、attention-only 与包含 MLP 的设置，同时记录质量、参数量、显存与时延。

**追问：rank 越大越好吗？** 不保证。小数据可能过拟合，训练成本上升；任务是否需要更高秩要由验证集回答。

**易错：** 不能换 rank 时忘记实际缩放改变；也不能只报告“LoRA 微调”却说不出 target modules。依据：S06。

<a id="SFT05"></a>
## SFT05｜LoRA 合并后为什么通常不增加推理分支？（P0）


### 训练时分开改，交付时合成一张表

LoRA 的线性层可以写成“原权重产生的结果＋补丁产生的结果”。在满足相应条件时，先把补丁矩阵加进原权重，以后直接使用合好的权重，就不必每次额外走补丁分支。

这像把批注落实到最终稿。量化、多适配器切换等设置还要检查精度和具体实现。

**直答：** 对可合并的线性 LoRA，先把更新量加到原权重，就能用一个合并后的矩阵推理；合并效果要做数值与任务验证。

### 进一步：公式、边界与追问

**技术表述：** 对兼容的线性层可把低秩增量加回原权重，得到 W′=W+ΔW，再按普通线性层计算。

**展开：** 合并要匹配基座版本、精度与适配器缩放。量化基座重新合并/量化可能产生额外数值误差；多个 adapter 并不是随便相加就能保持各任务性能。

**追问：何时不合并？** 需要请求级切换多个适配器时，保留独立 adapter 更灵活，但调度与额外计算代价要实测。

**易错：** 合并减少分支不意味着模型从未发生数值变化。依据：S06。

<a id="SFT06"></a>
## SFT06｜QLoRA 是“用 4 bit 训练全部参数”吗？（P0）


### 把大底座压缩存放，另外训练小补丁

QLoRA 的直觉是：庞大的基础模型用较低位数表示并冻结，学习主要发生在 LoRA 小矩阵上。这样可以节省基础权重的存储。

低位存储不代表所有计算都在 4 bit 中进行，更不代表全部基础参数都在被更新。

**直答：** QLoRA 结合量化存放的冻结基座和可训练 LoRA；要分清权重存储精度、计算精度和实际更新的参数。

### 进一步：公式、边界与追问

**技术表述：** 不是。典型 QLoRA 把冻结基座以低比特存储，在计算时按需要反量化，训练较高精度的低秩适配器。

**展开：** 论文包含 NF4、双重量化与分页优化器等设计。低比特权重存储、矩阵乘计算精度、梯度和优化器状态精度是不同概念。

**追问：4 bit 模型显存就是参数数÷2 字节吗？** 那只是裸权重粗估，还需量化元数据、未量化层、激活、适配器和运行缓冲。

**易错：** QLoRA 不等于所有矩阵乘都在原生 int4 中完成。依据：S07。

<a id="SFT07"></a>
## SFT07｜训练 loss 不下降，按什么顺序排查？（P0）


### 学生成绩不动，先检查题目有没有发对

loss 不下降，先看模型是否真的收到了正确输入和答案、答案位置有没有计分、参数是否参与更新。把一两条干净样本反复训练，看能否学会，是很有帮助的小检查。

如果最小例子也学不会，再查学习率、数值异常和程序连接。直接扩大模型或跑更久，可能只会放大浪费。

**直答：** 按“数据与标签—计分位置—参数与梯度—学习率和数值”的顺序排查，先验证模型能学会极小数据集。

### 进一步：公式、边界与追问

**技术表述：** 先验证数据和监督是否正确，再检查梯度、优化器和学习率，最后才扩大模型或算力。

**展开：** 取极小样本尝试过拟合；检查模板还原、label shift、有效 token 数、EOS、截断；核查 requires_grad、optimizer 参数、梯度范数与实际学习率。确认训练模式、精度溢出和 NaN 来源。

**追问：几条样本也记不住说明什么？** 高概率是实现、数据或优化问题，尚不能归因于泛化能力不足。

**易错：** loss 为零也可能是所有 label 被忽略，不一定训练完美。

<a id="SFT08"></a>
## SFT08｜loss 很好，但生成乱码或不停重复怎么办？（P0）


### 跟着答案填空容易，自己往下写可能出错

训练时前文常含真实答案；生成时前文是模型自己刚写出的内容。一步写偏，后面可能继续偏。模板、结束符或生成参数不一致，也会导致重复和停不下来。

因此不仅看训练扣分，还要真的让模型独立回答几道固定问题，保存完整输出检查。

**直答：** 低训练损失不保证自由生成正常；先对齐训练与生成的模板、结束符和分词，再检查数据重复与生成设置。

### 进一步：公式、边界与追问

**技术表述：** 对齐训练和推理的 tokenizer、chat template、特殊 token、EOS 与解码设置，再检查数据污染和过拟合。

**展开：** 比较同一输入在基座、SFT checkpoint 的 greedy 输出；核查词表/embedding 尺寸、padding side、模板重复插入和结束条件。统计重复片段、异常长度与语言混杂，不只看一条输出。

**追问：调高 repetition penalty 就解决了吗？** 可能掩盖问题，也可能破坏代码、专有名词和必要复述，应先定位。

**易错：** 训练验证都使用错误模板，也能得到看似一致的低 loss。

<a id="SFT09"></a>
## SFT09｜为什么训练要看 token 数和长度分布？（P0）


### 100 条短句和 100 篇长文，训练量差很多

模型逐 token 计算。只报“训练了 1 万条”看不出实际工作量：长度越长，处理的 token 更多，注意力成本和显存也可能更大。

还要区分总 token 与真正参与损失的 token。很长的用户输入和很短的助手回答，不应被统计成同样长度的回答监督。

**直答：** token 数和长度分布决定真实计算与监督规模；比较实验时同时报告样本、总 token、有效计分 token 和长度截断。

### 进一步：公式、边界与追问

**技术表述：** token 决定主要计算与监督量；长样本会影响 batch 权重、显存、截断和吞吐。

**展开：** 报告样本数同时报告有效训练 token、prompt/completion 分布和截断比例。内容安全长对话若总在关键风险前被截断，模型学不到跨轮信息。

**追问：动态 padding 与 packing 差别？** 前者按批内最大长度补齐；后者把独立短样本装进同一序列，涉及边界语义。

**易错：** 训练速度从 samples/s 提高，可能只是样本更短；应同时看有效 tokens/s。

<a id="SFT10"></a>
## SFT10｜怎么选择 checkpoint 和早停指标？（P0）


### 不一定是最后一版作业最好

checkpoint 是训练途中保存的模型快照。后面的快照可能训练分更好，却过拟合、误拒更多，或忘记了通用能力。

应预先规定用哪些开发集指标选快照，并保留最终测试集做独立判断。早停就是发现继续训练收益不足或退化时及时停下。

**直答：** 用事先确定的验证指标和约束选择训练快照，不能只选训练 loss 最低或最后保存的那一个。

### 进一步：公式、边界与追问

**技术表述：** 按冻结的多指标选择规则决定，而非只取训练 loss 最低的版本。

**展开：** 内容安全可在满足最低长尾召回和正常响应率的约束下，优化主指标与成本；RAG 则约束引用可靠与无证据拒答。保存各 checkpoint 的配置、数据快照和生成设置。

**追问：如果不同指标互相冲突？** 呈现 Pareto 候选与业务约束，说明选择代价；不要临时改指标把某个 checkpoint 包装成最好。

**易错：** 使用最终测试集做早停会泄漏选择信息。

## SFT11｜SFT 能否替代偏好优化？（P0）


### “照着好答案学”和“分清谁更好”有何不同？

SFT 直接给一份好答案，告诉模型怎样写；偏好优化给出两个答案或好坏反馈，让模型学习哪些输出更值得出现。

例如两份回答都通顺，但一份更符合安全规则，仅做示范训练和直接学习两者差异，提供的监督信息不同。是否需要后者，要看实际短板和反馈。

**直答：** SFT 学示范行为，偏好优化利用优劣关系调整生成倾向；它们可以配合，也可能在某些任务上只用 SFT 就已足够。

### 进一步：公式、边界与追问

**技术表述：** 强 SFT 是必要基线，但只模仿 chosen 不一定充分利用“为什么 rejected 更差”的相对信息。

**展开：** 若数据只有可靠好答案、差答案质量参差，SFT 可能更合适；若有同题可比的偏好对，DPO/SimPO 可利用排序信号。应比较基座、SFT、继续 SFT、偏好优化，控制额外训练预算。

**追问：偏好算法赢了，是不是算法必然优越？** 可能来自更多数据、不同标注器和生成候选，应做配对数据、长度控制等消融。

**易错：** 不要把所有 SFT 回答叫“标准答案”，开放任务可能有多个合理解。

<a id="SFT12"></a>
## SFT12｜训练运行记录最低需要什么？（P0）


### 过两周，还能做出同一道菜吗？

如果只记得“用了 LoRA，效果不错”，却没保存数据版本、模型版本、模板、参数和随机种子，就像做菜只记得“加了一些调料”，难以复现。

日志还应记录训练何时开始、花了多少资源、最终选择哪个快照，以及怎样测试。

**直答：** 保存能重建训练与评测条件的记录：模型、数据、模板、配置、代码版本、随机性设置、资源和结果，而不只是最好分数。

### 进一步：公式、边界与追问

**技术表述：** 能从记录重建数据、模型、配置、运行环境和选择过程。

**展开：** 记录模型 revision、tokenizer/template、数据哈希及切分、随机种子、软件版本、硬件、精度、并行、batch/累积、优化器、学习率、保存策略、主评测及日志。附真实开始结束时间、有效 token 与峰值显存。

**追问：只有 config 就可复现吗？** 还需要代码版本、数据可达性、依赖和评测协议；非确定性算子可能使逐位复现不现实，应说明统计复现标准。

**易错：** 不能把没有实际运行的配置写成训练结果。
