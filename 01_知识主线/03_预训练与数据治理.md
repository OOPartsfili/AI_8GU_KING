# 03 预训练、数据治理与实验控制

**完整预训练路线：**本章侧重数据治理；从目标到实际训练流程的 20 题见 PT01—PT20，包含预算、优化、MTP、长上下文与训练异常排查。

把训练数据当作教材来理解：教材从哪里来、是否教错、有没有重复、考试题是否提前泄漏。先读 D01 区分训练阶段，后面每题都围绕一个具体的数据问题。

<a id="D01"></a>
## D01｜预训练、继续预训练、SFT、对齐分别改变什么？（P0）


### 学语言、学专业、学答题、学偏好

可以把训练阶段理解成不同的学习材料：预训练广泛读文本，学习接下来通常怎样写；继续预训练加入某领域材料，进一步熟悉其语言和知识；SFT 看“问题—示范回答”，学会按要求回答；对齐再利用偏好或奖励，调整什么样的回答更值得生成。

这些阶段会相互影响，并不是严格分成四个独立能力开关。

**直答：** 先看每个阶段给模型什么材料、用什么反馈。广泛文本、领域文本、示范答案和偏好反馈，会把模型引向不同的学习方向。

### 进一步：公式、边界与追问

**本章进阶约定与范围：**

定位：理解训练信号从哪里来，能解释数据效果与算法效果。预训练工程属于补强知识，不在简历中冒充已完成经历。

**技术表述：** 预训练学习广泛分布；继续预训练适配新领域或语言；SFT 学习指令到回答的示范；偏好或奖励优化进一步改变行为选择。

**展开：** 它们的分界主要在数据与目标，不是简单由“是否更新全部参数”区分。领域继续预训练常保留 next-token 目标；SFT 可全参也可 LoRA。流程可交替，不保证每个模型都经历相同阶段。

**追问：业务知识过期，先继续预训练吗？** 先评估检索、数据库与工具是否更合适。频繁变化、需精确引用的知识通常更适合外部更新；领域语言与稳定技能再考虑训练。

**易错：** SFT 不是只能改格式，也可能学知识和技能；但参数记忆不保证精确可控的知识更新。

<a id="D02"></a>
## D02｜Scaling law 与 Chinchilla 怎么回答？（P1）


### 大模型和多做题，预算应该怎样分？

预算固定时，可以造一个更大的模型，也可以让较小模型读更多训练 token。只增加模型大小，却没有足够数据训练，就可能花了很多钱却没把容量用好。

Scaling law 研究这些规模与损失之间的经验关系；Chinchilla 研究了特定设置下模型规模和训练数据量的分配。经验关系能指导预算，不是跨任务都精确成立的配方。

**直答：** 不只问模型要多大，还要问数据和计算是否匹配。规模规律给出经验指导，具体比例仍要结合训练方式与任务验证。

### 进一步：公式、边界与追问

**技术表述：** Scaling law 用经验规律描述损失随参数、数据与计算预算变化；Chinchilla 强调在其研究条件下，模型规模和训练 token 应共同配置。

**展开：** 不能把某个 token/parameter 比例当永恒最佳值。若模型要服务很多请求，更多训练小模型可能降低总生命周期推理成本，即使不满足单次训练的 compute-optimal 配比。

**追问：6ND 是什么？** Dense Transformer 训练 FLOPs 的粗估，N 为参数数、D 为训练 token 数，系数依赖计算计数和假设；长注意力、稀疏专家等需修正。

**易错：** 更低预训练 loss 不直接等于更高安全性或 Agent 成功率。依据：S05。

<a id="D03"></a>
## D03｜“高质量数据”如何操作化？（P0）


### “好教材”不能只用一个形容词判断

一页语言通顺但答案错误的教材，对训练可能有害；一页内容正确但和目标任务无关，也未必有用。因此要把“高质量”拆成能检查的条件。

例如抽查答案是否正确、是否重复、格式能否解析、难度是否合适、边界情况是否覆盖，再统计每项的比例。

**直答：** 把数据质量拆成正确性、相关性、多样性、可用性等具体检查项，并用抽样审核和训练对照验证它们的价值。

### 进一步：公式、边界与追问

**技术表述：** 用明确的目标适配性、正确性、多样性、去重和可追踪标准定义，并用受控实验验证。

**展开：** 数据卡至少记录来源、授权范围、时间、语言、主题、长度、质量规则、去重方法、版本。过滤器可能偏爱某种文风或语言，误删专业数据，因此要抽样审查“被保留”和“被删除”的样本。

**追问：只要大模型打分高就好？** 评审器可能偏向冗长、自信或熟悉风格，应与人工样本对齐并观察下游指标。

**实验：** 固定训练 token 预算，比较原始、规则过滤、模型评分过滤三组，报告任务收益与被删场景，不只报保留比例。

<a id="D04"></a>
## D04｜精确去重、近似去重与泄漏检查怎么区分？（P0）


### 一字不差、换个说法、提前见过考题

两条样本完全相同，精确去重就能发现；“如何退票”和“怎样办理退票”可能语义相近，需要近似去重。测试题或答案进入训练材料，则是评测泄漏，要跨数据切分检查。

后两者都不能仅靠文件是否完全相同来判断。题目换了措辞，核心答案也可能已经泄漏。

**直答：** 精确去重找相同内容，近似去重找高度相似内容，泄漏检查则关注训练材料是否提前暴露测试信息，检查范围不同。

### 进一步：公式、边界与追问

**技术表述：** 精确去重找规范化后相同样本；近似去重找高度相似片段或模板；泄漏检查判断测试信息是否进入训练或选择过程。

**展开：** 可用哈希处理完全重复，用 n-gram shingles、MinHash/LSH 做候选召回后核验近似重复；语义相近不一定等于应删。要防页面不同却包含相同问答、翻译版本和同攻击模板。

**追问：训练测试随机切分够吗？** 不够。按用户、会话、文档、模板或时间分组，单位由实际泛化目标决定；先识别重复族再分组切分。

**易错：** 高训练测试相似度是线索，不是泄漏的充分证明；阈值需人工审查。

<a id="D05"></a>
## D05｜数据配比怎么调？（P1）


### 每天练什么，会改变学生擅长什么

一个训练批次里若 90% 都是数学题，模型得到的大部分更新也来自数学。调整数据配比，就是调整不同能力被练习的频率。

但多练某类可能挤掉其他类的训练时间。应在总 token 预算相同时比较，而不是一边改变比例、一边多训练一倍。

**直答：** 数据配比决定模型把训练机会花在哪些任务上；用目标能力、遗忘情况和固定预算下的对照来选择比例。

### 进一步：公式、边界与追问

**技术表述：** 从部署需求建立目标分布，再兼顾稀缺能力与遗忘风险，通过固定预算的混合实验调配比。

**展开：** 数据集大小不同，可按任务采样权重而非自然数量拼接；过度重复小数据可能记忆化。报出每类采样概率、实际 token 占比及 epoch 等效次数。

**追问：安全数据越多越好吗？** 过强拒答示范可能增加正常请求误拒。要搭配安全邻域、澄清、可回答的敏感主题和通用能力集。

**易错：** 样本比例与 token 比例不是同一个量，长文本可能主导损失。

<a id="D06"></a>
## D06｜Packing 为什么提速，又有哪些坑？（P0）


### 一节车厢不要只坐两个人

若训练长度固定为 1000 token，某条样本只有 100 token，其余位置用填充补齐，会浪费计算。Packing 把多条短样本装进同一长序列，提高有效内容占比。

装在一起后，还得标清边界、计分位置和注意力规则，防止后一条样本不合理地利用前一条的信息。

**直答：** Packing 通过减少填充浪费提高利用率，但要正确处理样本边界、注意力和损失遮罩，不能只拼接文本。

### 进一步：公式、边界与追问

**技术表述：** 将多段短样本装入较长序列，减少 padding。关键是样本边界、注意力隔离、位置编号与 loss mask 的一致性。

**展开：** 独立样本若直接拼接，后者可能看到前者；这可以是有意训练设计，也可能是泄漏。SFT 回答起点、EOS、系统提示和截断规则必须明确。

**追问：只加 EOS 就隔离 attention 吗？** 通常不会。EOS 是 token；真正阻断跨样本关注需要支持的 mask/变长注意力实现。

**检查：** 打印打包后 token、样本 ID、position ID、有效 label，手查至少一条跨边界样本。

## D07｜合成数据与自训练如何避免错误放大？（P0）


### 学生出的练习册，也需要老师校对

模型生成数据很便宜，但可能重复同一个错误。如果把这些回答全当正确答案再训练，错误会被反复强化。

可用程序检查、可靠参考或人工抽查筛选，再保留真实数据作独立考试。关键是新增数据带来了什么信息，而不只是数量变大。

**直答：** 合成数据需要独立质量检查和去重；生成者与评审者共享错误时尤其要谨慎，最终收益用独立测试验证。

### 进一步：公式、边界与追问

**技术表述：** 让生成、筛选和评测形成可追踪闭环，用独立验证与真实数据锚定，避免同一模型的偏差自我确认。

**展开：** 记录生成模型、提示模板、采样参数和来源种子；去重并按生成家族隔离。数学可用可执行答案校验，业务安全要抽样人工检查语境。

**追问：学生一定不可能超过教师吗？** 不成立。额外数据、任务定向训练、采样聚合和不同评测都可能带来超越；必须控制信息和计算预算。

**易错：** “由强模型生成”不等于真标签；风格变一致也可能损害覆盖。

<a id="D08"></a>
## D08｜数据污染如何让模型选择过程作弊？（P0）


### 不止提前见过考题才算作弊

反复看同一测试集，每次都根据分数改提示词、选模型，即使没有把测试题拿来训练，也逐渐在“针对这张卷子优化”。

开发集用来试方法，最终测试集用来做一次相对独立的判断。两者角色混用，会高估对新问题的能力。

**直答：** 数据污染既包括训练见过测试内容，也包括反复用测试结果指导选择；需要隔离开发、选型和最终评测。

### 进一步：公式、边界与追问

**技术表述：** 不仅训练看到测试题算污染，反复根据同一个测试集调提示、阈值和超参数，也会把测试集变成开发集。

**展开：** 训练集用于拟合，验证集用于选择，冻结测试集用于最终估计。线上挑战集可滚动，但要区分发现问题的数据与衡量修复泛化的数据。

**追问：公开基准还能用吗？** 可以做可比参照，但不能独自证明无泄漏泛化。搭配新时间切片、私有未见样本和任务变体。

**易错：** “没直接训练 benchmark 文件”并不保证没从网页、翻译或合成样本间接见过。

<a id="D09"></a>
## D09｜灾难性遗忘如何识别与缓解？（P0）


### 补了一门课，原来的强项却退步

模型专门练安全拒答后，可能连正常问题也不愿回答；只练某种格式后，也可能更难完成别的任务。这类旧能力退化需要通过旧任务的固定测试发现。

缓解可以从混入通用样本、降低更新强度、缩短训练或调整训练目标入手。具体哪种有效，要用前后对照判断。

**直答：** 灾难性遗忘是学习新任务时旧能力明显退化。训练目标能力的同时，要保留旧能力测试，观察收益和代价。

### 进一步：公式、边界与追问

**技术表述：** 新任务收益伴随旧能力显著退化时，需要检查遗忘。可考虑降低更新强度、混合通用数据、正则化或参数高效训练。

**展开：** 在训练前固定通用、领域、安全和格式评测，沿 checkpoint 画多指标曲线。LoRA 也可能改变行为，不是自动免疫遗忘。

**追问：loss 持续下降但旧能力退化怎么办？** 验证早停、减少 epoch/学习率、修正数据配比，并确认不是提示模板或解码参数变了。

**易错：** 每个 benchmark 波动都叫遗忘不严谨，需要看误差范围与一致性。

## D10｜怎么证明收益来自算法？（P0）


### 换了老师，也换了教材，成绩上涨该归功于谁？

新方法用了更多数据、更长训练、更大的模型，分数更高不能单独证明新算法有效。要尽量让比较双方其他条件一致，只改变要研究的部分。

如果无法完全一致，就明确列出差异，控制最关键因素，再用补充对照解释可能影响。

**直答：** 证明算法贡献，需要控制模型、数据、训练和采样预算等条件；一次综合升级有效，不等于其中每个改动都有效。

### 进一步：公式、边界与追问

**技术表述：** 控制起始模型、训练数据、预算、评测和调参资源，只改变待研究因素，再做消融与不确定性分析。

**展开：** DPO/SimPO 比较至少统一 SFT checkpoint、偏好对、tokenizer、最大长度、数据切分和生成评测配置；算法自身关键超参数允许合理调优，记录搜索预算。

**追问：步数相同就公平吗？** 长度、采样次数和每步计算可能不同。可分别报告固定数据、固定训练 FLOPs/时长、固定总成本三种视角。

**易错：** 完全不给新方法调参也不是公平；只挑最好 seed 同样会夸大收益。
