# 02 Transformer、位置编码与模型结构

这一章解释模型怎样读前文、记顺序和交换信息。先读 M01、M04，知道 token、分数与概率，再从 T01 的 Q/K/V 例子开始。符号和工程变体放在直觉之后理解。

<a id="T01"></a>
## T01｜Self-Attention 的 Q、K、V 是什么？（P0）


### 把一句话看作正在互相查资料的词

读“杯子放在桌上，因为它很稳”时，“它”需要联系前面的词才有意义。自注意力让每个位置根据当前需要，从其他位置取信息。

可以把 Q 想成“我想找什么”，K 是“我提供什么线索”，V 是“我实际携带的信息”。Q 和各个 K 越匹配，对应 V 被取用的比例越大；最后把取来的信息加权汇总。

Q、K、V 不是人写好的标签，而是模型把原有表示经过三组可学习变换算出来的。同一个词可以同时作为提问者和信息提供者。

**直答：** 自注意力让一个位置按相关程度汇总其他位置的信息。Q 用来查询，K 用来匹配，V 提供被汇总的内容，这三者都由模型学习得到。

### 进一步：公式、边界与追问

**本章进阶约定与范围：**

依赖：M01–M06。重点是维度、复杂度、信息流与推理代价，避免只背组件名称。

**技术表述：** Q 表示当前位置要寻找什么信息，K 表示每个位置可被如何匹配，V 是匹配后实际汇聚的内容。

$$Q=XW_Q,\ K=XW_K,\ V=XW_V$$

$$O=\mathrm{softmax}(QK^\top/\sqrt{d_k}+M)V.$$

**展开：** 单头 X∈R^{B×L×d}，Q/K∈R^{B×L×d_k}，注意力矩阵为 B×L×L。softmax 沿被关注的 key 位置归一化。Q/K/V 是同一输入的不同可学习投影，不是三份独立文本。

**追问：为什么 Q 和 K 不共用一套权重？** 不同投影可表达非对称关系，共享属于额外结构约束，不是数学上不允许。

**易错：** 注意力权重不是完整因果解释；残差、MLP 与层间计算同样影响输出。依据：S01。

## T02｜为什么除以 √d_k？（P0）


### 比分为什么需要统一尺度？

注意力用 Q 和 K 的对应数字相乘再相加，得到匹配分数。向量维度越多，参与相加的项越多，在常见初始化假设下分数波动也会变大。

把波动很大的分数直接交给 softmax，可能很快变成“一个候选接近 100%，其他接近 0”，训练不容易细调。除以维度的平方根，是把这种规模带来的波动拉回合适范围。

**直答：** 除以 √d_k 主要是控制匹配分数的尺度，避免维度变大时 softmax 过早变得极端。它是在常见方差假设下的缩放，不是让每个向量长度都等于 1。

### 进一步：公式、边界与追问

**技术表述：** 在各维近似独立、零均值、单位方差的分析假设下，点积方差随 d_k 增长；缩放能减轻 softmax 饱和。

**展开：** Var(∑q_i k_i)≈d_k，除以 √d_k 后方差约为 1。实际训练后的向量不严格满足假设，因此这是初始化和优化尺度的解释。

**追问：不缩放会怎样？** 大幅 logits 差异可能使分布过尖、梯度变小，训练更难；不能说一定训练失败。

**易错：** 分母是每个 head 的 key 维度平方根，不必等于整个 hidden size 的平方根。依据：S01。

## T03｜多头注意力解决什么问题？（P0）


### 同一句话，可以从几个角度看

“小王把书递给小李”里，模型可能需要同时联系“谁在做动作”“给了什么”“给谁”。多头注意力就是并行使用几组不同的 Q、K、V 变换，让模型有机会建立不同的信息联系。

这些头不一定自动分别负责语法、指代、情感；有的功能也会重叠。多头给了不同观察方式，具体学出什么由训练决定。

**直答：** 多头注意力让模型在不同表示空间里并行提取信息，再合并结果；它增加了表达关系的方式，但不保证每个头都有固定的人类可命名职责。

### 进一步：公式、边界与追问

**技术表述：** 用多个投影子空间学习不同关联，再拼接并投影，让单个位置能够综合不同关系。

**展开：** 常见设置 H 个头，每头维度 d/H，输出拼接仍为 d；并非头数增加就必然按 H 倍增加全部参数。头可能冗余，也不一定能逐一对应“语法头”“事实头”。

**追问：头越多越好吗？** 固定 d 时每头更窄，可能损失表达；实际还受 kernel、KV cache 与硬件效率影响。

**易错：** 多头不是对同一注意力结果简单做多次平均。依据：S01。

## T04｜MHA、MQA、GQA 怎么比较？（P0）


### 几个提问者，要不要各存一整套资料？

先把 Q 看作提问方式，K/V 看作查询线索和内容。MHA 让每个头有自己的 Q、K、V；MQA 保留多个 Q 头，但让它们共用一组 K/V；GQA 则分组共享，是两者之间的安排。

生成长回答时，需要保存历史 K/V。如果 8 个头各存一份，存储多；让 8 个头分成两组、每组共用一套 K/V，就能少存一些。

**直答：** MHA、MQA、GQA 的主要差别是 K/V 是否共享、共享到什么程度。共享通常能减少生成时的缓存，但质量和速度要结合具体模型与实现比较。

### 进一步：公式、边界与追问

**技术表述：** 区别在多个 query head 是否共享 K/V。MHA 各自有 K/V；MQA 全部共享一组；GQA 分组共享。

| 结构 | KV 头数 H_kv | 主要取舍 |
|---|---:|---|
| MHA | H_q | 表达灵活，KV 读写与缓存较多 |
| GQA | 介于 1 与 H_q 之间 | 在质量和访存间折中 |
| MQA | 1 | KV 最省，共享约束最强 |

**追问：GQA 缓存缩小多少？** 在层数、序列长度、head dim 和精度相同时，约按 H_kv/H_q 缩小；总显存还包括权重等。

**易错：** query 头数没有一起变成 1。依据：S03。

## T05｜因果 mask、padding mask、loss mask 有何区别？（P0）


### 三种“遮住”，遮的不是同一件事

想象学生做填空题：遮住后面的标准答案，是防止偷看未来，这对应 **causal mask（因果遮罩）**；忽略为了排齐长度而塞进去的空格，是 **padding mask（填充遮罩）**。

老师还可能让学生阅读题目，只对回答部分打分。这对应 **loss mask（损失遮罩）**：某些位置参与理解，但不计入训练扣分。

因此“能不能看见”和“要不要打分”必须分开。题目不计分，不代表模型不能读题。

**直答：** 因果遮罩限制看未来，填充遮罩排除无效填充，损失遮罩决定哪些位置参与训练评分；三者不能互相替代。

### 进一步：公式、边界与追问

**技术表述：** 因果 mask 阻止看未来；padding mask 阻止把补齐位置当信息；loss mask 控制哪些目标位置贡献训练损失。

**展开：** SFT 可让回答 token 看到完整用户输入，同时只对 assistant token 算 loss；这不意味着提示词在前向传播中被删除。packing 多个独立样本时，还要决定是否阻断跨样本注意力。

**追问：只屏蔽 prompt loss 就没有 prompt 的梯度了吗？** 提示词表示参与后续回答计算，因此仍可通过回答损失影响共享参数。

**易错：** 不能用 loss mask 代替 attention mask。检查目标 shift 是否只移动一次。

## T06｜RoPE 为什么有相对位置信息？（P0）


### 模型怎样知道两个词隔了多远？

如果只看到一堆词，却不知道顺序，“狗咬人”和“人咬狗”就很难区分。RoPE 给位置信息的一种做法，是根据位置旋转 Q、K 向量中的成对坐标。

可以先想两个表盘指针：一个转了角度 a，另一个转了 b，比较它们时会涉及两者的角度差。RoPE 的旋转设计使匹配计算能包含类似的“位置差”信息。

这个比喻只解释相对位置从哪里来；实际是高维向量中许多二维旋转，并非给词画一个真实表盘。

**直答：** RoPE 根据位置旋转 Q、K，让它们的匹配计算包含相对位置差。它给注意力加入顺序线索，但不自动保证任意长文本都能处理好。

### 进一步：公式、边界与追问

**技术表述：** 对 Q/K 的二维分量按位置旋转，两者点积中出现的是旋转角之差，因此可表达相对位置。

$$\langle R_mq,R_nk\rangle=q^\top R_m^\top R_n k=q^\top R_{n-m}k.$$

**展开：** 不同维度采用不同频率；绝对位置决定旋转，但注意力点积包含相对位移。通常作用在 Q/K，不要未经检查就说 V 也旋转。

**追问：天然支持无限长吗？** 公式可以算更长位置，但频率、位置分布和训练长度之外的泛化未获保证。位置插值、频率调整与长上下文训练需要评测。

**易错：** “有相对位置”不等于平移后所有网络行为完全相同。依据：S02。

## T07｜LayerNorm、RMSNorm 与 Pre-Norm 怎么讲？（P0）


### 一路计算下去，数字的尺度容易失控

模型有很多层，每层都会变换一组数字。如果数值尺度忽大忽小，后面就更难稳定学习。归一化的作用是调整这些表示的尺度。

LayerNorm 会考虑均值和方差；RMSNorm 主要按均方根缩放，不先减均值。Pre-Norm 的“Pre”说的是放置位置：先归一化，再交给该层的注意力或前馈变换。

**直答：** 归一化帮助控制各层表示的尺度；LayerNorm 与 RMSNorm 的计算方式不同，Pre-Norm 则指归一化放在主要变换之前。名字分别在描述“怎么算”和“放哪里”。

### 进一步：公式、边界与追问

**技术表述：** LayerNorm 在特征维做中心化与尺度归一；RMSNorm 主要按均方根缩放。Pre-Norm 在子层之前归一，常有较直接的残差梯度路径。

**展开：** LN 的典型形式是 (x−μ)/√(σ²+ε) 再仿射；RMSNorm 用 x/√mean(x²)，不减均值。具体是否有 bias 要看模型实现。

**追问：和 BatchNorm 区别？** LN 不依赖批间统计，更适合变长文本、较小 batch 及自回归推理。

**易错：** “RMSNorm 完全没有可学习参数”通常不对，常有逐维缩放。依据：S56。

## T08｜FFN、SwiGLU 与残差分别做什么？（P0）


### 先交换信息，再各自加工

注意力主要让不同位置交换信息；FFN（前馈网络）则对每个位置得到的表示做进一步加工。它通常先扩展维度，再压回去，中间加入非线性变换。

SwiGLU 在加工过程中加了可学习的门控：一条分支产生内容，另一条分支调节内容通过多少。残差连接则把加工前的输入直接加回来，让信息有一条较直接的传递路径。

**直答：** 注意力负责跨位置交流，FFN 对各位置的信息进一步变换，SwiGLU 用门控调节信息，残差把输入直接接回输出，帮助深层网络训练。

### 进一步：公式、边界与追问

**技术表述：** 注意力负责位置间信息混合，FFN 对每个位置做非线性特征变换；残差提供信息和梯度的直接通路。

**展开：** gated FFN 可写为 (SiLU(xW_g)⊙xW_u)W_d。相较两矩阵 FFN，多了门控投影，因此常调整中间宽度来控制参数量。注意力、FFN 并不是严格可分的“记忆模块”和“推理模块”。

**追问：FFN 参数可能比 attention 多吗？** 可以，取决于中间维度和注意力结构。解释参数量要列矩阵形状，不能只凭层名。

**易错：** 残差不是让网络“自动忽略所有差层”，而是改变函数参数化与优化路径。依据：S57。

## T09｜BPE、WordPiece、Unigram 与字符 n-gram 怎么区分？（P0）


### 是在切句子，还是在收集相邻片段？

“我爱学习”按字符取 2-gram，得到“我爱、爱学、学习”。n-gram 的 n 就是连续取几块；用字符还是词作单位，需要先说明。这些片段可以重叠。

BPE、WordPiece、Unigram 则主要用于学习一套分词词表，决定输入怎样切成 token。BPE 可以粗略理解为不断合并常见相邻片段；另两种方法采用不同的选择标准。

**直答：** 分词方法决定文本如何变成模型读取的 token；n-gram 是连续 n 个单位组成的片段，可用于统计或特征。两者有关联，但不是同一个概念。

### 进一步：公式、边界与追问

**技术表述：** 前三者是子词分词方案；字符 n-gram 是连续 n 个字符的片段特征，不天然构成唯一分词序列。

**展开：** BPE 迭代合并常见相邻单位；WordPiece 的训练与词表选择目标不同，不宜直接说“就是 BPE”；Unigram 以候选子词和概率模型评估切分。byte-level 方法可覆盖任意字节，但 token 数不等于字数。

**追问：内容安全为什么仍用字符 n-gram？** 对拼写变体和局部字母组合可形成低成本强基线，但长距离语境和反讽能力弱。

**易错：** 中文一个字未必恰好一个 token；换 tokenizer 后词表 ID、嵌入、模板和模型权重都需兼容。依据：S58。

## T10｜Encoder-only、Decoder-only、Encoder-decoder 怎么选？（P0）


### 看懂全文、接着写、读完再改写

Encoder-only 像先把整段材料读完再判断，适合文本分类等理解任务；Decoder-only 像不断根据已有前文往后写，适合生成。

Encoder-decoder 则分工：一部分先读输入，另一部分根据读到的内容生成输出，翻译就是容易理解的例子。这里是在讲结构倾向，实际任务可以有多种实现。

**直答：** 三类结构主要区别在信息怎样流动：双向理解、按前缀生成，或者编码输入后再生成。选择时结合任务、已有模型和训练成本。

### 进一步：公式、边界与追问

**技术表述：** Encoder-only 适合双向表征任务；Decoder-only 适合统一的自回归生成；Encoder-decoder 显式分离输入编码和输出生成。

**展开：** BERT 类 mask 语言建模与 GPT 类 next-token prediction 监督方式不同。分类、检索未必需要生成式大模型；机器翻译和结构化转写也可使用 encoder-decoder。

**追问：Decoder-only 能做 embedding 吗？** 可以经过池化、对比训练和检索评测适配，但不能认定最后 token 原始向量天然就是优秀检索表示。

**易错：** “decoder”不意味着一定包含 encoder-decoder cross attention。依据：S01、S59。

<a id="T11"></a>
## T11｜MoE 的总参数与激活参数有什么区别？（P1）


### 医院有很多科室，一次就诊不必经过全部科室

MoE 可以类比为许多可选择的处理单元，叫“专家”。每个 token 到来时，路由器只选其中一部分专家计算，而不是每个专家都算一遍。

所以“总参数”是所有专家等参数加起来有多少；“激活参数”是一次处理实际用到的那部分。专家是网络模块，不能直接理解成真的懂某一专业的医生。

**直答：** MoE 用路由选择部分专家参与每次计算，因此总参数可以很多，而单次激活参数较少。不过全部权重的存放、专家间通信仍然需要资源。

### 进一步：公式、边界与追问

**技术表述：** 总参数是所有专家等权重的总量；激活参数是单个 token 实际经过的专家及共享模块参数。

**展开：** Router 选择少数专家可降低每 token 的部分计算，但所有专家通常仍需存储，分布式路由还带来 all-to-all 通信、负载不均与容量限制。

**追问：总参数 100B、激活 10B，显存等于 10B 吗？** 通常不等于；权重驻留由部署分片、卸载和并行策略决定。不同 token 还可能激活不同专家。

**易错：** MoE 不是多个独立聊天机器人投票。依据：S60。

<a id="T12"></a>
## T12｜长上下文、滑窗、线性注意力各解决什么？（P1）


### 一本书太长，可以从三个方向减轻负担

一种做法是提高模型能读的长度；滑窗注意力则让某个位置主要看附近一段内容，减少全篇两两比较；一些线性注意力方法进一步改变计算形式，让成本随长度增长得更慢。

这些办法解决问题的方式不同。只看附近会影响远距离联系，改变注意力计算也可能改变表达能力。能输入很长，也不等于每个细节都记得住。

**直答：** 长上下文扩展可读范围，滑窗减少每个位置看见的范围，线性注意力改变计算方式来降低长度成本；它们都需要结合远距离任务检查效果。

### 进一步：公式、边界与追问

**技术表述：** 长上下文是能力目标；滑窗限制可关注范围；线性注意力或状态空间等结构改变计算和记忆形式。

**展开：** 标准全注意力的 score 计算随长度平方增长；滑窗用局部连接降低代价，但跨远距离信息传播受结构影响。压缩状态可以降低随历史长度增长的存储，却可能损失精确检索细节。

**追问：128K 上下文就能可靠记住 128K 内容吗？** 不一定。应测不同位置、干扰强度、多跳组合和规则更新，而非只测输入是否接受。

**易错：** FlashAttention 优化 IO，不把一般精确稠密注意力的算术复杂度改成 O(L)。依据：S04、S33。

<a id="T13"></a>
## T13｜参数量和 attention 复杂度怎么估算？（P0）


### 先数“存了多少数字”，再数“做了多少计算”

一个 100×200 的权重矩阵存了 2 万个参数。把各矩阵的元素数加起来，才能估计参数量。

注意力里，每个位置要与许多其他位置比较。长度从 100 变成 200，全位置两两配对从 1 万变为 4 万，因此这部分随长度平方增长。其他线性变换则有不同的增长方式。

**直答：** 参数量按权重矩阵尺寸数元素；计算量要按实际运算数估计。标准注意力的全位置交互有平方长度成本，但参数量、运算量和实际耗时是三个不同指标。

### 进一步：公式、边界与追问

**技术表述：** 参数量按矩阵尺寸相乘；attention 主要包含线性投影 O(Ld²) 和位置交互 O(L²d)。

**展开：** 标准 MHA 的 Q/K/V/O 四个 d×d 投影约 4d² 参数。两层 FFN、宽度 d_ff 时约 2dd_ff；SwiGLU 常为 3dd_ff。词嵌入约 Vd，输入输出权重是否共享会改变总量。

**追问：序列很短时谁更贵？** L²d 未必主导，投影与 FFN 可能占更大比例；实际时间还由并行度、访存和 kernel 决定。

**练习：** d=4096、d_ff=11008 的三投影 FFN，忽略 bias 时约 1.353 亿参数。不要拿 FLOPs 直接当毫秒。

<a id="T14"></a>
## T14｜FlashAttention 为什么“精确”却更省显存？（P0）


### 同一道大题，可以边算边汇总

普通实现可能先写出一张很大的注意力分数表，再读取它继续计算。FlashAttention 把任务切成块，边算边更新必要的汇总数字，减少大表的存储和来回搬运。

它像用较小草稿区完成同一套精确计算，而不是为了省事删掉一些候选。浮点数的运算顺序变了，仍可能出现细小数值差异。

**直答：** FlashAttention 通过分块计算和在线归一化，避免完整存下巨大中间表，减少显存读写；它保持稠密注意力的数学目标。

### 进一步：公式、边界与追问

**技术表述：** 它分块计算并维护在线 softmax 统计，减少大矩阵在显存与片上存储间搬运，避免完整存储注意力中间矩阵。

**展开：** 归一化统计可跨块合并，因此不必先存整张 L×L score。数学目标是相同的稠密注意力；浮点求和顺序不同仍可能产生微小数值差异。FlashAttention-2 进一步改进线程块与 warp 的工作划分，减少非矩阵乘运算和共享存储通信（S37）。

**追问：与 PagedAttention 的区别？** 前者主要优化注意力计算与 IO；后者主要改进服务中的 KV cache 分配和共享，二者可以配合。

**易错：** 不能说 FlashAttention 丢弃低分 token 来近似；也不能把论文特定硬件加速倍数写成普遍承诺。依据：S04、S34。

<a id="T15"></a>
## T15｜MLA 为什么可以压缩 KV cache？（P1）


### 历史资料能不能换一种更紧凑的表示？

生成每个新 token 都要参考历史 K/V，历史越长，缓存越大。MLA 设计了一种较低维的潜在表示，用较少的数字承载历史信息，并配合投影与位置处理来完成后续注意力。

它不是把已经训练好的任何模型都直接无损压缩，也不是仅减少几个 K/V 头。模型结构和训练本身需要适应这种表示。

**直答：** MLA 通过专门设计的低维表示减少部分 K/V 缓存，缓存布局取决于具体模型；理解时要看实际保存了哪些张量。

### 进一步：公式、边界与追问

**技术表述：** Multi-head Latent Attention 用较低维的潜在表示承载部分 K/V 信息，通过设计好的投影与计算吸收减少需要缓存的内容。

**展开：** 它不是简单把 GQA 的 KV 头数再减小；位置编码部分、潜变量维度与重建/吸收方式共同决定缓存布局。具体模型中要按缓存张量计算，而非直接套标准 MHA 公式。

**追问：低秩表示一定免费吗？** 可能引入投影、实现复杂度和训练适配，需看质量及实际 decode 性能。

**易错：** DeepSeek 某个版本的缓存配置不是所有 MLA 系统的固定值。依据：S48。

<a id="T16"></a>
## T16｜MoE 怎么避免某些专家过忙？（P1）


### 大家都排同一个窗口，其他窗口再多也没用

MoE 中如果路由器总选少数专家，那些专家会很忙，其他专家却闲着。计算既不均衡，也可能超过某个专家能处理的容量。

均衡方法会调整路由、加入鼓励分散分配的约束，或改变专家选择的偏置。目标不是强制每个输入都平均分发，而是在任务质量与负载之间取舍。

**直答：** MoE 要同时学会选合适专家和避免负载过度集中。除了总耗时，还要检查每个专家收到多少 token、是否溢出，以及设备间传输开销。

### 进一步：公式、边界与追问

**技术表述：** 通过路由设计、负载约束或偏置调整让 token 更均衡分配，并处理容量和通信。

**展开：** 辅助均衡损失可能与主任务目标相互影响；不同模型会采用不同方案。统计每专家 token 数、溢出/丢弃、跨设备通信和尾部专家耗时。

**追问：完全均衡就最好吗？** 过强均衡可能限制专业化；应在吞吐、质量和硬件约束间找合适取舍。

**易错：** 只报激活参数量会漏掉路由与 all-to-all 的系统代价。依据：S48、S60。
