# 维护规范

## 文件职责

- 01_知识主线 与 02_项目与面试：人工维护正文，是唯一事实源。
- sources.json：来源登记，固定 S 编号；保留标题、URL、核查日、使用范围与状态。
- build.py：由正文生成题目索引、来源索引、48 题速记、离线阅读器与质量报告。
- core_algorithms.py / test_core.py：教学代码与可重跑校验。
- distillation_examples.py / test_distillation.py：蒸馏概率、温度与 mask 算例。
- posttraining_pretraining_examples.py / test_posttraining_pretraining.py：OPD 局部梯度、GSPO/SAPO/GDPO 和预训练样本、预算算例。
- agent_reliability_examples.py / test_agent_reliability.py：订单工具契约、超时恢复、记忆、预算与验收的单进程教学模拟；不代表真实 Agent 基准成绩。
- transformer_handwrite.py / test_transformer_handwrite.py：第 21 章的完整 PyTorch 实现与数值、梯度、因果性、缓存及玩具学习检查。
- reader_visuals.js / reader_visuals.css：8 个按需加载的离线算法演示；构建时嵌入单文件阅读器。题目映射由 QUESTION_VIZ 维护。
- CHANGELOG.md：记录新增、修正、依据与影响的题号。

## 新人可读性规则（1.1）

- 每题先给一个具体任务、生活场景或可算的小例子，再解释方法做了什么。
- 术语第一次出现在入门讲解里时，先说白话含义；不要用另外几个没解释的术语代替解释。
- 类比说明机制后，写清它的边界。例如概率猜准仍不代表每次结果确定，专家网络不等于人类领域专家。
- 用“直答”收束已经解释过的概念。不要让直答成为读懂整题的先决条件。
- 标题“### 进一步：公式、边界与追问”是阅读器识别深读部分的标记，保留完全一致的文字。
- 深读区可以保留公式、论文版本、严谨前提与深入追问；每题来源仍要能够定位。
- 新增公式例子必须手算或运行核对。新增内容还需验证默认折叠、完整阅读与旧复习进度兼容。
- 修改正文后重建，20 题路线由 build.py 中 BEGINNER 维护；341 是当前题数，不是上限。

## 新增一题

按“## 固定题号｜问题（P0/P1/P2）”命名，新增后不复用旧题号。给直答、机制/例子、追问答案、条件或误区；算法定义或时效性观点附来源编号。代码练习注明运行范围。

P0 是岗位主干，P1 是延伸追问，P2 是研究储备。不要因为论文新就自动升级 P0。

## 新增一篇论文

1. 优先作者原论文、官方会议页、作者代码和官方文档。
   来源编号现支持 S01—S999；题目编号仍采用原有前缀与两位数字。新增后检查正文、章末与阅读器内的来源跳转。
2. 核对准确标题、版本、发布日期与会议决定；arXiv 作者声明与官方接收分别记录。
3. 说明它改变哪道题：新条件、新反例、新算法，还是仅新的实验分数。
4. 数字写清模型、基线、数据版本、计算预算和单位。没有这些条件时，宁可讲机制。
5. 记录未复现、文档动态变化或访问受限，不把未核查标作已验证。

## 什么时候更新

- 每次面试后：新增真实追问、修正解释、补个人证据。
- 每两周有空时：检查后训练/Agent 核心新研究，择优改题，不必追完每个模型。
- 训练器/推理框架升级前：核对默认 loss、mask、KL、归一化与缓存行为。
- 投递新岗位前：调整学习路线和重点，保留原题编号。

这里是建议的手动维护节奏，没有创建定时任务或监控。

## 修正优先级

最高：公式符号/分母错、引用错位、指标混淆、错误归因、个人经历失真。其次：版本变化、重要失效漏讲、代码不能运行。最后才是措辞和排版。

## 生成与校验

运行根目录“验证与重建.ps1”，会校验教学代码并重建阅读器。新 Transformer 实验需先准备 PyTorch 环境，方法见相应运行说明；脚本优先找本地 .venv-transformer，再找本次检查环境，然后尝试原 Python。网络来源检查需显式运行 check_sources.py --refresh，避免每次离线阅读都联网。

新增的 transformer_visual_qa.cjs 覆盖 8 个可视化在 4 档宽度下的交互、下载代码一致性、数值变化、按需挂载和性能。性能基线为 work/transformer-visual-revision/before.html（已经做过加载优化的 1.4），不能误用更早的慢版本来夸大效果。测量包含 4 倍 CPU 降速、5 次独立上下文；同时保留全部题目列表不挂载隐藏正文的约束。

手写章中引用的代码片段应与完整实现对应。修改代码后需同时更新讲解中的片段，逐段比较并运行行为测试；不可只检查代码“能解析”。代码中的索引与函数调用不是 Markdown 链接，构建器使用 Markdown 解析结果识别真实链接。

浏览器回归脚本为 browser_qa.cjs，需要 Node.js、Playwright 和 Edge。用 Node 运行该文件即可；支持 KNOWLEDGE_BROWSER 指定浏览器路径、KNOWLEDGE_QA_OUTPUT 指定截图与临时进度输出目录。脚本使用独立浏览器环境，不改个人浏览器进度；报告写入 browser-qa.json。新题按构建统计自动纳入检查。

Agent 教程的 50 题集合、12 题入门顺序与订单互动在 reader_template.html 维护。修改互动时，要检查 3 种情景各 5 步、前进/返回/重置、最终状态以及窄屏显示；必须区分 Agent 观察与教学视角的后台事实。浏览器回归已包含这些情景。可靠性实验的正常、超时与故障路径由根目录验证脚本一起运行。

公式还要单独运行 formula_qa.cjs，逐个检查 1440、768、390、320 像素宽度下的公式、真实滚动端点、上下边界与未转换命令；报告写入 formula-qa.json，同时生成全公式审阅图。不能仅凭“转换函数未报错”判断渲染正确。test_rendering.py 防止双线体丢失、未知命令直接显示和分隔符不完整等回归。

浏览器数学字母遵循 [MathML Core 的 mathvariant 约定](https://www.w3.org/TR/mathml-core/#the-mathvariant-attribute)：双线体等字母应输出对应 Unicode 字符。当前转换器已显式处理双线体；遇到未处理的其他字母变体会停止构建，避免悄悄显示成普通字母。

题目与研究记录可复制“新题与研究记录模板.md”；原始背景报告保存在同目录。

阅读器内的复习状态保存在当前浏览器本地；定期使用“导出进度”保存 JSON。换浏览器或移动文件后可导入。导入只接受已存在题号及已知状态，不执行文件中的任何代码。

### 阅读器加载与性能

- 继续使用单文件内嵌题库，无需 SQLite、IndexedDB 或后台服务。`knowledge` 数据块只包含目录，`data-q-*` / `data-doc-*` 保存完整记录；浏览器通过 `DB` 的按需属性读取正文。校验脚本应读取 `DB`，不要把目录数据块当成完整题库。
- 折叠题目只渲染标题；正文与深读分别按需创建。`build.py` 生成的深读包装与 `reader_template.html` 的拆分标记必须保持一致。
- 屏幕外的题目使用 `content-visibility` 延后排版；打印时恢复完整渲染。“展开全部”每批最多 4 题，并响应收起和路由切换。
- 复习状态继续使用 `llm-interview-study-v1`，阅读深度继续使用 `llm-study-depth`，不迁移或清空个人数据。
- 用 Node 运行 `performance_qa.cjs` 对比 `work/reader-performance/before.html` 与当前入口，报告写入 `performance-qa.json`。使用独立 Edge 环境、4 倍 CPU 降速、5 次中位数；它测量浏览器加载和渲染，不代表磁盘冷启动，也不改变个人进度。
- 修改懒加载后，运行 `browser_qa.cjs` 和 `formula_qa.cjs`，覆盖键盘展开、深读、批量展开取消、打印内容、319 题路由和四档屏宽公式。

## 不能被自动校验替代的审查

脚本可发现重复题号、未知来源、坏本地链接、无正文和数学渲染失败；不能证明论文因果结论正确、所有公式假设充分、岗位建议适合当前 JD。每次大改仍需人工抽查重点章节和研究原文。

## 版本规则

1.x：在既有结构中扩充/修正；2.0：主线、数据结构或评测协议发生不兼容变化。删除题目时保留迁移说明；引用 URL 变化保留旧地址或来源记录。
