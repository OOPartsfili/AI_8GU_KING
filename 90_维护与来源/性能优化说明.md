# 阅读器性能优化

日期：2026-09-15。入口仍为根目录的“开始阅读.html”。

## 问题与修改

原阅读器会在打开折叠列表时创建所有题目的正文、复习控件和公式节点。显示 319 道题时，内容区共有 12,901 个元素，其中 8,747 个属于隐藏的正文。搜索还会为每个关键词重复拼接并转小写整题文本。

本次继续使用 HTML 内嵌的本地题库，改为轻量目录和按题、按文档存储的数据块。启动只解析目录；需要正文时再解析一次并缓存。解析后移除原 JSON 文本节点。没有引入数据库服务、网络请求或安装步骤。

- 列表只创建标题；点击题目后加载正文，展开深读后创建对应公式。
- 屏幕外的题目使用浏览器的 `content-visibility` 延后排版，仍可滚动、键盘定位和点击。
- 搜索复用已经规范化的全文文本，保持原有多关键词 AND 匹配方式。
- “展开全部”每批最多 4 题；收起或切换页面会取消剩余工作。
- 打印前加载并展开完整内容，打印后恢复原折叠状态。
- 保留原复习进度存储键、阅读深度、导入导出格式和单文件离线使用方式。

## 前后对比

测试使用本机无界面 Edge、1440×1080、4 倍 CPU 降速、每项 5 次取中位数；每轮使用独立浏览器环境。显示耗时计入同步排版和两次动画帧。不是磁盘冷缓存测试，也不能代表所有电脑的速度。

| 场景 | 优化前 | 优化后 |
|---|---:|---:|
| 全题列表显示 | 781 ms | 206 ms |
| 搜索“模型”（232 题） | 265 ms | 100 ms |
| 48 道核心题列表 | 92 ms | 72 ms |
| Agent 50 题页 | 193 ms | 182 ms |
| 从搜索切到 M02 单题 | 252 ms | 289 ms |
| 首页加载事件 | 698 ms | 673 ms |

主要收益是长列表和搜索。全题列表同步阻塞从 657 ms 降到 53 ms，元素数从 12,901 降到 1,602，未展开正文的元素数为零。首次首页打开提升较小；本轮测试中 M02 单题切换没有提速。首次排版仍有成本，未将列表提速说成所有页面都同幅度提速。

精确数据与测量方法保存在 `performance-qa.json`，脚本为 `performance_qa.cjs`。
