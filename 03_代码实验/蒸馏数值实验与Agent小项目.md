# 蒸馏数值实验与 Agent 小项目

配合 KD03、KD04、KD11、KD22、KD23 阅读。目标是先亲手检查关键计算，再组织可验证的 Agent 数据。

## 第一步：三种动作的概率

教学中把选择简化成“查订单、查天气、直接猜”。教师判断为 [0.90, 0.08, 0.02]，学生为 [0.60, 0.30, 0.10]；实际大模型的下一 token 预测一般有数万候选，这里只缩小维度。

运行 distillation_examples.py 可以看到：

- 正向 KL 约 0.2270，反向 KL 约 0.3142；方向不同，惩罚数值不同。
- 温度 1、2、4 下的教师概率分布；温度越高，分布越平。
- 软目标损失乘 T² 后的解析梯度与有限差分比较。
- 被 mask 的工具观察位置改变预测分数时，该位置仍不进入直接损失。
- KD20 假设数字的成本摊平点：37500 个任务。

请先预测结果再运行。例如，把师生分布改成完全相同，两个 KL 应该是多少？

## 第二步：检查一次完整的训练记分

“mask”就是一张“这个位置是否计分”的表。模型的工具调用和答复记 1；用户输入、工具返回、补齐长度的 padding 通常记 0。不同训练目标可能另有约定，先写出规则再编码。

在真实因果语言模型中，第 t 个位置的输出分数预测第 t+1 个 token。配套函数接收的是**已经完成这个移位的分数和目标**，不要在调用时漏移或移两次。

观察 token 虽不直接计分，仍应留在后续回答的上下文里。“不计算该位置损失”不等于“模型不读取该位置”。

## 第三步：一个可以逐步实现的订单 Agent 实验

下面是项目设计，尚未执行教师调用或 GPU 训练。

1. **环境与任务：**做可重置的模拟订单工具；任务包含完整参数、缺订单号、查无结果、一次超时和多轮补问。环境固定随机种子，每次可重放。
2. **验证器：**根据实际订单状态检查终态和答复。工具调用 JSON 合法只是第一关，还要核对订单号、调用依赖和观察一致性。
3. **数据：**按任务族先留出测试集，再向教师采样训练任务。记录完整 messages、工具版本、真实工具结果、教师版本与验证结果；不把测试题用于教师生成训练答案。
4. **基线：**原始学生直接执行；学生用教师轨迹 SFT；教师直接执行。保持部署工具和单题预算可比较。
5. **定向改进：**收集学生自己跑错的状态，提供完整上下文给教师纠正。只能拿文本就先做纠正示范训练；若有兼容概率与所需训练资源，再做 GKD 对照。
6. **评测：**新任务、异常恢复、工具说明变化、重复运行。分别报告最终成功率、有效工具调用率、恢复成功率、P95 延迟和每成功任务成本。

**最小消融：**相同训练 token 下比较最终答案 SFT、完整轨迹 SFT、轨迹加学生状态纠正。若测试时增加多次采样或教师兜底，单独记一组并计算额外成本。

## 如何运行

在知识库根目录执行：

~~~text
python 03_代码实验/distillation_examples.py
python 03_代码实验/test_distillation.py
~~~

依赖为 Python 3 和 NumPy。根目录“验证与重建.ps1”也包含这两步。源码均位于本文件同目录；网页只是说明，不会自动执行代码或调用教师。

测试包含梯度有限差分、已知 KL 数值、温度稳定性、mask 行为与异常输入。它们用于检查基础计算，不能作为 Agent 能力提升或任何论文复现的证据。
